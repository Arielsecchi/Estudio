5 Unidad 5: Estructuras de repetición (for, while, do-while) y centinela

En la Unidad 4 tu programa aprendió a decidir: ejecutar ciertas líneas o saltearlas según una condición. En esta unidad aprende a repetir: ejecutar un mismo bloque de código muchas veces, sin que vos tengas que copiarlo y pegarlo. A esas estructuras se las llama ciclos o bucles. Vas a ver las tres que usa la cátedra —for, while y do-while— paso a paso, con trazas, y el patrón centinela para leer datos hasta un valor de corte. Arrancamos de cero, como siempre.

¿Por qué necesitamos repetir? La motivación

Imaginá que tu programa tiene que mostrar la palabra Hola diez veces en pantalla. Con lo que sabés hasta ahora, lo harías así:

cout << "Hola" << endl;
cout << "Hola" << endl;
cout << "Hola" << endl;
// ... y así seis líneas más, hasta diez

Funciona, pero es horrible. ¿Y si fueran cien veces? ¿O un millón? ¿Y si te equivocás en una línea y tenés que corregirla en las cien? Copiar y pegar el mismo código es propenso a errores, imposible de mantener y, sobre todo, no escala: la cantidad de veces muchas veces ni siquiera la conocés de antemano (depende de lo que el usuario tipee).

Un ciclo resuelve esto: es una estructura de control que ejecuta un bloque de código (llamado cuerpo del ciclo) varias veces, mientras se cumpla una condición. Cada ejecución del cuerpo es una iteración (una "vuelta" del ciclo). Vos escribís el bloque una sola vez y el ciclo se encarga de repetirlo.

Los ciclos en la vida real
Hacer flexiones — "Repetí: bajá y subí, hasta llegar a 20." Sabés exactamente cuántas: son 20. Eso es una repetición exacta.

Llenar un balde con un vaso — "Repetí: cargá el vaso y volcalo en el balde, mientras el balde no esté lleno." No sabés cuántos vasos van a ser: depende del tamaño del balde y del vaso. Eso es una repetición indefinida.

Esta diferencia —¿sé cuántas veces, o repito mientras pase algo?— es justo la que separa al for de los otros dos ciclos.

Dos familias de ciclos: repetición DEFINIDA vs INDEFINIDA

Antes de ver la sintaxis, lo más importante es entender cuándo usar cada ciclo. La pregunta clave es una sola: ¿sé de antemano cuántas veces tengo que repetir?

Tipo¿Sé cuántas veces?EstructuraEjemplo típico

La regla para elegir el ciclo
• Si conocés la cantidad de repeticiones (o la podés calcular antes de empezar) → usás FOR.
• Si no la conocés y repetís mientras se cumpla una condición → usás WHILE (chequea la condición antes de cada vuelta) o DO-WHILE (la chequea después, así que da al menos una vuelta).

Los tres ciclos podrían escribirse uno en términos de otro, pero cada uno está pensado para un caso: usar el que corresponde hace tu código más claro.

El for: repetición DEFINIDA

El for (en inglés, "para") es el ciclo que usás cuando sabés cuántas veces querés repetir. Su gran ventaja es que junta en una sola línea las tres cosas que todo conteo necesita: desde dónde empiezo, hasta dónde llego y de a cuánto avanzo. La sintaxis es:

for (inicialización; condición; incremento) {
    // cuerpo del ciclo: lo que se repite
}

Adentro de los paréntesis hay tres partes, separadas por punto y coma ;. Esa variable que controla el ciclo y lleva la cuenta de las vueltas se llama índice o variable de control (por costumbre se la nombra i). Veamos qué hace cada parte:

El orden EXACTO de ejecución de un for

Esto es lo que tenés que tener grabado a fuego. Cuando el programa llega a un for, los pasos son siempre en este orden:

Los pasos de un for, en orden
1. Se ejecuta la inicialización (int i = 1). Esto pasa una sola vez.
2. Se evalúa la condición (i <= 10):
    • Si es true → se ejecuta el cuerpo (paso 3).
    • Si es false → el ciclo termina y el programa sigue después de la llave }.
3. Se ejecuta el cuerpo del ciclo (las sentencias entre llaves).
4. Se ejecuta el incremento (i = i + 1).
5. Se vuelve al paso 2 (re-chequear la condición), repitiendo 3 y 4 mientras la condición siga dando true.

Fijate el detalle clave: la inicialización (paso 1) ocurre una sola vez, pero después el ciclo gira entre condición → cuerpo → incremento → condición → cuerpo → incremento... hasta que la condición da false. El cuerpo y el incremento nunca se ejecutan si la condición ya arrancó en false.

El primer ejemplo de la cátedra

Este es el for que muestra la cátedra (con un contador extra para llevar la cuenta de las vueltas, como viste en la Unidad 3):

int contador = 0;
for (int i = 1; i <= 10; i = i + 1) {
    cout << "hola" << endl;
    contador = contador + 1;
}

Leelo en palabras: "para i empezando en 1, mientras i sea menor o igual que 10, y sumándole 1 a i en cada vuelta: mostrá hola y sumá 1 al contador". El índice i va a tomar los valores 1, 2, 3, ..., 10, así que el cuerpo se ejecuta exactamente 10 veces: en pantalla aparece hola diez veces y contador queda valiendo 10.

El índice va del VALOR INICIAL al VALOR FINAL inclusive (con <=)
Cuando usás la condición i <= final, el índice toma todos los valores desde el inicial hasta el final, incluyéndolo. Por eso for (int i = 1; i <= 10; ...) da 10 vueltas (i = 1, 2, ..., 10). El esquema general de la cátedra es:

for (int INDICE = VALOR_INICIAL; INDICE <= VALOR_FINAL; INDICE = INDICE + 1)

El índice siempre se incrementa de a 1 y va desde VALOR_INICIAL hasta VALOR_FINAL inclusive. El ciclo sigue mientras INDICE <= VALOR_FINAL sea true; cuando da false, sale y continúa la ejecución.

Traza paso a paso de un for chiquito

"Hacer de computadora" es la mejor forma de entender un ciclo: anotás en una tabla qué vale el índice, qué da la condición y qué acción ocurre, vuelta por vuelta. Trazemos este for que muestra Hola con i yendo de 1 a 5 (el mismo ejemplo de las notas de la cátedra):

for (int i = 1; i <= 5; i = i + 1) {
    cout << "Hola" << endl;
}
Vueltai (al evaluar)Condición i <= 5Accióni tras el incremento
1ª11 <= 5 → truemuestra Hola2
2ª22 <= 5 → truemuestra Hola3
3ª33 <= 5 → truemuestra Hola4
4ª44 <= 5 → truemuestra Hola5

Resultado: Hola aparece 5 veces. Mirá la última fila: cuando i llega a 6, la condición 6 <= 5 da false, así que el cuerpo ya no se ejecuta y el ciclo termina. Ese chequeo "de más" que da falso es normal y necesario: es la forma en que el ciclo sabe que tiene que parar.

Variantes del for: partes vacías y el for infinito

Las tres partes del for son opcionales: podés dejar alguna (o todas) vacías, siempre que mantengas los dos ;. El código de la cátedra muestra dos variantes para que las reconozcas. En la primera, la inicialización y el incremento están fuera del for:

int i = 1;            // inicialización afuera
for (; i <= 10; ) {   // solo la condición; las otras dos partes, vacías
    cout << "hola" << endl;
    i = i + 1;        // incremento adentro del cuerpo
}

Hace exactamente lo mismo que el for completo: 10 vueltas. Simplemente, la creación del índice se hizo antes y el incremento se metió como una línea más del cuerpo. Es válido, aunque lo habitual y más claro es poner las tres partes dentro del paréntesis.

Y si dejás las tres partes vacías, obtenés un for que no termina nunca (la condición ausente se considera siempre verdadera):

for (;;) {            // for INFINITO: no hay condición que lo corte
    cout << "hola" << endl;
}

Este for (;;) muestra hola para siempre. La cátedra lo incluye para ilustrar la sintaxis, pero un ciclo infinito sin una salida controlada es un error (lo vemos en las cajas de trampas).

El while: repetición INDEFINIDA (condición al PRINCIPIO)

El while (en inglés, "mientras") es el ciclo que usás cuando no sabés cuántas veces vas a repetir: repetís mientras se cumpla una condición. La sintaxis es la más simple de todas:

while (CONDICION) {
    // cuerpo: se repite mientras CONDICION sea true
}

Funciona así: se evalúa la condición al principio. Si da true, se ejecuta el cuerpo y se vuelve a evaluar la condición; y así sucesivamente. En cuanto la condición da false, el ciclo termina y el programa sigue después de la llave.

Los pasos de un while, en orden
1. Se evalúa la condición:
    • Si es true → se ejecuta el cuerpo (paso 2).
    • Si es false → el ciclo termina.
2. Se ejecuta el cuerpo.
3. Se vuelve al paso 1 (re-chequear la condición), repitiendo el cuerpo mientras siga dando true.

Como la condición se chequea antes de entrar, el while puede girar 0 veces (si la condición arranca en false, el cuerpo no se ejecuta ni una sola vez) o infinitas veces (si la condición nunca llega a hacerse falsa). Esa es su característica distintiva: puede no ejecutarse nunca.

El ejemplo de la cátedra

La cátedra lee un número con cin y repite mientras ese número sea mayor que 8:

int x;
cin >> x;            // primera lectura: el usuario tipea un número
while (x > 8) {
    cout << "chau" << endl;
    cin >> x;        // vuelve a leer: x puede cambiar en cada vuelta
}

Recordá que cin >> x lee del teclado y guarda lo que el usuario tipea en x (la flecha >> "trae" el dato desde el teclado hacia la variable). Sigamos el flujo según lo que ingrese el usuario:

Traza del while de la cátedra
Supongamos que el usuario va tecleando: 10, después 9, después 3.

• cin >> x → x = 10. Condición 10 > 8 → true → muestra chau → cin >> x → x = 9.
• Condición 9 > 8 → true → muestra chau → cin >> x → x = 3.
• Condición 3 > 8 → false → sale del ciclo.

Mostró chau 2 veces. Ahora mirá un caso límite: si lo primero que teclea es 5, la condición 5 > 8 da false de entrada y el cuerpo no se ejecuta ni una vez (0 vueltas). Eso es lo que solo un while puede hacer.

El do-while: repetición INDEFINIDA (condición al FINAL)

El do-while (en inglés, "hacer... mientras") es casi igual al while, con una diferencia fundamental: la condición se chequea al final, después de ejecutar el cuerpo. La sintaxis es:

do {
    // cuerpo: se ejecuta y RECIÉN DESPUÉS se chequea la condición
} while (CONDICION);

Ojo a dos detalles de escritura: el cuerpo va primero (después de la palabra do), y el while con la condición va al final, terminado en punto y coma ; (este es el único ciclo que lleva ; después del paréntesis de la condición).

Los pasos de un do-while, en orden
1. Se ejecuta el cuerpo (sí o sí, sin preguntar nada todavía).
2. Se evalúa la condición:
    • Si es true → se vuelve al paso 1 (otra vuelta).
    • Si es false → el ciclo termina.

Como el cuerpo se ejecuta antes del primer chequeo, el do-while gira como mínimo 1 vez, pase lo que pase.

El código de la cátedra muestra el do-while paralelo a su while:

int y;
do {
    cout << "chau" << endl;
    cin >> y;
} while (y > 8);

Acá siempre se muestra chau al menos una vez antes de leer y y de chequear nada. Recién después de mostrar y leer, se evalúa y > 8 para decidir si hay otra vuelta. Compará con el while anterior: aquel leía antes y podía no mostrar chau nunca; este muestra chau sí o sí la primera vez.

El caso clásico del do-while: pedir usuario y contraseña
¿Cuándo el do-while es la elección natural? Cuando necesitás ejecutar el cuerpo al menos una vez para recién después poder evaluar la condición. El ejemplo de manual es un login: tenés que pedir usuario y contraseña al menos una vez antes de poder saber si están bien o mal. La cátedra lo plantea así (en pseudocódigo):

do {
    pedir usuario
    pedir contraseña
} while (las credenciales están mal);

Se piden las credenciales (1ª vuelta, seguro), y solo entonces se evalúa si están mal: si están mal, se vuelven a pedir; si están bien, se sale. Con un while normal tendrías que pedirlas una vez "a mano" antes del ciclo para tener algo que evaluar; el do-while lo resuelve más naturalmente.

El patrón centinela (valor de corte)

Un problema clásico: "se siguen ingresando números hasta que el usuario ingresa un valor especial". Ese valor especial que marca el fin de los datos se llama centinela o valor de corte. No es un dato a procesar: es una señal de "ya terminé de cargar". Ejemplos: terminar cuando ingresan 999, o 0, o un número negativo.

La cátedra lo plantea con el centinela 999: "se siguen ingresando números hasta que termina cuando se ingresa el número 999". Definamos las dos ideas centrales:

CORTE y la idea de "seguir mientras NO sea el centinela"
• CORTE: la condición que indica que hay que parar. Es valor == 999 (el dato ingresado es el centinela).
• !CORTE (no corte): la condición para seguir. Es valor != 999 (el dato no es el centinela).

Como el ciclo repite mientras haya que seguir, la condición del while es justamente !CORTE: "while (valor != 999)", es decir, "seguí mientras lo ingresado no sea 999".

La gran pregunta es dónde poner la lectura (cin >> valor). La cátedra distingue dos esquemas según una sutileza: ¿la condición del ciclo depende del dato que se lee, o no?

Esquema (a): la condición NO depende de la entrada → leés ADENTRO

Si la condición de corte no se fija en el valor recién ingresado (por ejemplo, repetir una cantidad fija de veces, o mientras un contador no llegue a cierto número), podés leer el dato cómodamente dentro del cuerpo:

// SI la CONDICIÓN NO depende de la entrada de datos
while (COND) {
    cin >> x;
    // ... procesar x ...
}

Acá la lectura es una acción más del cuerpo. Como COND no mira a x, no hay riesgo de procesar de más.

Esquema (b): la condición SÍ depende de la entrada → lectura ADELANTADA

Este es el caso del centinela y el que más confunde al principio. Si la condición sí depende del dato ingresado (while (x != 999) mira a x), no podés leer recién dentro del cuerpo, porque la primera vez el while evaluaría x sin que el usuario haya tecleado nada todavía. La solución es la lectura adelantada: leés una vez antes del while (para tener un primer valor que evaluar) y volvés a leer al final del cuerpo (para tener el siguiente):

// SI la CONDICIÓN SÍ depende de la entrada de datos
cin >> x;              // 1) lectura ADELANTADA: primer valor, antes del while
while (x != 999) {    // 2) la condición evalúa el x que YA tenemos
    // ... procesar x (que NO es 999) ...
    cin >> x;          // 3) leé el SIGUIENTE valor, al final del cuerpo
}

El truco es entender los dos cin: el de arriba carga el primer valor para que la condición tenga algo que mirar; el del final del cuerpo prepara el valor para la próxima evaluación de la condición. Así, cuando el usuario ingresa 999, ese valor se lee (en alguno de los dos cin), el while evalúa 999 != 999 → false y sale sin procesar el 999. ¡Eso es justo lo que queremos: el centinela marca el fin, no es un dato!

Traza de la lectura adelantada con centinela 999
El usuario teclea: 5, 8, 999. Seguimos el código del esquema (b):

• cin >> x (adelantada) → x = 5.
• while (5 != 999) → true → procesa el 5 → cin >> x → x = 8.
• while (8 != 999) → true → procesa el 8 → cin >> x → x = 999.
• while (999 != 999) → false → sale. El 999 nunca se procesa.

Se procesaron solo el 5 y el 8 (los datos reales), no el centinela. Si hubieras leído dentro del cuerpo sin la lectura adelantada, habrías procesado el 999 por error antes de chequear.

Dos atajos: break y continue

Dentro de cualquier ciclo podés usar dos sentencias especiales para alterar su flujo. Ya viste break en el switch de la Unidad 4; en los ciclos cumple un rol parecido.

break — corta el ciclo por completo: lo abandona inmediatamente y el programa salta a lo que venga después de la llave de cierre, sin importar la condición. Sirve para salir antes de tiempo cuando ya encontraste lo que buscabas:

for (int i = 1; i <= 10; i = i + 1) {
    if (i == 5) {
        break;           // al llegar i a 5, abandona el for
    }
    cout << i << endl;    // muestra 1, 2, 3, 4 y corta
}

continue — saltea el resto del cuerpo de la vuelta actual y va directo a la siguiente iteración (en el for, pasa al incremento y vuelve a chequear la condición). No corta el ciclo: solo se saltea lo que queda de esa vuelta:

for (int i = 1; i <= 5; i = i + 1) {
    if (i == 3) {
        continue;        // en la vuelta de i = 3, salta el cout y sigue
    }
    cout << i << endl;    // muestra 1, 2, 4, 5 (se saltea el 3)
}
break vs continue en una frase
• break = "me voy del ciclo" (lo termina del todo).
• continue = "salteo esta vuelta" (sigo con la próxima iteración).

Usalos con moderación: muchas veces una condición bien pensada en el while o un if en el cuerpo logran lo mismo y se leen mejor.

Errores típicos que tenés que evitar

Ciclo INFINITO: olvidar el incremento o que la condición nunca se haga falsa
Un ciclo que nunca termina deja tu programa colgado mostrando cosas (o sin responder) para siempre. La causa número uno es olvidar modificar la variable de control, de modo que la condición se quede eternamente verdadera. Mirá:

int i = 1;
while (i <= 10) {
    cout << "hola" << endl;
}  ← ¡falta i = i + 1;! Como i siempre vale 1, 1 <= 10 es siempre true y nunca para.

Lo mismo pasa con for (;;) (sin condición) o si en un while (x != 999) te olvidás de volver a leer x. Regla: asegurate de que en cada vuelta algo acerque la condición a hacerse falsa (incrementar el índice, leer un dato nuevo, etc.).
Error "off-by-one": confundir < con <= (una vuelta de más o de menos)
Cambiar <= por < (o al revés) altera la cantidad de vueltas en uno, y es un error tan común que tiene nombre propio: off-by-one ("por uno de diferencia").

• for (int i = 1; i <= 10; i = i + 1) → da 10 vueltas (i = 1, 2, ..., 10).
• for (int i = 1; i < 10; i = i + 1) → da 9 vueltas (i = 1, 2, ..., 9): ¡el 10 se queda afuera!

Antes de dar por bueno un for, "hacé de computadora" con el primer y el último valor del índice y contá las vueltas. ¿Querés incluir el valor final? Usá <=. ¿Querés frenar justo antes? Usá <.
Procesar el valor centinela por error
En un ciclo con centinela, el valor de corte no es un dato: es la señal de "terminé". Si lo procesás (lo sumás, lo mostrás, lo contás), tu resultado queda mal. El error típico es leer dentro del cuerpo sin lectura adelantada:

do {
    cin >> x;
    suma = suma + x;  ← cuando x es 999, ¡lo suma igual antes de cortar!
} while (x != 999);

Por eso, cuando la condición depende del dato, se usa la lectura adelantada (leer antes del while y al final del cuerpo): así el while ve el 999 y sale antes de procesarlo. Si igual querés usar este esquema, tenés que chequear con un if (x != 999) antes de sumar.

Repaso de la unidad

Lo que tenés que llevarte
• Un ciclo repite un bloque (el cuerpo) varias veces; cada vuelta es una iteración. Sirve para no copiar y pegar código.
• Repetición definida (sé cuántas veces) → for. Repetición indefinida (repito mientras se cumpla una condición) → while / do-while.
• for (init; condición; incremento): la init corre una vez; después gira condición → cuerpo → incremento. Con i <= final el índice llega hasta el final inclusive.
• while (COND) evalúa al principio: puede dar 0 vueltas.
• do { ... } while (COND); evalúa al final: da mínimo 1 vuelta (y lleva ; al final).
• Centinela (valor de corte): se repite mientras NO sea el centinela (while (x != 999)). Si la condición depende del dato, usá lectura adelantada (leer antes del while y al final del cuerpo) para no procesar el centinela.
• break abandona el ciclo; continue saltea el resto de la vuelta.
• Cuidado con el ciclo infinito (olvidar el incremento / leer de nuevo), el off-by-one (< vs <=) y procesar el centinela.
