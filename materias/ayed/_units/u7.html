7 Unidad 7: Modularización — procedimientos, funciones, parámetros y recursividad

Hasta ahora escribiste todos tus programas amontonados dentro de main: una sentencia abajo de la otra, todo junto. Eso funciona para programas chiquitos, pero apenas crecen se vuelven un bollo imposible de leer y de mantener. En esta unidad vas a aprender a partir un programa en piezas —llamadas módulos— para que cada una haga una cosa bien. Vas a ver los dos tipos de módulos de C++: los procedimientos (que hacen algo pero no devuelven nada) y las funciones (que devuelven un valor). Después: cómo pasarles datos (parámetros), la diferencia clave entre pasarlos por valor y por referencia, qué es la firma de una función y la sobrecarga, el alcance (scope) de las variables, y por último el tema más alucinante: la recursividad, funciones que se llaman a sí mismas. Todo desde cero y con el código tal cual lo da la cátedra.

¿Qué es modularizar y por qué conviene?

Modularizar es dividir un programa grande en piezas más chicas, cada una con un nombre y una tarea concreta. A esas piezas las llamamos módulos, y en C++ se construyen con funciones y procedimientos. En vez de tener doscientas líneas seguidas en main, tenés un main cortito que llama a piezas con nombres que se entienden: leerDatos(), calcularPromedio(), mostrarResultado().

Modularizar en la vida real
Pensá en un restaurante. No hay una persona que compre, cocine, sirva, cobre y limpie todo a la vez en un solo bloque caótico. Hay roles: el que cocina, el mozo, el cajero. Cada uno hace su tarea, y vos —cliente— pedís "una pizza" sin saber cómo se amasa por dentro. El restaurante es el programa; cada rol es un módulo. Si mañana cambian la receta de la masa, solo se toca al cocinero: el mozo y el cajero ni se enteran.
Las cuatro razones para modularizar
• Legibilidad: un main que llama a saludar(), procesar(), despedir() se lee como un índice. Entendés qué hace el programa de un vistazo, sin perderte en el cómo.
• Reusabilidad: escribís el módulo una sola vez y lo llamás muchas. ¿Necesitás dibujar una línea separadora diez veces? Escribís raya() una vez y la llamás diez veces, en vez de copiar y pegar el mismo cout diez veces.
• Abstracción: para usar un módulo te alcanza con saber qué hace y qué recibe/devuelve, sin conocer su tripa interna. Usás cout sin saber cómo le habla a la pantalla; igual usás tus propias funciones.
• Mantenimiento: si hay un error en el cálculo del promedio, lo arreglás en un solo lugar (la función) y queda arreglado en todos lados donde se la llama. Sin módulos, tendrías que cazar el mismo bug copiado en mil lados.

A esta forma de encarar problemas se la llama "divide y vencerás" (divide and conquer): un problema grande y difícil se vuelve manejable cuando lo partís en subproblemas chicos, resolvés cada uno por separado (cada uno en su módulo) y después los combinás. Es la idea más importante de toda la programación, y la vas a usar para siempre.

Procedimientos: módulos que hacen pero no devuelven nada (void)

Un procedimiento es un módulo que ejecuta una serie de acciones pero no entrega ningún valor de vuelta. En C++ se lo declara con la palabra clave void (que en inglés significa "vacío", "nada"): justamente, no devuelve nada. La sintaxis más simple es:

void nombre() {
    // las acciones que hace el procedimiento
}

Se lee de izquierda a derecha: void dice "no devuelve nada"; nombre es el nombre que vos le ponés (con el que después lo vas a llamar); los paréntesis () son donde irían los parámetros (por ahora vacíos, lo vemos más adelante); y entre llaves { } va el cuerpo, las sentencias que se ejecutan cuando lo llamás. El ejemplo más simple de la cátedra es una línea separadora:

void raya() {
    cout << "------------" << endl;
}

Cómo se invoca (se llama) un procedimiento

Definir el procedimiento no lo ejecuta: solo lo deja "guardado", listo para usar. Para que efectivamente corra, hay que invocarlo (llamarlo) escribiendo su nombre seguido de los paréntesis y un punto y coma:

raya();   // ahora SÍ se ejecuta: muestra ------------

Cuando el programa llega a raya();, hace una especie de "salto": va al cuerpo de raya, ejecuta sus líneas (el cout), y al terminar vuelve exactamente a la línea de abajo de donde lo llamaste, y sigue. Ese ida y vuelta es lo que hace tan cómodos a los módulos.

Un procedimiento puede llamar a otro

Adentro de un procedimiento podés llamar a otros procedimientos. La cátedra arma saludar() y despedir(), y saludar() reutiliza a raya():

void saludar() {
    cout << "Hola" << endl;
    cout << "Como va?" << endl;
    raya();
}

void despedir() {
    cout << "hasta luego" << endl;
    cout << "nos vemos la proxima" << endl;
    raya();
}

Fijate la reusabilidad en acción: tanto saludar como despedir terminan con una línea separadora, y ninguna de las dos repite el cout << "------------": ambas llaman a raya(). Si mañana querés que la raya sea más larga, la cambiás en un solo lugar (dentro de raya) y se actualiza en todos lados.

Llamándolos desde main (varias veces = reuso)

En main los invocás como cualquier otra sentencia. Y los podés llamar las veces que quieras:

int main() {

    saludar();
    saludar();

    despedir();

    return 0;
}
Traza: qué muestra ese main
El programa arranca en main y va de arriba hacia abajo.

1. saludar(); → salta a saludar: muestra Hola, Como va?, y llama a raya() que muestra ------------. Vuelve a main.
2. saludar(); otra vez → repite lo mismo: Hola, Como va?, ------------.
3. despedir(); → muestra hasta luego, nos vemos la proxima, y raya() muestra ------------.

Salida final en pantalla:
Hola
Como va?
------------
Hola
Como va?
------------
hasta luego
nos vemos la proxima
------------

Una sola definición de saludar, dos llamadas, dos veces el saludo: eso es reuso.

Funciones: módulos que devuelven un valor (return)

Una función es un módulo que, además de poder hacer cosas, calcula y devuelve un valor al que la llamó. La diferencia con un procedimiento es justamente esa: el procedimiento no devuelve nada (void); la función devuelve un dato de un tipo concreto. La sintaxis es:

tipo nombre() {
    // ... cálculos
    return valor;   // entrega un valor del tipo declarado
}

Ahora, donde antes ponías void, va el tipo del dato que devuelve: int si devuelve un entero, bool si devuelve verdadero/falso, float si devuelve un decimal, string si devuelve texto, etc. Y aparece la palabra clave return, que cumple dos roles a la vez:

Qué hace exactamente return valor;
• Entrega el valor a quien llamó a la función: ese valor "sale" de la función y ocupa el lugar de la llamada.
• Termina la función en el acto: cualquier línea que esté debajo del return ejecutado no se corre. El return es la puerta de salida.
• El tipo del valor tiene que coincidir con el tipo declarado: si la función es int, devolvés un entero; si es bool, un true/false.

Estos son los ejemplos de la cátedra, uno por cada tipo. Una función que devuelve un int:

int obtenerNumero() {
    int n = 30;
    return n;     // devuelve 30
}

Una que devuelve un bool (un booleano, verdadero/falso) y otra que devuelve un float (un decimal):

bool pepe() {
    return true;
}

float func2() {
    return 1.5;
}

Lo más importante: hay que USAR el valor devuelto

Acá está la diferencia práctica más grande con los procedimientos. A un procedimiento lo llamás "suelto" (raya();) porque no devuelve nada. Pero una función devuelve un valor, y ese valor tenés que hacer algo con él: guardarlo en una variable, mostrarlo, o usarlo en una cuenta. Si no, el valor se calcula y se tira a la basura.

La forma más común es guardarlo en una variable:

int w = obtenerNumero();   // obtenerNumero() devuelve 30, así que w queda en 30
cout << w << endl;          // muestra: 30

Pensálo así: cuando el programa ejecuta obtenerNumero(), esa llamada se reemplaza por el valor que devuelve. O sea, la línea termina siendo, en los hechos, int w = 30;. Por eso también podés usar la llamada dentro de una expresión más grande, como si fuera un número más:

int z = 1 + obtenerNumero();   // 1 + 30
cout << z << endl;              // muestra: 31

Acá obtenerNumero() devuelve 30, la expresión queda 1 + 30, da 31, y eso es lo que se guarda en z. Una función con un nombre claro se lee casi como castellano:

int calcularLaCantidadDeAlumnos() {
    //................
    return 50;
}

int cant = calcularLaCantidadDeAlumnos();   // cant queda en 50
Trampa: olvidar el return en una función no void
Si declarás una función que devuelve un tipo (por ejemplo int) pero te olvidás de poner el return, la función no entrega ningún valor: el resultado es basura impredecible (un número cualquiera que había en memoria) y el compilador, en el mejor de los casos, te avisa con un warning. La regla: toda función no void tiene que terminar devolviendo un valor de su tipo por todos los caminos posibles. Si tu módulo no necesita devolver nada, entonces no es una función: hacelo void.
Trampa: llamar a una función y no usar lo que devuelve
Escribir obtenerNumero(); sola, en una línea, no es un error de compilación, pero casi siempre es un error lógico: la función calcula su valor 30 y, como nadie lo recibe, se descarta. Es como ir al cajero, sacar la plata y dejarla ahí. Si te interesa el valor, guardalo o usalo: int w = obtenerNumero();.

Parámetros: pasarle datos al módulo para que trabaje

Los módulos de recién siempre hacían exactamente lo mismo: raya() siempre dibuja la misma línea, obtenerNumero() siempre devuelve 30. Para que un módulo sea de verdad útil, necesita poder trabajar con datos distintos cada vez. Esos datos de entrada se llaman parámetros, y se declaran entre los paréntesis, indicando el tipo y un nombre para cada uno.

Un procedimiento que recibe un string (un texto) y saluda a esa persona:

void saludarA(string nombre) {
    cout << "Hola " << nombre << endl;
}

Dentro del cuerpo, nombre se usa como una variable normal: vale lo que le hayan pasado al llamar. Y al llamar, ponés el valor concreto entre los paréntesis:

saludarA("Adrian");   // muestra: Hola Adrian
saludarA("Carla");    // muestra: Hola Carla

El mismo procedimiento, con distintos datos, produce distintos resultados. También podés pasarle el valor a través de una variable, no solo un literal escrito a mano:

string n = "Pedro";
saludarA(n);          // muestra: Hola Pedro

Parámetro vs. argumento (la palabra fina)

Dos nombres para no confundir
• Parámetro: es el nombre que aparece en la definición de la función, el "hueco" que espera un valor. En void saludarA(string nombre), el parámetro es nombre.
• Argumento: es el valor concreto que le pasás al llamarla. En saludarA("Adrian"), el argumento es "Adrian".

Dicho fácil: el parámetro es el casillero, el argumento es lo que metés en el casillero. (En la práctica mucha gente los usa como sinónimos; no te van a retar por eso, pero está bueno saber la diferencia.)

Funciones con parámetros: lo mejor de los dos mundos

Lo más potente es combinar las dos cosas: un módulo que recibe datos (parámetros) y devuelve un resultado (función). El ejemplo canónico de la cátedra es una suma:

int suma(int a, int b) {
    return a + b;
}

Recibe dos enteros (a y b, separados por coma) y devuelve su suma. Mirá las distintas formas de llamarla y usar lo que devuelve:

int total = suma(2, 8);     // argumentos literales: total queda en 10
cout << total << endl;       // muestra: 10

int d = 5;
int f = 6;
int total2 = suma(d, f);    // argumentos por variables: total2 queda en 11
cout << total2 << endl;      // muestra: 11

Otro ejemplo de la cátedra, que recibe un número y devuelve el siguiente:

int dameElSiguienteNumero(int nro) {
    return nro + 1;
}

int x = dameElSiguienteNumero(8);   // x queda en 9
cout << x << endl;                   // muestra: 9
El orden de los argumentos importa
Los argumentos se asignan a los parámetros por posición: el primer argumento va al primer parámetro, el segundo al segundo, y así. En suma(d, f) con d=5 y f=6, adentro de la función a vale 5 y b vale 6. Para la suma da igual el orden, pero para una resta resta(10, 3) y resta(3, 10) dan resultados opuestos. Prestá atención a en qué orden pasás las cosas.

Paso por valor vs. paso por referencia (sección clave)

Esta es una de las ideas más importantes —y más confundidas— de toda la unidad. La pregunta es: cuando le paso una variable a un módulo y el módulo la modifica… ¿se modifica también la variable original de afuera, o no? La respuesta depende de cómo pasaste el parámetro: por valor o por referencia.

Por VALOR (lo que pasa por defecto): se trabaja sobre una COPIA

Por defecto, cuando pasás un argumento, la función recibe una copia de ese valor. Es como si fotocopiaras el dato y le dieras la fotocopia a la función. La función puede rayar, romper o cambiar su fotocopia todo lo que quiera: el original de afuera queda intacto. Mirá:

void duplicarMal(int n) {      // n es una COPIA del argumento
    n = n * 2;                  // cambio la copia... nada más
}

int main() {
    int x = 5;
    duplicarMal(x);             // le paso una copia de x (un 5)
    cout << x << endl;           // muestra: 5  (¡NO cambió!)
    return 0;
}
¿Por qué x sigue valiendo 5?
1. int x = 5; → en memoria, la variable x de main vale 5.
2. duplicarMal(x); → se crea una copia de ese 5 y se la mete en el parámetro n. Ahora hay dos casilleros distintos: x (en main, vale 5) y n (en la función, vale 5), independientes.
3. n = n * 2; → se modifica solo n: ahora n vale 10. Pero x ni se enteró, sigue en 5.
4. La función termina y n desaparece. Volvemos a main.
5. cout << x → muestra 5. El original nunca se tocó.

Por REFERENCIA (con &): se trabaja sobre la variable ORIGINAL

Si querés que la función modifique la variable de verdad (no una copia), agregás un ampersand & pegado al tipo del parámetro. Eso lo convierte en un parámetro por referencia: la función ya no recibe una fotocopia, sino que trabaja directamente sobre el mismo casillero de memoria de afuera. Es como darle a la función no la fotocopia, sino el original mismo. Cualquier cambio que haga, persiste al volver:

void duplicar(int& n) {        // OJO el &: n es la variable ORIGINAL, no una copia
    n = n * 2;                  // modifico el original
}

int main() {
    int x = 5;
    duplicar(x);                // le paso x "de verdad"
    cout << x << endl;           // muestra: 10  (¡SÍ cambió!)
    return 0;
}
¿Por qué ahora x sí cambia a 10?
1. int x = 5; → x vale 5.
2. duplicar(x); → como el parámetro es int& n (por referencia), no se copia nada: n pasa a ser otro nombre para el mismísimo casillero de x. Donde dice n, leé "x".
3. n = n * 2; → como n es x, esto pone 10 en el casillero de x.
4. La función termina. Volvemos a main.
5. cout << x → muestra 10. El cambio quedó.
El detalle que decide todo: el &
La única diferencia entre void duplicar(int& n) y void duplicarMal(int n) es ese &. Con & → por referencia → modifica el original. Sin & → por valor → trabaja sobre una copia y el original no cambia. Un solo carácter cambia por completo el comportamiento del programa. El & va pegado al tipo (podés verlo pegado al tipo int& n o pegado al nombre int &n; son lo mismo).

¿Para qué sirve el paso por referencia?

Tiene dos usos centrales que vas a aprovechar muchísimo:

Cuándo usar referencia
• Parámetros de salida: devolver MÁS de un resultado. Una función con return devuelve un solo valor. Pero a veces necesitás devolver dos o tres (por ejemplo, el máximo y el mínimo de una lista). Pasás esas variables por referencia y la función las "carga" desde adentro: void calcular(int datos, int& maximo, int& minimo). Salen modificadas con los resultados.
• Modificar el dato que recibís. Cuando el objetivo del módulo es cambiar la variable que le das (duplicarla, ordenarla, incrementarla), la referencia es la herramienta.
Trampa: modificar un parámetro por VALOR esperando que cambie afuera
El error clásico es escribir algo como void incrementar(int n) { n = n + 1; }, llamarlo con incrementar(x) y esperar que x aumente. No aumenta: n es una copia, el incremento se pierde cuando la función termina. Si querés que el cambio persista afuera, el parámetro tiene que ser por referencia: void incrementar(int& n). Es uno de los bugs más comunes y silenciosos del principiante: el programa compila, corre, y "misteriosamente" la variable no cambia.

La firma de una función y la sobrecarga (overloading)

La firma de una función es lo que la identifica de forma única para el compilador. Y está compuesta por exactamente dos cosas:

¿Qué forma la FIRMA?
Firma = NOMBRE de la función + TIPOS de sus parámetros (en orden).

Y muy importante: el tipo de retorno NO forma parte de la firma. Tampoco forman parte los nombres de los parámetros (da igual si el parámetro se llama nombre o apellido): lo que cuenta son los tipos y su orden.

Por ejemplo, la firma de void mostrarPersona(string nombre) es mostrarPersona(string). La firma de int suma(int a, int b) es suma(int, int).

Sobrecarga: varias funciones con el MISMO nombre

La sobrecarga (en inglés overloading) es poder tener varias funciones con el mismo nombre, siempre y cuando tengan firmas distintas (es decir, difieran en la cantidad o el tipo de sus parámetros). El compilador decide cuál llamar según los argumentos que le pases. Es comodísimo: usás un solo nombre intuitivo para "la misma idea" aplicada a distintos datos. El ejemplo de la cátedra con mostrarPersona:

// FIRMA: mostrarPersona(string)
void mostrarPersona(string nombre) {
    cout << "Nombre: " << nombre << endl;
}

// FIRMA: mostrarPersona(string, string)
void mostrarPersona(string nombre, string apellido) {
    cout << "Nombre: " << nombre << " - Apellido: " << apellido << endl;
}

// FIRMA: mostrarPersona(string, int)
void mostrarPersona(string nombre, int dni) {
    cout << "Nombre: " << nombre << " - DNI: " << dni << endl;
}

// FIRMA: mostrarPersona(string, string, int)
void mostrarPersona(string nombre, string apellido, int edad) {
    cout << "Nombre: " << nombre << " - Apellido: " << apellido << " - Edad: " << edad << endl;
}

Las cuatro se llaman mostrarPersona, pero cada una tiene una firma distinta, así que conviven sin problema. Al llamarlas, el compilador mira los argumentos y elige la correcta:

mostrarPersona("Adrian");                    // usa mostrarPersona(string)
mostrarPersona("Adrian", "Fiore");           // usa mostrarPersona(string, string)
mostrarPersona("Adrian", 10);                // usa mostrarPersona(string, int)  → el 10 es DNI
mostrarPersona("Pedro", "Gonzalez", 25);     // usa mostrarPersona(string, string, int)

Cuándo NO se puede sobrecargar

No podés tener dos funciones con la misma firma, aunque te parezca que son distintas. Dos casos sutiles que la cátedra marca explícitamente como "NO SE PUEDE":

// Ya existe: void mostrarPersona(string nombre, string apellido)  → firma (string, string)

// NO SE PUEDE: tiene la MISMA firma (string, string).
// Cambiar el NOMBRE de los parámetros no cambia la firma.
// void mostrarPersona(string apellido, string nombre) {
//     cout << "Nombre: " << nombre << " - Apellido: " << apellido << endl;
// }
// Ya existe: void mostrarPersona(string, string, int)

// NO SE PUEDE: misma firma (string, string, int).
// El TIPO DEL RETURN no forma parte de la firma: cambiar void por int NO alcanza.
// int mostrarPersona(string nombre, string apellido, int edad) {
//     cout << "..." << endl;
//     return 1;
// }
Trampa: creer que cambiar el nombre del parámetro o el tipo de retorno crea una firma nueva
Son los dos errores típicos con sobrecarga:
✗ Renombrar el parámetro (de nombre a apellido) no cambia la firma: los tipos son los mismos.
✗ Cambiar solo el tipo de retorno (de void a int) no cambia la firma: el retorno no cuenta.
En ambos casos el compilador ve la misma firma repetida y tira error de "redefinición / función duplicada". Para sobrecargar de verdad tenés que cambiar la cantidad o los tipos de los parámetros.
Ojo: una llamada que compila igual puede ser un error LÓGICO
Como mostrarPersona(string, string) existe, la llamada mostrarPersona("Fiore", "Adrian") compila perfecto… pero muestra "Nombre: Fiore - Apellido: Adrian", que está al revés. La cátedra lo marca como error lógico: el programa funciona, pero hace lo que no querías porque te equivocaste en el orden de los argumentos. En cambio, una llamada como mostrarPersona("Pedro", 25, "Gonzalez") directamente no compila: no existe ninguna firma mostrarPersona(string, int, string).

Alcance (scope) de las variables: ¿dónde vive cada variable?

El alcance (en inglés scope) de una variable es la zona del programa donde esa variable existe y se la puede usar. La regla de oro es simple:

La regla del bloque { }
Una variable existe solo dentro del bloque { } donde fue declarada, desde la línea en que se declara hasta la llave de cierre } de ese bloque. Apenas el programa sale de ese bloque, la variable desaparece (deja de existir y no se la puede usar más). A una variable así se la llama variable local de ese bloque.

Esto explica algo que ya venías viendo sin darte cuenta: la variable n dentro de obtenerNumero no existe en main; los parámetros de una función solo viven dentro de esa función. Cada bloque es como una habitación: lo que declarás adentro, se queda adentro.

Variables locales de distintas funciones son INDEPENDIENTES

Como cada función es su propio bloque, podés tener una variable res en una función y otra res en otra: son dos variables totalmente distintas que casualmente comparten nombre. No se pisan, no se mezclan, no saben una de la otra. El nombre se "reusa" sin conflicto porque viven en cuartos separados.

Ocultamiento (shadowing): un bloque interno tapa a uno externo

Hay un caso fino: si declarás una variable en un bloque interno con el mismo nombre que una de afuera, la de adentro "tapa" (oculta) a la de afuera mientras dure el bloque interno. Adentro, el nombre se refiere a la variable interna; al salir del bloque, vuelve a "verse" la de afuera (que nunca se tocó). Es exactamente lo que pasa en el ejemplo de scope de la cátedra. Mirálo entero:

int main() {

    int x = 3;
    cout << x << endl;

    int z = 10;
    cout << "z vale: " << z << endl; //10

    if (1 == 1) {
        int y = 28;
        cout << y << endl;
        x = 7;
        cout << "z vale: " << z << endl; //10
        int z = 20;
        cout << "z vale: " << z << endl; //20
    }

    cout << x << endl;
    cout << "z vale: " << z << endl; //10

    return 0;
}

Hay dos cosas distintas pasando acá: el ocultamiento de z y la modificación de x. Vamos paso a paso.

Traza completa: qué muestra el programa
Seguimos el bloque externo (el de main) y el interno (el del if):

1. int x = 3; → x (externa) vale 3.
2. cout << x → muestra 3.
3. int z = 10; → z (externa) vale 10.
4. cout << "z vale: " << z → muestra z vale: 10.
5. Entra al if (porque 1 == 1 es true). Abre bloque interno.
6. int y = 28; → y existe solo dentro del if. Muestra 28.
7. x = 7; → ojo: NO hay un x interno, así que esto modifica la x externa (la misma de siempre). Ahora x vale 7.
8. cout << "z vale: " << z → todavía no se declaró el z interno, así que este z es el externo → muestra z vale: 10.
9. int z = 20; → acá nace un nuevo z interno que vale 20. A partir de esta línea y hasta el cierre del if, este z interno TAPA al externo (ocultamiento).
10. cout << "z vale: " << z → ahora z es el interno → muestra z vale: 20.
11. Cierra el bloque interno }: mueren y y el z interno. El z externo sigue valiendo 10 (nunca se tocó: el de 20 era otro).
12. cout << x → muestra 7 (la x externa quedó modificada desde el paso 7).
13. cout << "z vale: " << z → de nuevo se ve el z externo → muestra z vale: 10.

Salida en pantalla: 3 · z vale: 10 · 28 · z vale: 10 · z vale: 20 · 7 · z vale: 10 (cada uno en su renglón).
Las dos lecciones del ejemplo
• z (ocultamiento): afuera vale 10; adentro del if se declara otro z = 20 que oculta al de afuera; al salir del if, ese z interno muere y vuelve a verse el 10. Eran dos variables distintas que compartían nombre.
• x (modificación real): como dentro del if no se declaró ningún x, la línea x = 7; no crea uno nuevo: modifica el único x que existe (el externo). Por eso afuera, después del if, x ya vale 7. La diferencia con z es que z fue redeclarada adentro (con int) y x no.

Variables globales: por qué se evitan

Una variable declarada fuera de toda función (a nivel del archivo) se llama global: la pueden ver y modificar todas las funciones del programa. Suena cómodo, pero es una mala práctica en general, porque cualquier parte del programa puede cambiarla y se vuelve imposible saber quién la modificó y cuándo: aparecen bugs muy difíciles de rastrear, y rompe la abstracción (las funciones dejan de ser cajas independientes). La regla práctica de la materia: pasá los datos como parámetros y devolvé resultados con return (o por referencia); reservá las globales para constantes que de verdad sean de todo el programa.

Recursividad: una función que se llama a sí misma

La recursividad es una técnica donde una función se llama a sí misma para resolver un problema, descomponiéndolo en una versión más chica del mismo problema. Suena a magia (¿una función que se llama a sí misma no se cuelga para siempre?), pero la clave es que cada llamada trabaja sobre un caso más pequeño, hasta llegar a uno tan simple que se resuelve sin volver a llamarse. Por eso, toda función recursiva necesita dos partes:

Los dos ingredientes obligatorios de la recursión
• Caso base (condición de corte): el caso más simple, que se resuelve directamente, SIN volver a llamarse. Es el freno que detiene la cadena. Si falta, la recursión nunca termina.
• Caso recursivo: la función se llama a sí misma con un problema más chico, acercándose al caso base.

El ejemplo clásico: el factorial

El factorial de un número n (se escribe n!) es el producto de todos los enteros desde 1 hasta n. Por ejemplo, 3! = 3 · 2 · 1 = 6. La definición matemática ya es recursiva: n! = n · (n−1)!, y 0! = 1 (ese es el caso base). Así lo escribe la cátedra en C++:

int factorial(int nro) {
    int res;
    if (nro != 0) {
        res = nro * factorial(nro - 1);   // CASO RECURSIVO: se llama con nro-1 (más chico)
    } else {
        res = 1;                          // CASO BASE: 0! = 1, sin volver a llamarse
    }
    return res;
}

Leelo así: "si nro no es 0, el resultado es nro multiplicado por el factorial de nro − 1 (un problema más chico); si nro es 0, el resultado es 1 (y acá freno)". Cada llamada reduce nro en 1, así que tarde o temprano llega a 0 y se corta.

Traza de factorial(3): cómo se apilan las llamadas
Cada llamada queda en pausa esperando el resultado de la llamada que hizo. Primero se "baja" hasta el caso base, y después se "sube" calculando:

Bajada (cada una llama a la siguiente y queda esperando):
• factorial(3): 3 != 0 → res = 3 * factorial(2)  ⟶ pausa, espera factorial(2)
• factorial(2): 2 != 0 → res = 2 * factorial(1)  ⟶ pausa, espera factorial(1)
• factorial(1): 1 != 0 → res = 1 * factorial(0)  ⟶ pausa, espera factorial(0)
• factorial(0): 0 != 0 es false → entra al else → res = 1 → devuelve 1  ✋ (caso base, acá frena)

Subida (cada una recibe el resultado y completa su cuenta):
• factorial(1) recibe 1 → res = 1 * 1 = 1 → devuelve 1
• factorial(2) recibe 1 → res = 2 * 1 = 2 → devuelve 2
• factorial(3) recibe 2 → res = 3 * 2 = 6 → devuelve 6

Resultado final: factorial(3) = 3 · 2 · 1 = 6. Y por el mismo mecanismo: factorial(0)=1, factorial(1)=1, factorial(2)=2, factorial(4)=24.
La "pila" de llamadas
Cada vez que una función se llama (a sí misma o a otra), la llamada en curso se apila: queda guardada con todas sus variables locales, en pausa, hasta que la nueva llamada devuelva. Por eso factorial(3) espera a factorial(2), que espera a factorial(1)… Cuando el caso base devuelve, la pila se va desapilando de a una, y cada nivel completa su cuenta. Esa estructura "lo último que entra es lo primero que sale" se llama pila (stack), y la vas a estudiar en detalle más adelante.
Trampa MORTAL: recursión sin caso base (recursión infinita)
Si te olvidás del caso base —o la condición de corte nunca se cumple— la función se llama a sí misma para siempre. Por ejemplo, si en el factorial te olvidás el else y siempre hacés res = nro * factorial(nro - 1), con un número negativo (o sin freno) nro nunca llega a 0 y las llamadas se apilan sin fin. Como cada llamada ocupa memoria en la pila, esta se llena y revienta: el programa explota con un error llamado desbordamiento de pila (stack overflow). Toda recursión DEBE tener un caso base alcanzable.

Lo mismo, sin recursión: la versión iterativa

Casi todo lo que se puede hacer con recursión se puede hacer también con un ciclo (iteración). El propio archivo de la cátedra trae, comentada, la versión del factorial con un for:

int factorial(int nro) {
    int res = 1;
    for (int i = 1; i <= nro; i++) {
        res = res * i;          // 1*1, *2, *3, ... hasta nro
    }
    return res;
}

Esta versión multiplica res por 1, 2, …, hasta nro, sin que la función se llame a sí misma. Da el mismo resultado que la recursiva. ¿Cuál usar? La iterativa suele ser más eficiente (no apila llamadas, no arriesga desbordar la pila); la recursiva a veces es más elegante y se parece más a la definición matemática del problema. Las dos son válidas: con el tiempo vas a desarrollar el ojo para elegir.

Repaso de la unidad

Lo que tenés que llevarte
• Modularizar = partir el programa en módulos chicos (funciones/procedimientos). Gana en legibilidad, reuso, abstracción y mantenimiento ("divide y vencerás").
• Un procedimiento (void nombre() { ... }) hace algo pero no devuelve nada; se llama con nombre();.
• Una función (tipo nombre() { ... return valor; }) devuelve un valor con return (que además corta la función). Hay que usar el valor: int w = obtenerNumero();.
• Los parámetros son los datos de entrada (en la definición); los argumentos son los valores concretos al llamar. Se asignan por posición.
• Por valor (default): la función recibe una copia; el original no cambia. Por referencia (con &): trabaja sobre el original; los cambios persisten. Sirve para parámetros de salida (devolver más de un dato) o modificar lo recibido.
• La firma = nombre + tipos de los parámetros; el tipo de retorno y los nombres de parámetros no cuentan. La sobrecarga permite mismo nombre con firmas distintas; no se puede repetir firma.
• El alcance (scope): una variable vive solo dentro de su bloque { }. El ocultamiento hace que una variable interna tape a otra externa del mismo nombre (mientras dura el bloque). Las globales se evitan.
• La recursividad = función que se llama a sí misma. Necesita caso base (corte, sin recursión) y caso recursivo (problema más chico). factorial(3) = 3·2·1 = 6. Sin caso base → desbordamiento de pila. Alternativa: versión iterativa con for.
