8 Unidad 8: Arreglos (vectores)

Hasta ahora cada dato que guardabas vivía en su propia variable: edad, nota, sueldo. Eso alcanza cuando son pocos. Pero, ¿qué hacés cuando tenés que guardar 100 notas a la vez para después recorrerlas? En esta unidad aparece la primera estructura de datos de verdad de la materia: el arreglo (también llamado array o vector). Vamos desde cero: qué problema resuelve, cómo se declara, cómo se accede a cada posición, cómo se recorre con un for, qué pasa por dentro en la memoria, y cómo se pasa a una función. No hace falta más que lo de las unidades anteriores (variables, for, los patrones de la U6).

El problema: 100 variables es inviable

Imaginá que el enunciado te pide leer las notas de 100 alumnos y después hacer algo con ellas (mostrarlas todas, buscar la más alta, promediarlas…). Con lo que sabés hasta ahora tendrías que declarar:

int nota1;
int nota2;
int nota3;
// ... y así hasta ...
int nota100;

Esto es inviable por varios motivos: son 100 líneas para declarar, ¿cómo las leés con un ciclo si cada una tiene un nombre distinto?, ¿cómo recorrés nota1, nota2, … automáticamente? No se puede escribir notaX donde X sea una variable. El nombre de cada variable es fijo y hay que escribirlo a mano.

La idea del arreglo
Un arreglo (array / vector) guarda un conjunto de elementos del MISMO tipo bajo un solo nombre, y a cada elemento lo identificás por su número de posición (un índice). En vez de 100 nombres distintos, tenés un nombre (notas) y pedís el elemento que quieras con un número: notas[0], notas[1], … notas[99]. Y como ese número puede ser una variable, ahora sí podés recorrer todo con un ciclo.

Las tres palabras —arreglo, array y vector— son sinónimos en esta materia: nombran la misma cosa. Vas a escucharlas indistintamente, así que acostumbrate a las tres.

Cómo se declara un arreglo

La forma general de declarar un arreglo es:

tipo nombre[CANTIDAD_MAX];

Donde:

ParteQué significa
tipoEl tipo de dato de cada elemento (todos iguales): int, float, char, etc.
nombreEl nombre del arreglo (uno solo para todo el conjunto).
[CANTIDAD_MAX]Entre corchetes, cuántos elementos como máximo va a poder guardar. Es el tamaño FIJO del arreglo.

Un ejemplo concreto, el de la cátedra:

int arr[5];

Esa línea dice: "creá un arreglo llamado arr que puede guardar hasta 5 números enteros". Reservás de una el espacio para 5 enteros, todos juntos, bajo el nombre arr.

El tamaño es FIJO y se decide al declarar
CANTIDAD_MAX es la cantidad máxima de elementos que el arreglo puede guardar, y queda fijada al momento de declararlo. No podés cargar más que eso: en int arr[5] entran 5 enteros y ni uno más. (En esta etapa de la materia el tamaño es un número fijo conocido al escribir el programa; más adelante verás formas de manejar tamaños variables.)

Posiciones, índices y subíndices: ¡arrancan en CERO!

Para acceder a un elemento puntual del arreglo usás el nombre seguido de la posición entre corchetes:

nombre[posicion];

Esa posición se llama índice o subíndice. Y acá viene lo más importante de toda la unidad, lo que más confunde al principio:

Los índices van de 0 a CANTIDAD_MAX − 1
El primer elemento NO es la posición 1: es la posición 0. Las posiciones válidas van desde 0 hasta CANTIDAD_MAX − 1.

En int arr[5] las posiciones válidas son: 0, 1, 2, 3, 4. Son 5 posiciones (que es lo correcto: el arreglo tiene 5 lugares), pero numeradas del 0 al 4. No existe la posición 5.

Una vez que tenés el arreglo declarado, cada arr[i] se comporta como una variable normal de tipo int: le podés asignar un valor con = y podés leer su valor (por ejemplo, mostrarlo). Veamos las dos cosas, tal como aparecen en el código de la cátedra:

int arr[5];        // 5 lugares: posiciones 0, 1, 2, 3, 4

arr[0] = 21;       // guardo 21 en la posicion 0
arr[1] = 48;       // guardo 48 en la posicion 1
arr[3] = 7;        // guardo 7 en la posicion 3
arr[2] = 28;       // guardo 28 en la posicion 2
arr[4] = 70;       // guardo 70 en la posicion 4

cout << arr[0] << endl;   // LEO la posicion 0 -> muestra: 21
cout << arr[1] << endl;   // LEO la posicion 1 -> muestra: 48
El orden en que cargás no importa
Fijate que en el código de arriba se carga primero la posición 0, después la 1, después la 3, después la 2 y al final la 4. Da igual: cada arr[i] = ... es independiente, escribe en su casillero sin importar el orden en que aparezcan las líneas. Después de esas 5 asignaciones el arreglo quedó así, sin importar el orden de carga:
Índice (posición)01234
Valor guardado214828770

Te conviene imaginarte el arreglo como una fila de casilleros numerados (como los lockers de un gimnasio): todos del mismo tamaño (porque guardan el mismo tipo), pegados uno al lado del otro, y cada uno con su número de casillero (el índice) empezando en 0.

Inicialización por lista (cargar en la misma declaración)

Cuando ya conocés los valores desde el arranque, en vez de asignar posición por posición podés cargarlos todos juntos en la misma línea de la declaración, usando llaves y separando con comas:

int arr2[3] = {4, 9, 56};

Eso es equivalente a haber escrito tres asignaciones:

int arr2[3];
arr2[0] = 4;
arr2[1] = 9;
arr2[2] = 56;

Los valores se reparten en orden: el primero de la lista va a la posición 0, el segundo a la 1, el tercero a la 2. Así, arr2[0] es 4, arr2[1] es 9 y arr2[2] es 56.

Recorrer un arreglo con un for

Acá está la verdadera potencia del arreglo: como la posición es un número, podés usar la variable del for como índice y así pasar por todos los elementos con un ciclo de pocas líneas. El patrón es recorrer de 0 hasta CANTIDAD − 1:

for(int i = 0; i <= 4; i++) {
    cout << arr[i] << endl;
}

En cada vuelta, i toma un valor distinto (0, 1, 2, 3, 4) y arr[i] es el elemento de esa posición. Vamos a "hacer de computadora" y trazar el recorrido con el arreglo que cargamos antes (21, 48, 28, 7, 70):

Traza del recorrido: arr = {21, 48, 28, 7, 70}
• i = 0 → ¿0 <= 4? Sí → muestra arr[0] = 21, baja renglón.
• i = 1 → ¿1 <= 4? Sí → muestra arr[1] = 48.
• i = 2 → ¿2 <= 4? Sí → muestra arr[2] = 28.
• i = 3 → ¿3 <= 4? Sí → muestra arr[3] = 7.
• i = 4 → ¿4 <= 4? Sí → muestra arr[4] = 70.
• i = 5 → ¿5 <= 4? No → corta el ciclo.

Salida en pantalla (uno por renglón):
21
48
28
7
70 ✓
Dos formas equivalentes de escribir la condición
Como las posiciones de int arr[5] llegan hasta 4, podés cortar el for de dos maneras que hacen exactamente lo mismo:
• for(int i = 0; i <= 4; i++)  → "hasta el índice máximo, 4, inclusive".
• for(int i = 0; i < 5; i++)  → "mientras sea menor que el tamaño, 5".

La segunda (i < 5, o sea i < CANTIDAD) es la que más vas a ver, porque escribís directamente el tamaño del arreglo y no tenés que acordarte de restarle 1. Las dos recorren las posiciones 0, 1, 2, 3, 4.

Qué pasa por dentro: memoria contigua y acceso directo

¿Por qué un arreglo es tan cómodo y rápido? La razón está en cómo se guarda en la memoria. Cuando declarás int arr[5], la máquina reserva un bloque CONTIGUO de memoria: 5 casilleros para enteros, pegados uno tras otro, sin huecos en el medio.

El nombre del arreglo guarda la dirección del comienzo
En la variable arr (el nombre del arreglo) no está "el arreglo entero": está la dirección de memoria donde EMPIEZA el bloque (la posición de arranque). A partir de ahí, los elementos siguen ordenados de a uno.

Entonces, ¿cómo hace la computadora para ir a la posición i sin recorrer todo desde el principio? Con una cuentita. Como sabe dónde empieza el bloque y sabe cuánto ocupa cada elemento (cuántos bits ocupa el tipo de dato), calcula directamente:

direccion de arr[i] = direccionDeComienzo + i × (tamano del tipo)

Por ejemplo, con int arr[5] (donde cada int ocupa, digamos, 32 bits), para ubicar arr[i] hace direccionDeComienzo + i × 32. Es una multiplicación y una suma: una sola cuenta, y listo.

Acceso directo en tiempo CONSTANTE
Como ubicar cualquier posición se reduce a esa única cuenta, acceder a cualquier elemento cuesta lo mismo: da igual pedir arr[0] que arr[4] que arr[9999] (en un arreglo grande). No hay que "caminar" desde el principio. Esto se llama acceso directo y se dice que es en tiempo constante. En la notación de complejidad que viste, esto se anota como O(1) (o, como aparece en las notas, O(n) = k: el costo no depende de la posición, es siempre el mismo k).

Tamaño físico vs. elementos útiles (la variable N)

Hay una distinción que la cátedra remarca mucho y que conviene tener clarísima. El arreglo tiene un tamaño FÍSICO fijo (lo que reservaste al declararlo, por ejemplo 100 lugares). Pero en la práctica casi nunca usás todos los lugares: reservás "de más, por las dudas" y cargás solo los que necesitás.

Pensalo así: declarás int notas[100] porque "podrían venir hasta 100 alumnos", pero hoy se anotaron solo 30. Tenés 100 casilleros reservados, pero solo 30 están cargados con datos válidos. Los otros 70 contienen basura: valores impredecibles que quedaron en la memoria y que no significan nada.

Llevá una variable N con los elementos REALMENTE cargados
Como el tamaño físico no te dice cuántos datos válidos hay, se acostumbra llevar una variable entera —que la cátedra llama N (o también cantElemUtiles, size, length, len)— que guarda cuántas posiciones están realmente en uso. Y entonces:

• El recorrido válido va de 0 hasta N − 1 (NO hasta el tamaño físico − 1).
• Las posiciones de N en adelante contienen basura y no se tocan.
ConceptoQué esEjemplo
Tamaño físicoCuánto reservaste al declarar (fijo).int notas[100] → 100
Elementos útiles (N)Cuántos cargaste de verdad (variable).N = 30
Confundir tamaño físico con elementos útiles
Si recorrés siempre hasta el tamaño físico (las 100 posiciones) cuando en realidad cargaste solo 30, vas a procesar 70 posiciones llenas de basura: tu promedio, tu máximo y tus cuentas van a salir mal, con números que nunca ingresaste. Siempre recorré hasta N − 1, no hasta el tamaño físico, salvo que el arreglo esté lleno y N coincida con el tamaño.

Operación 1 — Cargar el arreglo (con cin en un for)

"Cargar" es llenar el arreglo con datos que el usuario ingresa. Como cada posición es un arr[i], alcanza con un for que en cada vuelta lea un valor con cin y lo guarde en la posición i. Acá usamos un N ya conocido (por ejemplo 5):

#include <iostream>
using namespace std;

int main() {
    int notas[5];
    int n = 5;                  // cuantos voy a cargar

    for(int i = 0; i < n; i++) {
        cout << "Ingrese la nota " << i << ": ";
        cin >> notas[i];         // guardo lo ingresado en la posicion i
    }

    return 0;
}

En la primera vuelta (i = 0) lo que el usuario escriba se guarda en notas[0]; en la segunda (i = 1) en notas[1]; y así hasta notas[4]. El mismo cin >> notas[i] sirve para todas las posiciones, porque i va cambiando.

Operación 2 — Búsqueda secuencial

Buscar en un arreglo es responder "¿está tal valor? ¿en qué posición?". La búsqueda secuencial (o lineal) es la más simple: recorrés el arreglo desde el principio comparando cada elemento con el valor buscado, hasta encontrarlo (o llegar al final sin éxito). Usamos una bandera y guardamos la posición:

#include <iostream>
using namespace std;

int main() {
    int arr[5] = {21, 48, 28, 7, 70};
    int n = 5;
    int buscado = 28;

    int posEncontrada = -1;         // -1 = "todavia no lo encontre"

    for(int i = 0; i < n; i++) {
        if(arr[i] == buscado) {
            posEncontrada = i;      // me guardo DONDE estaba
        }
    }

    if(posEncontrada != -1) {
        cout << "Encontrado en la posicion " << posEncontrada << endl;
    } else {
        cout << "No esta en el arreglo." << endl;
    }

    return 0;
}
Traza buscando el 28 en {21, 48, 28, 7, 70}
posEncontrada arranca en −1.

• i = 0 → ¿arr[0] (21) == 28? No.
• i = 1 → ¿arr[1] (48) == 28? No.
• i = 2 → ¿arr[2] (28) == 28? Sí → posEncontrada = 2.
• i = 3 → ¿arr[3] (7) == 28? No.
• i = 4 → ¿arr[4] (70) == 28? No.

Como posEncontrada quedó en 2 (distinto de −1): Encontrado en la posicion 2 ✓
¿Por qué arrancar la posición en −1?
El −1 es un valor "imposible" como posición (los índices válidos arrancan en 0), así que sirve de marca de "no encontrado". Si después del ciclo posEncontrada sigue valiendo −1, es porque nunca entró al if: el valor no estaba. Es la misma idea de bandera/centinela que usabas en los patrones de la U6, aplicada a posiciones.

Operación 3 — Copiar un arreglo en otro

Un arreglo no se copia con un simple = (eso no funciona con arreglos como con las variables comunes). Para copiar el contenido hay que recorrer y copiar posición por posición, justo como en el código de la cátedra:

int arr[5] = {21, 48, 28, 7, 70};

int copia[5];
for(int i = 0; i <= 4; i++) {
    copia[i] = arr[i];      // copio el elemento i de arr al elemento i de copia
}

En cada vuelta tomás arr[i] (el valor original de esa posición) y lo guardás en copia[i] (la misma posición del nuevo arreglo). Al terminar el ciclo, copia tiene exactamente los mismos valores que arr, pero es un arreglo independiente: cambiar uno no afecta al otro (cada uno tiene su propio bloque de memoria).

Operación 4 — Buscar el máximo (o el mínimo) del arreglo

Acá reusás un patrón que ya conocés: el de máximo/mínimo de la Unidad 6. La diferencia es que antes los valores llegaban de a uno por cin con un centinela; ahora ya están todos guardados en el arreglo, así que en vez de leer con cin simplemente recorrés con el for y comparás arr[i].

Y hay una ventaja muy linda: como el arreglo te deja acceder a cualquier posición, podés arrancar el máximo con el primer elemento (arr[0]) y comparar desde la posición 1 en adelante. Así te evitás todo el lío de "¿con qué valor inicializo el máximo?" que tenías en la U6:

#include <iostream>
using namespace std;

int main() {
    int arr[5] = {21, 48, 28, 7, 70};
    int n = 5;

    int max = arr[0];               // arranco con el PRIMER elemento
    for(int i = 1; i < n; i++) {    // comparo desde la posicion 1
        if(arr[i] > max) {
            max = arr[i];           // nuevo record
        }
    }

    cout << "El maximo es: " << max << endl;
    return 0;
}
Traza del máximo en {21, 48, 28, 7, 70}
max arranca en arr[0] = 21. El for empieza en i = 1.

• i = 1 → ¿arr[1] (48) > 21? Sí → max = 48.
• i = 2 → ¿arr[2] (28) > 48? No.
• i = 3 → ¿arr[3] (7) > 48? No.
• i = 4 → ¿arr[4] (70) > 48? Sí → max = 70.

Resultado: El maximo es: 70 ✓  Para el mínimo es idéntico, pero arrancás min = arr[0] y comparás con <: if(arr[i] < min) min = arr[i];.

Pasaje de arreglos a funciones

Como vas a querer reusar estas operaciones (cargar, buscar el máximo, etc.), lo natural es meterlas en funciones. Para que una función reciba un arreglo, se declara el parámetro con corchetes vacíos: tipo nombre[]. El ejemplo de la cátedra:

void cargarArray(int a[]) {
    a[0] = 7;
    a[1] = 30;
}

Pero acá hay algo muy importante que la cátedra remarca, y que es distinto a todo lo que viste con las variables comunes:

Los arreglos se pasan SIEMPRE por referencia
Con una variable común (un int, por ejemplo), la función recibe una copia: si la modifica adentro, afuera no cambia nada. Con los arreglos es al revés: NO se copia el arreglo entero. Lo que se pasa es, en realidad, la dirección de memoria donde empieza (ese "comienzo" del que hablamos antes). Por eso la función trabaja sobre el mismo arreglo que está afuera: si la función modifica una posición, el cambio PERSISTE cuando la función termina.

Veámoslo con el programa completo de la cátedra. El main declara un arreglo, lo manda a cargarArray y después lo recorre para ver qué quedó:

#include <iostream>
using namespace std;

void cargarArray(int a[]) {
    a[0] = 7;
    a[1] = 30;
}

int main() {
    int arrayPrueba[2];             // sin cargar: contiene basura
    cargarArray(arrayPrueba);       // le paso el arreglo a la funcion

    for(int i = 0; i <= 1; i++) {
        cout << arrayPrueba[i] << endl;
    }

    return 0;
}
¿Qué imprime? — y por qué cambió afuera
Antes de llamar a la función, arrayPrueba tiene basura en sus 2 posiciones. Al llamar cargarArray(arrayPrueba), la función recibe la dirección de arrayPrueba (su comienzo), así que dentro de la función a es el mismo arreglo que arrayPrueba afuera. La función hace a[0] = 7 y a[1] = 30, que escriben directamente en los casilleros reales. Cuando la función termina, esos cambios quedan. El for entonces muestra:

7
30 ✓

Si los arreglos se pasaran por copia (como un int común), afuera arrayPrueba habría seguido con basura. Pero no: con arreglos, lo que toca la función queda tocado afuera.
Por eso se pasa también N como parámetro aparte
Cuando le pasás un arreglo a una función, la función recibe la dirección de inicio… pero no sabe cuántos elementos útiles tiene (esa información no viaja con el arreglo). Por eso lo habitual es pasar también el N como un segundo parámetro, así la función sabe hasta dónde recorrer. Por ejemplo:

void cargar(int a[], int n) { for(int i = 0; i < n; i++) cin >> a[i]; }

Y como el arreglo es por referencia, lo que la función cargue queda cargado en el arreglo del main.

Errores típicos (para no perder puntos)

Salirse de rango: arr[5] en un int arr[5]
Es el error más grave y el más fácil de cometer por culpa de que los índices arrancan en 0. En int arr[5] las posiciones que existen son 0, 1, 2, 3, 4. La posición 5 NO existe (sería la sexta). Si hacés arr[5] = 10; estás escribiendo fuera del espacio reservado, pisando memoria que no es tuya. C++ muchas veces no te avisa al compilar: el programa parece andar pero corrompe datos o se rompe de forma impredecible (en la materia se anota como "no tengo que cargar datos fuera del espacio reservado"). Regla de oro: el índice máximo válido es tamaño − 1.
Confundir tamaño físico con elementos útiles
Ya lo vimos, pero se repite tanto que va de nuevo: si reservaste int v[100] pero cargaste N = 30, recorré 0 a N − 1 (0 a 29), NO 0 a 99. Procesar las 70 posiciones de basura te arruina cualquier cuenta.
Olvidar que el índice arranca en 0
El primer elemento es arr[0], no arr[1]. Y el "elemento número 5" (el quinto) es arr[4], no arr[5]. Arrancar un recorrido en i = 1 "porque empiezo a contar desde 1" te saltea el primer elemento (el de la posición 0). Salvo casos puntuales (como el máximo, donde arrancás en 1 a propósito porque ya tomaste el 0), los recorridos empiezan en i = 0.

Repaso de la unidad

Lo que tenés que llevarte
• Un arreglo (array / vector) guarda un conjunto de elementos del mismo tipo bajo un solo nombre. Resuelve el problema de "necesito 100 variables".
• Se declara tipo nombre[CANTIDAD_MAX]; (ej. int arr[5];). El tamaño es fijo.
• Se accede con nombre[posicion]. Los índices van de 0 a CANTIDAD_MAX − 1 (¡arrancan en 0!). En int arr[5]: posiciones 0,1,2,3,4; el índice máximo es 4.
• Inicialización por lista: int arr2[3] = {4, 9, 56};.
• Se recorre con for(int i = 0; i < n; i++) usando arr[i] en cada vuelta.
• En memoria es un bloque contiguo; el nombre guarda la dirección de comienzo; ubicar arr[i] es una sola cuenta → acceso directo en tiempo constante, O(1).
• Distinguí tamaño físico (lo reservado) de elementos útiles N (lo cargado). Recorré de 0 a N − 1; el resto es basura.
• Operaciones básicas: cargar (for con cin), búsqueda secuencial (recorrer comparando), copiar (posición a posición), máximo/mínimo (arrancando con arr[0]).
• Los arreglos se pasan a funciones por referencia (se pasa la dirección): lo que la función modifica persiste afuera. Por eso se suele pasar N como parámetro aparte.
