9 Unidad 9: Registros (structs) y arreglos de structs

Hasta ahora, cuando necesitabas guardar muchos datos juntos, usabas un arreglo (un vector): una fila de cajitas que sirve para almacenar muchos valores… pero todos del mismo tipo. Un arreglo de int guarda enteros, uno de string guarda textos. ¿Y si lo que querés describir es una cosa formada por datos de distinto tipo? Por ejemplo una persona: tiene un DNI (un número), un nombre (un texto) y un apellido (otro texto). Para eso existe el registro —en C++, el struct—: un tipo de dato nuevo, inventado por vos, que agrupa varios datos relacionados bajo un solo nombre. En esta unidad vas a aprender a definir tus propios tipos, a meterlos unos adentro de otros, a pasarlos a funciones (por valor y por referencia) y a combinarlos con arreglos. Todo desde cero y con el código tal cual lo da la cátedra.

¿Qué problema resuelve un registro?

Pensá en un punto del plano, como en geometría: tiene una coordenada x y una coordenada y. Las dos son enteros, así que hasta podrías guardarlas en dos variables sueltas:

int x = 3;
int y = 2;
cout << x << ", " << y << endl;   // muestra: 3, 2

Funciona… pero x e y son dos variables independientes: nada en el código dice que "van juntas", que forman un punto. Si ahora querés un segundo punto, te aparece otro par de variables sueltas:

int x2 = 1;
int y2 = 4;
cout << x2 << ", " << y2 << endl;  // muestra: 1, 4

Con dos puntos ya tenés cuatro variables flotando. Con diez puntos, veinte variables. Y si quisieras pasarle "un punto" a una función, tendrías que pasarle dos parámetros y rezar para no mezclarlos. El problema de fondo es que el lenguaje no sabe que x e y son una sola entidad.

Tampoco te salva un arreglo: un arreglo agrupa muchos datos, sí, pero todos del mismo tipo. Un punto justo da la casualidad de ser dos enteros, pero una persona es un int (el DNI) y dos string (nombre y apellido): tipos distintos que no entran juntos en un solo arreglo.

Arreglo vs. registro: la diferencia de fondo
• Un arreglo agrupa muchos datos del MISMO tipo (muchos enteros, muchos textos). Los accedés por posición: v[0], v[1]…
• Un registro (struct) agrupa pocos datos de DISTINTO tipo que describen una entidad (un punto, una persona). Los accedés por nombre de campo: p.x, persona.dni.

Un struct es, ni más ni menos, un tipo de dato definido por vos (el usuario), hecho a medida del problema.

Definir un registro: la palabra clave struct

Para crear un tipo nuevo usás la palabra clave struct, le ponés un nombre y, entre llaves, listás los campos (los datos que lo componen), cada uno con su tipo y su nombre. La forma general es:

struct NombreDelTipo {
    tipoDeDato nombreCampo1;
    tipoDeDato nombreCampo2;
    tipoDeDato nombreCampo3;
    ....
    tipoDeDato nombreCampoN;
};

A cada uno de esos datos internos lo llamamos campo (o miembro, o atributo). Aplicado al punto de la cátedra, que guarda x, y y además una descripcion de texto, queda así:

struct Punto {
    int x;
    int y;
    string descripcion;
};

Leído en castellano: "definí un tipo nuevo llamado Punto; todo Punto tiene un entero x, un entero y y un texto descripcion". Por convención, los nombres de tipos se escriben con mayúscula inicial (Punto, Persona, Recta) para distinguirlos de las variables, que van en minúscula.

Definir un tipo NO crea ninguna variable todavía
La definición de un struct es como un molde o plano de construcción: describe cómo es un Punto, pero no fabrica ninguno. Es como el plano de una casa: el plano no es una casa, es la forma de construir casas. Recién cuando declarás una variable de ese tipo (lo vemos en la próxima sección) se reserva memoria de verdad. Por eso la definición suele ir arriba de todo, antes de main, junto a los #include.
El error más típico: olvidar el ; después de la }
La llave de cierre de un struct lleva punto y coma. Esto es muy fácil de olvidar porque en los if, los for y las funciones la llave de cierre no lo lleva. Pero un struct es una declaración, y como toda declaración termina en ;:

✗ struct Punto { int x; int y; }  → falta el ;, no compila.
✓ struct Punto { int x; int y; };

El error que tira el compilador suele ser confuso y apuntar a la línea de abajo (a veces directo a int main), porque sigue leyendo esperando que la declaración termine. Ante un error raro justo después de un struct, lo primero que tenés que revisar es ese ; final.

Declarar una variable y acceder a los campos: el operador punto .

Una vez definido el tipo Punto, ya podés usarlo igual que usás int o string: para declarar variables. Escribís el nombre del tipo y el nombre de la variable:

Punto punto1;

Esto crea una variable punto1 que adentro tiene los tres campos (x, y, descripcion), todavía sin valores útiles. Para entrar a un campo —tanto para escribirlo como para leerlo— se usa el operador punto .: se escribe la variable, un punto, y el nombre del campo. Se lee "el x de punto1":

Punto punto1;
punto1.x = 3;                  // guardo 3 en el campo x de punto1
punto1.y = 2;                  // guardo 2 en el campo y de punto1
punto1.descripcion = "el punto 1";
cout << punto1.x << ", " << punto1.y << endl;   // muestra: 3, 2

Fijate que punto1.x se comporta exactamente como una variable int: le podés asignar (punto1.x = 3;), lo podés leer (cout << punto1.x;), sumarlo, etc. Lo mismo punto1.descripcion es un string común y corriente. El operador punto simplemente dice cuál de los campos del registro querés tocar.

El operador punto en una frase
variable.campo significa "el campo que vive adentro de variable". A la izquierda del punto va siempre una variable de tipo struct; a la derecha, el nombre de un campo de ese struct. Y ese variable.campo se usa como cualquier dato del tipo del campo.

Inicialización por lista: cargar todos los campos de una

Asignar campo por campo (tres líneas para tres campos) funciona, pero es largo. C++ te deja inicializar el struct entero en el momento de declararlo, usando una lista de valores entre llaves, separados por comas. Los valores se asignan a los campos en el mismo orden en que los definiste:

Punto punto2 = {1, 4, "este es el punto 2"};
cout << punto2.x << ", " << punto2.y << endl;   // muestra: 1, 4

Como en struct Punto el orden de los campos es x, y, descripcion, el 1 va a x, el 4 va a y y el texto "este es el punto 2" va a descripcion. Es decir, estas dos formas dejan a punto2 exactamente igual:

Campo por campoPor lista (equivalente)
Punto punto2;
punto2.x = 1;
punto2.y = 4;
punto2.descripcion = "este es el punto 2";		Punto punto2 = {1, 4, "este es el punto 2"};
El orden importa, y mucho
La lista {...} se asigna por posición, no por nombre. Si te equivocás de orden, el compilador no te avisa (mientras los tipos coincidan) y el programa hace cosas raras. Por ejemplo, Punto p = {4, 1, "x"}; deja x = 4 e y = 1, ¡al revés de lo que quizás querías! Respetá siempre el orden en que aparecen los campos en la definición del struct.

Asignar un struct a otro: se copia TODO (semántica de valor)

Acá hay algo muy importante y muy cómodo: si tenés dos variables del mismo tipo struct, podés asignar una a la otra con un simple =, y C++ copia todos los campos, uno por uno. No tenés que copiar campo por campo a mano.

Punto a = {3, 2, "original"};
Punto b = a;     // b queda con x=3, y=2, descripcion="original": una COPIA de a

Lo crucial: b es una copia totalmente independiente de a. Son dos cajas separadas en memoria que por ahora tienen el mismo contenido. Si después cambiás un campo de b, a no se entera. A esto se lo llama semántica de valor: asignar copia el valor completo, no comparte.

Esto se ve clarísimo con la Recta de la cátedra, que es un struct con dos puntos adentro (ya lo vemos en detalle en la próxima sección; por ahora alcanza con saber que r.p1.x es la x del primer punto de la recta r). Mirá esta secuencia:

Recta r;
r.p1.x = 9;        // la x del primer punto de r vale 9

Recta r3 = r;      // r3 es una COPIA independiente de r
r3.p1.x = 2;       // toco SOLO la copia r3

cout << r.p1.x  << endl;   // muestra: 9   (la original NO cambió)
cout << r3.p1.x << endl;   // muestra: 2   (solo cambió la copia)

Sigamos la traza como si fuéramos la computadora:

Línear.p1.xr3.p1.xQué pasó
r.p1.x = 9;9—r3 todavía no existe.
Recta r3 = r;99r3 nace como copia de r: copia todos los campos, así que su p1.x arranca en 9.
r3.p1.x = 2;92Toco solo a r3. Como es independiente, r queda intacta.
Asignar un struct = fotocopiarlo
Punto b = a; (o b = a;) hace una fotocopia de a dentro de b, campo por campo. Después son dos cosas distintas: tocar una no afecta a la otra. Esto vale aunque el struct tenga otros structs adentro (se copia todo, hasta el último rincón).

Structs anidados: un registro adentro de otro

Un campo de un struct puede ser de cualquier tipo… incluso de otro struct que vos hayas definido antes. A esto se lo llama anidar (un struct dentro de otro). Es la forma natural de modelar cosas que están compuestas por otras cosas.

El ejemplo de la cátedra es la Recta: una recta tiene un nombre y está formada por dos puntos. Como ya tenemos el tipo Punto, lo reutilizamos como tipo de dos campos:

struct Recta {
    string nombre;
    Punto p1;
    Punto p2;
};

Ahora, para acceder a un campo que está dentro de otro struct, encadenás el operador punto: primero entrás a la Recta, después al Punto, después al campo del punto. Se lee de izquierda a derecha:

Recta r;
r.nombre = "recta ejemplo 1";
r.p1.x = 9;                    // la x  del punto p1 de la recta r
r.p1.y = 7;                    // la y  del punto p1 de la recta r
r.p1.descripcion = "aaaaa";
r.p2 = punto1;                 // a p2 le asigno un Punto entero (copia)

cout << r.p2.x << endl;        // la x del punto p2 de la recta r

Desglosá r.p1.x de izquierda a derecha: r es la recta → .p1 es su primer punto → .x es la coordenada x de ese punto. Tres puntos, tres niveles. Y fijate en r.p2 = punto1;: a un campo que es Punto le podés asignar otro Punto entero de una sola vez (se copian sus tres campos), exactamente por la semántica de valor de la sección anterior.

Una Recta también se puede inicializar por lista, anidando llaves: la lista de afuera es para la Recta, y donde va un Punto metés otra lista entre llaves:

Recta r2 = {"abc", {1, 4, "bbbb"}, punto1};
//          nombre   ↑ p1 (un Punto entre llaves)   ↑ p2 (un Punto ya existente)

El anidamiento puede tener más de un nivel. La cátedra modela una Persona que, además de DNI, nombre y apellido, tiene una dirección, que a su vez es un struct con calle, número, etc. Primero se define el tipo interno y después el que lo usa:

struct Direccion {
    string calle;
    int nro;
    int cp;
    string provincia;
    string pais;
};

struct Persona {
    int dni;
    string nombre;
    string apellido;
    Direccion direccion;
};

Y se accede igual, encadenando puntos hasta el campo que querés:

Persona persona;
persona.dni = 40123456;
persona.nombre = "Ana";
persona.direccion.calle = "Medrano";   // la calle, de la direccion, de la persona
persona.direccion.nro = 951;
cout << persona.direccion.calle << endl;   // muestra: Medrano
Regla para definir tipos anidados
El tipo interno tiene que estar definido antes de usarlo. Por eso Punto se define arriba de Recta, y Direccion arriba de Persona: cuando el compilador lee Punto p1; dentro de Recta, ya tiene que saber qué es un Punto. Y para acceder, recordá la lectura de izquierda a derecha: persona.direccion.calle = "la calle, de la dirección, de la persona".

Funciones con structs: recibir, devolver y modificar

La gran ventaja de tener un tipo propio es que ahora podés tratar a un punto como un solo dato: pasárselo a una función completo, o que una función te devuelva uno. Veamos los tres casos, con el código de la cátedra.

Recibir un struct por valor

Una función puede recibir un struct como parámetro, igual que recibe un int. Acá un procedimiento que muestra un punto:

void mostrarPunto(Punto p) {
    cout << p.x << ", " << p.y << endl;
}

Y se lo llamamos pasándole una variable Punto entera:

mostrarPunto(punto1);   // muestra: 3, 2

Como el parámetro p se recibe por valor, lo que entra a la función es una copia de punto1 (con todos sus campos). Adentro, p es una variable local; cualquier cosa que le hicieras a p no tocaría a punto1.

Devolver un struct

Una función puede construir un struct adentro y devolverlo con return. El tipo de retorno (a la izquierda del nombre) es el nombre del struct. Esta función arma un punto nuevo que es la suma de otros dos:

Punto sumar(Punto p1, Punto p2) {
    Punto res;
    res.x = p1.x + p2.x;
    res.y = p1.y + p2.y;
    return res;
}

Adentro declara un Punto res, le carga campo por campo la suma, y lo devuelve con return res;. Quien la llama recibe ese punto y lo puede guardar en una variable:

Punto p3 = sumar(punto1, punto2);   // p3.x = 3+1 = 4 ; p3.y = 2+4 = 6

Con punto1 = {3,2,...} y punto2 = {1,4,...}, el resultado p3 tiene x = 4 e y = 6. (La función no toca la descripcion, así que ese campo de res queda sin un valor útil; en este ejemplo no importa porque solo nos interesan las coordenadas.)

Modificar el original: recibir por referencia con &

¿Y si quiero que la función cambie el punto original, no una copia? Para eso se recibe el parámetro por referencia, poniendo un & (ampersand) después del tipo. Con &, el parámetro no es una copia: es el mismo dato de afuera, con otro nombre adentro. Lo que le hagas, le pasa al original.

void incX(Punto& p) {
    p.x = p.x + 1;
}

Mirá el efecto al llamarla. punto1.x valía 3; después de incX(punto1) vale 4, de verdad:

incX(punto1);
cout << punto1.x << endl;   // muestra: 4

Tracemos qué pasa con punto1.x:

Momentopunto1.xComentario
Antes de llamar3Lo dejamos así en punto1.x = 3;.
Dentro de incX3 → 4Como p es Punto& p, es punto1: p.x = p.x + 1 le suma 1 al original.
Después de volver4El cambio quedó: punto1.x ahora vale 4.

Si incX hubiera recibido el punto por valor (void incX(Punto p), sin el &), habría incrementado solo su copia local y punto1.x habría seguido valiendo 3 afuera. El & es lo que marca toda la diferencia.

Por valor vs. por referencia, con structs
• Por valor (void f(Punto p)): entra una copia. La función puede leerla y trastearla, pero el original de afuera no cambia.
• Por referencia (void f(Punto& p), con &): entra el mismo dato. Lo que la función modifica sí cambia afuera.

Además, pasar un struct por valor copia todos sus campos, y si el struct es grande eso cuesta tiempo y memoria. Por eso muchas veces se pasan por referencia: para modificar el original o simplemente para evitar la copia.
Creer que "por valor" modifica el original
Un error clásico: escribís void incX(Punto p) (sin &), adentro hacés p.x = p.x + 1;, y te sorprende que afuera punto1.x siga en 3. No está roto: sin &, p es una copia, y le sumaste 1 a la copia, que se descarta al terminar la función. Si querés tocar el original, necesitás el &.

Arreglos de structs: juntar las dos ideas

Ahora combinamos lo de esta unidad con los arreglos: nada te impide hacer un arreglo cuyos elementos son structs. Cada casillero del arreglo es un struct completo. Es la forma natural de guardar muchas entidades del mismo tipo: muchos puntos, muchas personas.

Punto puntos[2] = { {1, 2}, {3, 4} };

Esto crea un arreglo de 2 Punto. Cada par de llaves de adentro inicializa un punto: el casillero 0 queda en {1,2} y el 1 en {3,4}. (Como solo damos dos valores por punto, se completan x e y; la descripcion queda vacía.) Para llegar a un campo, primero elegís el elemento con el corchete [i] y después aplicás el punto:

cout << puntos[0].x << endl;   // muestra: 1   (la x del punto en la posicion 0)
cout << puntos[1].y << endl;   // muestra: 4   (la y del punto en la posicion 1)

La lectura de puntos[1].y es, de izquierda a derecha: puntos es el arreglo → [1] elige el segundo elemento (un Punto) → .y es su coordenada y. Y como es un arreglo, lo recorrés con un for de toda la vida, usando puntos[i] en cada vuelta:

for (int i = 0; i < 2; i++) {
    cout << puntos[i].x << ", " << puntos[i].y << endl;
}
/* Muestra:
   1, 2
   3, 4
*/

También podés declarar el arreglo vacío (sin inicializar) y cargar cada casillero después, asignándole un struct entero. Así aparece en el archivo de complejos de la cátedra:

Complejo arr[5];      // arreglo de 5 Complejo, todavia sin cargar
arr[0] = c1;          // en la posicion 0 guardo el complejo c1 (copia)
arr[1] = c2;
arr[3] = c3;

cout << arr[3].real << " " << arr[3].imaginaria << "i" << endl;

Cada arr[i] = ...; copia un Complejo entero en ese casillero (otra vez la semántica de valor). Y arr[3].real es "la parte real del complejo que está en la posición 3".

Primero el corchete, después el punto
En un arreglo de structs el orden es arreglo[i].campo: primero elegís cuál elemento con [i], y después entrás a su campo con .. Escribir arreglo.campo[i] no tiene sentido (el arreglo no tiene un campo campo) y no compila.

Ejemplo integrador completo: números complejos

Cerramos juntando todo lo de la unidad en un solo programa: el de números complejos de la cátedra. Un número complejo tiene una parte real y una parte imaginaria (lo que en matemática escribís como 3 + 5i). Lo modelamos con un struct de dos campos float:

struct Complejo {
    float real;
    float imaginaria;
};

Ahora tres módulos que muestran los tres usos de structs en funciones. Primero, uno que crea un complejo a partir de sus partes y lo devuelve (usa inicialización por lista adentro):

Complejo crearComplejo(float real, float imaginaria) {
    Complejo c = {real, imaginaria};
    return c;
}

Segundo, uno que recibe dos complejos por valor y devuelve su suma (sumar dos complejos es sumar real con real e imaginaria con imaginaria):

Complejo sumarComplejos(Complejo c1, Complejo c2) {
    Complejo c = {c1.real + c2.real, c1.imaginaria + c2.imaginaria};
    return c;
}

Tercero, un procedimiento que multiplica un complejo por un número (un escalar). Como queremos modificar el complejo original, lo recibimos por referencia con &:

void multiplicarEscalar(Complejo& c, int valor) {
    c.real = c.real * valor;
    c.imaginaria = c.imaginaria * valor;
}

Y el main que lo usa todo —crear, sumar, multiplicar por referencia y guardar en un arreglo—:

int main() {

    Complejo c1 = crearComplejo(40, 10);
    Complejo c2 = crearComplejo(50, 5);

    Complejo c3 = sumarComplejos(c1, c2);
    cout << c3.real << " " << c3.imaginaria << "i" << endl;

    multiplicarEscalar(c3, 2);
    cout << c3.real << " " << c3.imaginaria << "i" << endl;

    Complejo arr[5];
    arr[0] = c1;
    arr[1] = c2;
    arr[3] = c3;

    cout << arr[3].real << " " << arr[3].imaginaria << "i" << endl;

    return 0;
}

Sigamos la traza paso a paso, como una computadora:

LíneaQué haceEstado / salida
c1 = crearComplejo(40, 10);Crea y devuelve un complejo.c1 = {40, 10}

cout << c3...Muestra c3.imprime 90 15i

cout << arr[3]...Muestra el complejo de la posición 3.imprime 180 30i

La salida completa del programa es:

90 15i
180 30i
180 30i

En catorce líneas de main usaste todo: definiste un tipo propio (struct Complejo), una función que devuelve un struct (crearComplejo), otra que recibe structs y devuelve uno (sumarComplejos), un procedimiento que modifica por referencia (multiplicarEscalar con &), accediste a campos con el punto (c3.real) y guardaste structs en un arreglo (arr). Ese es exactamente el repertorio de la unidad, funcionando junto.

Repaso de la unidad

Lo que tenés que llevarte
• Un registro (struct) es un tipo de dato definido por vos que agrupa campos de distinto tipo para describir una entidad (un punto, una persona).
• Se define con struct Nombre { tipo campo1; tipo campo2; ... };  ¡con ; después de la }!
• Se declara como cualquier variable (Punto p1;) y se accede a los campos con el operador punto: p1.x = 3; cout << p1.x;.
• Se puede inicializar por lista, en el orden de los campos: Punto p2 = {1, 4, "..."};.
• Asignar copia todo (semántica de valor): Recta r3 = r; crea una copia independiente; tocar r3 no afecta a r.
• Los structs se pueden anidar: un campo puede ser otro struct (Recta con dos Punto; Persona con Direccion), y se accede encadenando puntos (r.p1.x, persona.direccion.calle).
• Las funciones pueden recibir structs (por valor = copia), devolverlos (return res;) y modificar el original recibiéndolos por referencia con & (void incX(Punto& p)).
• Un arreglo de structs guarda muchas entidades del mismo tipo; se accede arreglo[i].campo (primero el corchete, después el punto) y se recorre con un for.
