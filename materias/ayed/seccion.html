1 Unidad 1: Introducción — algoritmos, datos y tu primer programa

Esta primera unidad arranca de cero absoluto: vas a entender qué es un algoritmo, qué son los datos, qué significa programar, y vas a escribir, entender línea por línea y correr tu primer programa en C++. No hace falta saber nada previo.

¿Qué es un algoritmo?

Un algoritmo es una secuencia finita de pasos, ordenados y bien definidos, que resuelven un problema. La idea clave es que si seguís esos pasos en el orden indicado, siempre llegás al mismo resultado para la misma entrada: el comportamiento es predecible.

No es algo exclusivo de las computadoras. Usás algoritmos todo el tiempo en la vida real, solo que no los llamás así.

Algoritmos de la vida cotidiana
Receta de cocina — "1) Calentar el agua. 2) Cuando hierve, echar los fideos. 3) Esperar 10 minutos. 4) Colar." Son pasos, en orden, que resuelven el problema "cocinar fideos".

Llegar a la facultad — "1) Tomar el 28. 2) Bajar en Medrano. 3) Caminar 2 cuadras." Si alguien sigue exactamente esos pasos, llega al mismo lugar.

El trabajo del programador es escribir estos "pasos" de forma tan precisa que hasta una máquina —que no entiende sobreentendidos ni "vos ya sabés"— pueda ejecutarlos sin equivocarse.
Propiedades de todo buen algoritmo
• Preciso: cada paso no deja lugar a dudas (nada de "agregar sal a gusto").
• Ordenado / definido: los pasos tienen un orden claro y conocés cuál sigue.
• Finito: termina en algún momento, después de una cantidad limitada de pasos.
• Determinístico: con la misma entrada produce siempre la misma salida.
• Tiene entrada (los datos con los que arranca, que pueden ser cero) y salida (el resultado).

¿Qué son los datos y qué es una estructura de datos?

Un dato es un valor que el programa manipula: el número 42, la palabra "Hola", el valor lógico verdadero. Los algoritmos no operan en el vacío: leen datos, los transforman y producen nuevos datos.

Una estructura de datos es la forma de organizar esos datos para poder usarlos cómodamente en el algoritmo. No es lo mismo tener 100 números sueltos que tenerlos ordenados en una "lista" donde podés acceder al elemento número 37 de una.

La ecuación que da nombre a la materia
Algoritmos + Estructuras de datos = Programas. Esta frase (del científico Niklaus Wirth) resume la materia: un programa útil combina buenos pasos (algoritmos) operando sobre datos bien organizados (estructuras de datos). Las primeras unidades se enfocan en los algoritmos; más adelante aparecen las estructuras (vectores, registros).

¿Qué significa "programar"? Lenguajes y compilación

La computadora, en el fondo, solo entiende lenguaje de máquina: ceros y unos. Escribir directamente en ceros y unos sería imposible para un humano. Por eso usamos lenguajes de programación de alto nivel —como C++— que se parecen más al inglés y a las matemáticas, y que después se traducen a lenguaje de máquina.

El texto que vos escribís se llama código fuente (un archivo de texto, en C++ con extensión .cpp). Pero ese texto no se puede ejecutar tal cual: hay que traducirlo.

C++ es un lenguaje COMPILADO
El camino de tu código a un programa que corre es:

código fuente (programa.cpp) → COMPILADOR → ejecutable (un archivo que la máquina puede correr).

El compilador es un programa que lee todo tu .cpp, revisa que esté bien escrito (si hay errores de sintaxis, no compila y te avisa) y genera el ejecutable. Esto se hace una vez; después corrés el ejecutable las veces que quieras. (Otros lenguajes, como Python, son interpretados: se traducen línea por línea cada vez que corren. C++ no: primero compila, después ejecuta.)

Tu primer programa: "Hola mundo", línea por línea

Este es el programa más simple que muestra un texto en pantalla. Mirálo entero y después lo desarmamos:

#include <iostream>
using namespace std;

int main() {
    cout << "Hola mundo" << endl;
    return 0;
}

Cada parte cumple un rol concreto:

#include <iostream>

Es una directiva que le dice al compilador: "traé el conjunto de herramientas de entrada/salida". iostream significa input/output stream (flujo de entrada/salida). Gracias a esta línea podemos usar cout (mostrar en pantalla) y cin (leer del teclado). Sin ella, el programa no sabría qué es cout.

using namespace std;

Las herramientas estándar de C++ viven en un "espacio de nombres" llamado std (de standard). Esta línea nos permite escribir cout en lugar de std::cout cada vez. Es una comodidad: la vas a ver en casi todos los programas de la materia.

int main() { ... }

Es la función principal: el punto de arranque de todo programa en C++. Cuando ejecutás el programa, la computadora busca main y empieza a correr las líneas que están entre sus llaves { }, de arriba hacia abajo. Todo programa tiene exactamente un main.

Inicio y fin de tu programa
Comienzo: int main() {
Fin:     return 0; seguido de }

Todo lo que quieras que el programa haga va adentro de esas llaves.

cout << "Hola mundo" << endl;

Esta es la línea que hace algo visible: muestra el texto Hola mundo en pantalla y baja un renglón. La explicamos en detalle en la próxima sección.

return 0;

Le indica al sistema operativo que el programa terminó bien. El 0 significa "todo salió OK" (un número distinto se usaría para indicar que hubo un error). Como main está declarada como int (devuelve un entero), debe terminar devolviendo un número: por eso return 0;.

Mostrar por pantalla: cout y endl

cout (se lee "ci-aut", console output) es la salida estándar: la pantalla. Para mandarle algo se usa el operador <<, que podés imaginar como una flecha que empuja datos hacia la pantalla.

cout << "Hola mundo";        // muestra: Hola mundo
cout << 42;                  // muestra: 42
cout << "Edad: " << 20;      // muestra: Edad: 20

Fijate que podés encadenar varios << en una misma línea: cada uno empuja una cosa más a la pantalla, en orden, de izquierda a derecha. El texto entre comillas dobles ("...") se muestra tal cual; los números se muestran sin comillas.

endl y "\n": el salto de línea

endl (de end line) produce un salto de renglón: lo próximo que se muestre aparece en la línea de abajo. Es lo mismo que escribir "\n" dentro de un texto.

cout << "Linea 1" << endl;
cout << "Linea 2" << endl;

/* Muestra en pantalla:
   Linea 1
   Linea 2
*/
Error típico: olvidar los << entre cada cosa
Si querés mostrar un texto y un número juntos, cada elemento necesita su propia flecha:
✗ cout << "Edad: " 20;  → error, falta el << antes del 20.
✓ cout << "Edad: " << 20;

Comentarios: notas para humanos

Un comentario es texto que el compilador ignora por completo. Sirve para que vos (o quien lea el código) entienda qué hace cada parte. No afecta en nada lo que el programa ejecuta.

Hay dos formas:

// Comentario de UNA línea: desde las // hasta el final del renglón.

/* Comentario de
   VARIAS líneas: todo lo que está
   entre la barra-asterisco queda comentado. */

cout << "Hola" /* incluso en el medio de una linea */ << endl;
Usá comentarios desde el día uno
Comentar bien tu código es una costumbre profesional, no un adorno. Te ayuda a recordar qué pensabas y le facilita la corrección al docente. Pero comentá el porqué, no lo obvio: x++; // sumo 1 a x no aporta nada; x++; // cuento un alumno mas sí.

El punto y coma ; y los bloques { }

En C++, cada sentencia (cada instrucción completa) termina con un punto y coma ;. Es el delimitador de sentencias: le dice al compilador "esta orden terminó acá".

Las llaves { } sirven para agrupar varias sentencias en un bloque que se trata como una unidad (ya viste el bloque de main; más adelante los vas a usar en if, ciclos, funciones).

El error número uno de quien empieza: olvidar el ;
Si olvidás un punto y coma, el compilador se confunde y tira un error que muchas veces apunta a la línea siguiente (porque sigue leyendo esperando que la sentencia anterior termine). Ante un error raro de compilación, lo primero que conviene revisar es si falta un ; en la línea de arriba.

¿Cómo corro mi programa?

En la materia se trabaja típicamente con un editor como Visual Studio Code + un compilador de C++ (como g++, de MinGW). El flujo es siempre el mismo:

PasoQué pasa
1. Escribís el códigoGuardás el archivo .cpp (código fuente).
2. CompilásEl compilador traduce y, si no hay errores, genera el ejecutable. Si hay errores, los corregís y volvés a compilar.

La regla mental más importante para empezar
Salvo que una estructura de control diga lo contrario (lo verás en las próximas unidades), el programa se ejecuta secuencialmente, de arriba hacia abajo, una sentencia a la vez. Cuando leas un programa, "hacé de computadora": seguí las líneas en orden imaginando qué va pasando.

2 Unidad 2: Variables y tipos de datos

En la unidad anterior tu programa solo mostraba textos fijos. En esta unidad vas a aprender a guardar datos en la memoria de la computadora para poder usarlos, modificarlos y mostrarlos: eso son las variables. También vas a ver de qué tipos pueden ser esos datos (números enteros, decimales, caracteres, textos, valores de verdadero/falso) y cómo leer un dato que el usuario escribe por teclado. Seguimos de cero: cada término nuevo lo definimos antes de usarlo.

¿Qué es una variable?

Una variable es un espacio en la memoria de la computadora donde tu programa guarda un dato para usarlo más tarde. Pensala como una cajita con una etiqueta: la etiqueta es el nombre que vos le ponés, y adentro de la cajita hay un valor que podés mirar o cambiar.

¿Por qué se llama "variable"? Porque su contenido puede variar mientras el programa corre: hoy la cajita guarda un 10, dos líneas después puede guardar un 27. Lo que no cambia es su nombre ni el tipo de dato que puede guardar.

Las 3 componentes de toda variable
Cada variable que creás tiene siempre estas tres cosas:

• IDENTIFICADOR — el nombre con el que la llamás. Ej: edad, cantidadDeAlumnos. Es la "etiqueta" de la cajita.
• VALOR — el dato que guarda adentro en este momento. Ej: 20.
• TIPO DE DATO asociado — qué clase de dato puede guardar: un número entero, un decimal, una letra, un texto... Lo elegís vos al crearla y ya no cambia.
La analogía de la cajita
Imaginá una cajita etiquetada edad que solo acepta números enteros y que adentro tiene un 20:

• IDENTIFICADOR → edad (lo que dice la etiqueta)
• VALOR → 20 (lo que hay adentro hoy)
• TIPO → número entero (lo que la cajita acepta guardar)

Mañana podés cambiar el contenido a 21, pero la etiqueta sigue diciendo edad y la cajita sigue aceptando solo enteros.

Las dos etapas de una variable: definición y asignación

Para usar una variable hay dos momentos bien distintos que tenés que separar en tu cabeza: primero la creás (definición) y después le ponés valores (asignación). Vamos una por una.

Etapa 1 — DEFINICIÓN (crear la variable)

Definir una variable es crear la cajita: reservar el espacio en memoria y decirle al compilador su nombre y su tipo. Se escribe así:

<tipo de dato> <nombre de la variable>;

// ejemplo real:
int x;

Esa línea se lee: "creá una variable llamada x que va a guardar números enteros (int)". Dos reglas clave sobre la definición:

• Se hace una sola vez por variable, antes de poder usarla. No tiene sentido (ni se permite) volver a definir la misma variable.

• Ni bien la definís y todavía no le pusiste un valor, la cajita no está vacía: tiene un valor BASURA, un número aleatorio e impredecible que quedó de antes en esa zona de memoria. Nunca confíes en ese valor.

Error típico: usar una variable recién definida (valor basura)
Apenas definís int x;, x NO vale 0: vale lo que haya quedado en esa posición de memoria (puede ser 32766, -4391, cualquier cosa). Si la mostrás o la usás en una cuenta sin haberle asignado nada antes, vas a obtener resultados aleatorios y distintos en cada ejecución. Regla de oro: nunca uses una variable que no inicializaste vos.

Etapa 2 — ASIGNACIÓN (ponerle un valor)

Asignar es guardar un valor adentro de la cajita que ya existe. Se usa el signo =, que en programación NO significa "es igual" sino "asigná" / "guardá":

<nombre de la variable> = <valor>;

// ejemplo real:
x = 10;

Eso se lee: "guardá el valor 10 dentro de x". A diferencia de la definición, la asignación se puede repetir todas las veces que quieras: cada nueva asignación pisa (reemplaza) el valor anterior.

El = es asignación, no igualdad
En x = 10; pensalo como una flecha hacia la izquierda: el valor va a la DERECHA y la variable que lo recibe va a la IZQUIERDA. El valor de la derecha "viaja" hacia la cajita de la izquierda.

Por eso x = 10; es válido (guardá 10 en x) pero 10 = x; NO tiene sentido: no podés guardar nada "dentro del número 10".
Una variable, varias asignaciones (traza paso a paso)
int x;        // DEFINICIÓN: existe x, pero adentro hay BASURA
x = 10;       // ASIGNACIÓN: ahora x vale 10
x = 25;       // ASIGNACIÓN: el 10 se pisa, ahora x vale 25
x = x + 5;    // ASIGNACIÓN: toma el valor actual (25), suma 5, guarda 30
Seguimos el contenido de la cajita x línea por línea:
• Tras int x; → x = basura
• Tras x = 10; → x = 10
• Tras x = 25; → x = 25
• Tras x = x + 5; → x = 30  (primero se calcula la derecha con el valor viejo: 25 + 5 = 30, y recién después se guarda en x)

El atajo: definición con inicialización

Casi siempre vas a querer darle un valor a la variable en el mismo momento de crearla, así nunca queda con basura. Eso se llama inicializar, y combina las dos etapas en una sola línea:

int x = 10;    // define x (entero) Y le guarda 10 de una

Es equivalente a hacer int x; y después x = 10;, pero más corto y más seguro (no pasás por el estado de basura). Es la forma que vas a usar la mayoría de las veces.

Reglas para nombrar variables (identificadores)

El identificador es el nombre de la variable. No podés ponerle cualquier cosa: C++ tiene reglas obligatorias (si no las cumplís, no compila) y además hay convenciones (buenas costumbres que no son obligatorias pero que todos siguen).

Reglas OBLIGATORIAS (si no, error de compilación)
• Puede tener letras (a–z, A–Z), dígitos (0–9) y el guion bajo _. Nada más.
• No puede empezar con un dígito. edad2 es válido; 2edad no.
• Sin espacios. cantidad alumnos es inválido; usá cantidadAlumnos o cantidad_alumnos.
• Sin tildes ni eñes ni símbolos (á, ñ, $, %...). Escribí numeroDNi­os sin la eñe, por ejemplo cantidadNenes.
• No puede ser una palabra reservada del lenguaje (como int, return, main).
C++ distingue MAYÚSCULAS de minúsculas (case sensitive)
Para C++, edad, Edad y EDAD son tres variables DISTINTAS. Si definís int edad; y después escribís Edad = 20;, el compilador te dice que Edad no existe. Cuidá siempre cómo escribís cada letra: este es uno de los errores más comunes al empezar.

Convención: camelCase y nombres descriptivos

La convención que se usa en la materia (y en gran parte del mundo C++) para nombres de varias palabras es camelCase: la primera palabra va en minúscula y cada palabra siguiente arranca con mayúscula, todo pegado, sin espacios ni guiones.

int cantidadDeAlumnosEnElCurso;   // camelCase
float promedioFinal;
string nombreDelUsuario;

Se llama así porque las mayúsculas en el medio parecen las jorobas de un camello. Además, elegí nombres descriptivos: que el nombre diga qué guarda la variable.

Un buen nombre se explica solo
Comparál: int c; vs int cantidadDeAlumnos;. Las dos funcionan, pero la segunda hace que tu código se lea como una frase y no tengas que adivinar qué es c. Nombres claros = menos errores y corrección más fácil. Evitá nombres de una sola letra salvo para cosas muy chiquitas y momentáneas.

Tipos de datos

El tipo de dato define qué clase de valor guarda la variable y, muy importante, cuánta memoria ocupa. La memoria se mide en bytes (un byte son 8 bits, es decir 8 ceros/unos). Cuantos más bytes, más grande es el rango de valores que entra. Vamos a recorrer todas las familias.

Numéricos enteros

Guardan números sin parte decimal (…, -2, -1, 0, 1, 2, …). Se diferencian por cuántos bytes ocupan, y por lo tanto por cuán grandes pueden ser:

TipoTamañoPara qué

short int2 bytesEnteros chicos

long int4 bytesEnteros grandes

En la práctica, mientras aprendés, casi siempre vas a usar int para los enteros.

signed vs unsigned: ¿admite negativos o no?

Cada tipo entero puede ser:

• signed (con signo): admite negativos y positivos. Es el comportamiento por defecto: si escribís int a secas, es signed.

• unsigned (sin signo): NO admite negativos, solo desde 0 hacia arriba. A cambio, como no "gasta" la mitad del rango en números negativos, duplica el máximo positivo que puede guardar.

El caso de unsigned short (sacado del código de la cátedra)
Un short int ocupa 2 bytes. Con signo llega hasta unos 32767. Pero sin signo (sin gastar rango en negativos) llega al doble, hasta 65535: 
unsigned short int x = 65535;   // máximo valor que entra en un short sin signo
Por eso unsigned conviene cuando sabés que el valor nunca va a ser negativo (una cantidad de personas, una edad) y querés aprovechar todo el rango positivo.

Numéricos decimales (de punto flotante)

Guardan números con parte decimal, como 1.5, 3.14159 o -0.001. (En C++ el separador decimal es el punto, no la coma.)

Booleano

El tipo bool (1 byte) guarda un valor de verdad: solo puede valer true (verdadero) o false (falso). Sirve para responder preguntas de sí/no (¿el usuario es mayor de edad?, ¿el número es par?). Lo vas a usar muchísimo cuando lleguen las decisiones (if).

bool vBooleanaA = true;
bool vBooleanaB = false;

Carácter: char con comilla SIMPLE

El tipo char (1 byte) guarda un único carácter: una letra, un dígito o un símbolo. El valor va siempre entre comillas SIMPLES ' ':

char letra = 'A';    // UN carácter, comilla simple
char signo = '$';
char digito = '7';   // ojo: esto es el CARÁCTER 7, no el número 7

Cadena de caracteres: string con comillas DOBLES

El tipo string guarda un texto: un conjunto de caracteres, de cualquier largo. El valor va siempre entre comillas DOBLES " ". (Ocupa 1 byte por cada carácter, más 1 byte extra de control.)

string saludo = "Hola mundo";    // un texto, comillas dobles
string nombre = "Adrian";
Error típico: confundir 'A' (char) con "A" (string)
Aunque parezcan lo mismo, son tipos distintos:
• 'A' con comilla simple → es un char, UN solo carácter.
• "A" con comillas dobles → es un string, un texto (que justo tiene un carácter).

Por eso char c = "A"; da error (le estás dando un texto a una cajita de un solo carácter) y char c = 'A'; es lo correcto. Regla simple: comilla simple para char, comillas dobles para string.

Un char en el fondo es un número (código ASCII)

Acá viene algo que sorprende a todos: la computadora no sabe de letras, solo de números. Cada carácter tiene asociado un número entero según una tabla estándar llamada ASCII. Por ejemplo, la letra 'A' es el número 65, la 'B' el 66, y así. Por eso un char "es" un número de 1 byte por dentro.

Esto significa que podés definir un char dándole directamente su número ASCII:

char y = 65;     // 65 es el código ASCII de 'A', así que y vale 'A'

¿Cómo veo el número que hay detrás de un carácter? Si hacés cout << letra; vas a ver la letra (A), porque cout sabe que es un char y lo muestra como carácter. Para ver el número hay dos trucos que usa la cátedra:

• El + adelante (+letra): ese + fuerza a que el char se trate como número entero, así cout muestra el código en lugar de la letra.

• printf("%d", letra): printf es otra forma de mostrar por pantalla; el %d significa "mostralo como número entero (decimal)", forzando también a ver el código.

Ver la letra y su código ASCII (programa de la cátedra)
#include <iostream>
using namespace std;

int main() {
    char letra = 'A';   // guarda la letra A (ASCII 65)
    char y = 65;        // guarda el código 65, que ES la letra A

    cout << "El valor de letra es: " << +letra << endl;  // el + muestra el NÚMERO
    cout << "El valor de y es: " << y << endl;            // sin +, muestra la LETRA

    printf("%d", letra);   // %d fuerza a mostrar el número: 65
    printf("%d", y);       // idem: 65

    return 0;
}
Salida en pantalla:
El valor de letra es: 65
El valor de y es: A
6565
Fijate la diferencia: con +letra aparece 65 (el número), y con y a secas aparece A (la letra). Los dos printf imprimen 65 pegados (no hay salto de línea entre ellos), por eso se ve 6565.

Leer un dato por teclado: cin

Hasta ahora vos ponías los valores en el código. Pero lo interesante es que el usuario escriba un dato mientras el programa corre. Para eso está cin (se lee "ci-in", de console input): la entrada estándar, o sea el teclado.

Se usa con el operador >>. Si en la unidad 1 viste que cout << empuja datos hacia la pantalla, acá la flecha apunta al revés: cin >> variable trae lo que se escribe en el teclado y lo mete dentro de la variable. La flecha apunta desde el teclado HACIA la variable.

<tipo de dato> <nombre variable>;   // primero defino la cajita
cin >> <nombre variable>;            // después leo el teclado y lo guardo ahí
Leer un entero y mostrarlo
#include <iostream>
using namespace std;

int main() {
    int x;                       // defino la cajita (todavía con basura)
    cout << "Ingresa un numero: ";
    cin >> x;                     // el usuario escribe; ese valor se guarda en x
    cout << "Ingresaste el " << x << endl;
    return 0;
}
Si el usuario escribe 7 y aprieta Enter, la pantalla muestra:

Errores típicos con variables

Elegir un tipo que no alcanza para el valor (overflow)
Cada tipo tiene un máximo. Si intentás guardar un valor más grande del que entra, el número "se desborda" (overflow) y obtenés un resultado incorrecto, no un error. Ejemplo: un unsigned short llega hasta 65535; si le guardás 70000, el valor da la vuelta y queda algo chiquito y sin sentido. Solución: elegí el tipo según el rango de valores que vas a manejar (ante la duda con enteros, usá int).
Los tres errores que más vas a cometer al principio
• Usar una variable sin inicializar → te trae un valor BASURA aleatorio.
• Confundir 'A' (char, comilla simple) con "A" (string, comillas dobles).
• Equivocarte con mayúsculas/minúsculas del nombre (Edad ≠ edad).

Si un programa "anda mal sin razón", revisá primero estas tres cosas.

¿Qué es una expresión? ¿Qué es un operador?

Una expresión es cualquier combinación de valores y operadores que la computadora puede evaluar (calcular) hasta obtener un único resultado. Pensala como una cuenta: tiene "ingredientes" y una "operación" que los combina, y al final da un valor.

Dentro de una expresión hay dos piezas:

Operadores y operandos
• Un operador es el símbolo que indica qué operación hacer: + (sumar), * (multiplicar), < (menor que), etc.
• Un operando es cada valor sobre el que el operador trabaja. Pueden ser números escritos directamente (4, 6), variables (x, z) u otras expresiones.

Ejemplo: en 4 + 6, el + es el operador y 4 y 6 son los dos operandos. El resultado de evaluar esa expresión es 10.

Una expresión puede ser tan simple como un solo número (42 es una expresión que vale 42) o tan grande como quieras (x + 3 * 4 - z). Lo importante: toda expresión, al evaluarse, se reduce a un único valor de algún tipo (un número, o un bool, etc.).

Según cuántos operandos toma, un operador puede ser:

Operadores unarios y binarios
• Binario: trabaja con dos operandos, uno a cada lado. Es lo más común: a + b, x < y, p && q.
• Unario: trabaja con un solo operando. Por ejemplo el ! (negación lógica) se escribe delante de su único operando: !encontrado.

Operadores aritméticos: número op número → número

Los operadores aritméticos toman dos números y producen otro número. Son los que ya conocés de la matemática, más uno nuevo (el resto). En la cátedra se resumen así: NÚMERO op NÚMERO ⟶ NÚMERO.

La división / a fondo: división ENTERA vs división real

Acá está la trampa más importante de toda la unidad. En C++, el tipo del resultado de la división depende del tipo de los operandos:

La regla de oro de la división
• Si los dos operandos son enteros, C++ hace una división entera: calcula cuántas veces entero entra uno en el otro y descarta (tira) la parte decimal. No redondea: la corta.
• Si al menos uno de los operandos es real (tiene decimales, como 5.0), C++ hace la división real y conserva los decimales. 
cout << 5 / 2 << endl;     // 2   (entero / entero  -> division ENTERA, se descarta el .5)
cout << 5.0 / 2 << endl;   // 2.5 (uno es real -> division REAL, conserva decimales)
cout << 7 / 2 << endl;     // 3   (3.5 -> se corta el .5, queda 3)
cout << 1 / 4 << endl;     // 0   (0.25 -> se descarta todo el decimal, queda 0)

Fijate que 5 / 2 no da 2.5 ni 3: da 2. La computadora no redondea hacia el más cercano, simplemente elimina lo que está después de la coma. Por eso 1 / 4 da 0 y no 0.25: ambos son enteros, el resultado real sería 0,25, y al descartar el decimal queda 0.

Esto aparece tal cual en el código de la cátedra (clase_02_operaciones_aritmeticas.cpp). Mirá cómo el tipo de la variable que recibe y el de los operandos cambian todo:

float v1 = 3;

float d = v1 / 2;     // v1 es float (real), asi que la division es REAL: 3.0 / 2 = 1.5
cout << d << endl;     // 1.5

float v = 3.0 / 2;    // 3.0 es real -> division REAL = 1.5
cout << v << endl;     // 1.5

En el primer caso, aunque escribís v1 / 2 y el 2 es entero, como v1 es float alcanza para que toda la división sea real: da 1.5. En el segundo, 3.0 ya es real por la coma. La conclusión práctica: si querés decimales, asegurate de que al menos un operando sea real (escribilo con .0, como 5.0, o usá una variable float/double).

Trampa: división entera inesperada
Querés calcular el promedio de dos notas, 7 y 8:
✗ float prom = (7 + 8) / 2;  → 15 / 2 son dos enteros, da división entera 7 (¡se perdió el .5!). Aunque prom sea float, el cálculo ya se hizo con enteros antes de guardarlo.
✓ float prom = (7 + 8) / 2.0;  → con 2.0 la división es real y da 7.5.

Moraleja: que la variable destino sea float no te salva; lo que importa es el tipo de los operandos en el momento de operar.

El operador módulo %: el resto de la división entera

El operador % (se lee "módulo" o "resto") devuelve el resto que sobra al hacer una división entera. Trabaja solo con enteros.

Acordate de la división del colegio: 5 dividido 2 da cociente 2 y resto 1 (porque 2 × 2 = 4, y para llegar a 5 sobra 1). Bueno: 5 / 2 te da el cociente (2) y 5 % 2 te da el resto (1).

int resto = 5 % 2;
cout << resto << endl;   // 1   (5 = 2*2 + 1, sobra 1)

cout << 10 % 3 << endl;  // 1   (10 = 3*3 + 1)
cout << 12 % 4 << endl;  // 0   (12 = 4*3 + 0, division exacta, no sobra nada)
cout << 7  % 10 << endl; // 7   (10 no entra en 7, asi que sobra el 7 entero)
Para qué sirve % en la práctica
El módulo es utilísimo. Por ejemplo: un número es par si n % 2 da 0 (no sobra nada al dividir por 2) e impar si da 1. Y como vas a ver al final de la unidad, combinando / y % se pueden extraer los dígitos de un número (las unidades, las decenas, etc.). Es una herramienta que vas a usar muchísimo.

Los operadores de comparación (o relacionales) toman dos números y devuelven un valor lógico de tipo bool: o bien verdadero (true) o bien falso (false). Sirven para hacerle preguntas a los datos: "¿es x mayor que 10?". La cátedra lo resume: NÚMERO op NÚMERO ⟶ BOOLEANO.

Trampa clásica: confundir == (comparar) con = (asignar)
Este es el error más cometido por principiantes. Son dos operadores totalmente distintos:

• = (un solo igual) es la asignación: guarda un valor en una variable. x = 5; significa "metele 5 a x".
• == (doble igual) es la comparación: pregunta si dos cosas son iguales y devuelve true/false. x == 5 significa "¿x vale 5?".

Si en una decisión escribís x = 5 (con un solo igual) en vez de x == 5, no estás preguntando nada: le estás asignando 5 a x, y eso casi siempre rompe la lógica del programa. Regla: cuando quieras preguntar si son iguales, usá SIEMPRE ==.

Los tres operadores lógicos
• !  NOT (negación) — es unario (un operando): invierte el valor. !true es false y !false es true.

• NOT (!): "lo contrario". Da vuelta el valor.

Precedencia: en qué orden se resuelven los operadores

Cuando una expresión mezcla varios operadores, C++ no los resuelve de izquierda a derecha sin más: sigue un orden de prioridad (también llamado precedencia o jerarquía), igual que en matemática "primero multiplico y después sumo". Esta es la tabla de la cátedra, ordenada de mayor a menor prioridad:

3ª*   /   %Multiplicación, división, módulo

5ª<   <=   >   >=   ==   !=Comparaciones (relacionales)

Se lee así: lo que está más arriba se ejecuta primero. Los paréntesis ganan siempre: lo que esté adentro se resuelve antes que nada. El ! (unario) se aplica muy temprano, antes que && y ||. Las cuentas (* / % y luego + -) se hacen antes que las comparaciones, y los lógicos después. La asignación = es la última: primero se calcula todo el lado derecho y recién al final se guarda en la variable de la izquierda.

El ejemplo de la cátedra: * / antes que +
Con x valiendo 2 (del código de clase):

int r = x + 3 * 4;
Como * tiene más prioridad que +, primero se hace 3 * 4 = 12, después 2 + 12 = 14.  → r vale 14.

int a = (x + 3) * 4;
Acá el paréntesis fuerza el orden: primero x + 3 = 2 + 3 = 5, después 5 * 4 = 20.  → a vale 20.

Misma cuenta "a ojo", resultados distintos (14 vs 20): el paréntesis cambia qué se hace primero.
Consejo profesional: ante la duda, paréntesis
No tenés que memorizar la tabla entera a la perfección. Si una expresión te resulta ambigua o tenés que pensarla dos veces, poné paréntesis para dejar clarísimo el orden. (a && b) || c se entiende de una; a && b || c obliga a recordar que && va antes que ||. Los paréntesis no cuestan nada y hacen tu código legible y a prueba de errores.

Contadores: variables que suman (o restan) de a 1

Un contador es una variable cuyo único trabajo es aumentar o disminuir de a 1 cada vez. Sirve para contar cosas: cuántos alumnos aprobaron, cuántas vueltas dio un ciclo, etc. La idea es: tomo el valor actual de la variable, le sumo 1, y vuelvo a guardar el resultado en la misma variable.

La forma "explícita" de hacerlo es x = x + 1;. Hay que entenderla bien porque parece rara la primera vez:

Cómo leer x = x + 1;
No es una ecuación matemática (en matemática "x = x + 1" sería imposible). Es una asignación, y se lee de derecha a izquierda:

1) Primero se calcula el lado derecho x + 1 usando el valor actual de x.
2) Ese resultado se guarda de nuevo en x, pisando el valor viejo.

Si x valía 10, x + 1 da 11, y ese 11 se guarda en x. Ahora x vale 11.

Como contar de a 1 es tan común, C++ ofrece formas equivalentes y más cortas de escribir lo mismo:

Acumuladores (sumadores): sumar de a k

Un acumulador (también llamado sumador) es la generalización del contador: en vez de sumar siempre 1, suma una cantidad cualquiera k que puede cambiar en cada paso. Sirve para acumular totales: la suma de varios precios, el total de puntos, etc.

Regla de oro: SIEMPRE inicializar antes de usar

Acá va una regla que la cátedra recalca y que no podés saltearte: todo contador y todo acumulador DEBE estar inicializado en algún valor ANTES de empezar a usarlo. "Inicializar" significa darle un valor de arranque (típicamente 0 para sumar, o 1 para multiplicar).

¿Por qué? Porque cuando declarás una variable sin asignarle nada, no arranca en 0: arranca con un valor basura (lo que hubiera quedado en esa zona de memoria, un número impredecible). Si le sumás 1 a basura, obtenés "basura + 1", que sigue siendo basura. Tu programa daría resultados distintos y sin sentido cada vez que corre.

Contraejemplo de la cátedra: contador SIN inicializar (MAL)
Esto está marcado en el código de clase como algo que nunca debería pasar:

int v;        // se declara v PERO no se le da valor: v tiene BASURA
v = v + 1;    // basura + 1 = ... basura. Resultado impredecible.
Como v nunca recibió un valor inicial, v + 1 opera sobre un número desconocido. El arreglo correcto es inicializarla primero:

int v = 0;    // ✓ ahora v arranca en un valor conocido
v = v + 1;    // 0 + 1 = 1. Resultado correcto y predecible.
La costumbre que te ahorra horas de bugs
Cada vez que crees un contador o acumulador, dale su valor inicial en la misma línea en que lo declarás: int suma = 0;, int cantidad = 0;. Es una línea que parece de más pero te evita los errores más difíciles de detectar (los que dan resultados "casi bien" o cambian entre corridas).

Pre-incremento (++i) vs post-incremento (i++)

Ya vimos que i++ y ++i, usados solos, hacen lo mismo: suman 1 a i. La diferencia aparece cuando los usás dentro de una expresión más grande, donde además de incrementar, ese i++ o ++i aporta un valor a la cuenta. La pregunta es: ¿aporta el valor de i antes o después de sumarle 1?

La regla, en una frase
• ++i (pre-incremento): incrementa primero y después usa el valor ya aumentado. ("Primero sumo, después te doy el número.")
• i++ (post-incremento): usa el valor actual primero y después incrementa. ("Primero te doy el número que tengo, y recién ahí sumo.")

En ambos casos i termina valiendo uno más; lo que cambia es qué valor aporta a la expresión en el momento.
Traza del ejemplo de la cátedra: int k = (++i + j++);
Partimos de i = 10 y j = 20. Resolvemos la expresión (++i + j++) pieza por pieza:

1) ++i es pre-incremento: primero sube i a 11, y aporta a la cuenta ese valor ya aumentado → aporta 11. (Ahora i vale 11.)
2) j++ es post-incremento: aporta a la cuenta el valor actual de j, que es 20, y después sube j a 21 → aporta 20. (Ahora j vale 21.)
3) La suma es 11 + 20 = 31, que se guarda en k.

Resultado final:  i = 11,  j = 21,  k = 31.

int i = 10;
int j = 20;
int k = (++i + j++);
cout << i << endl;   // 11  (++i lo subio a 11 antes de usarlo)
cout << j << endl;   // 21  (j++ se uso como 20 y despues subio a 21)
cout << k << endl;   // 31  (11 + 20)
Fijate el detalle clave de j: en la cuenta participó como 20 (su valor de antes), pero al imprimirlo después ya vale 21, porque el post-incremento sí lo aumentó, solo que después de aportar su valor.
Recomendación para principiantes
Cuando un incremento es una sentencia suelta (su único objetivo es contar), usá la forma simple i++; y no te preocupes por pre/post: ahí dan exactamente lo mismo. Evitá meter i++ o ++i en medio de expresiones complicadas: confunde y es fuente de errores. La distinción pre/post hay que entenderla (te la pueden tomar), pero en tu propio código conviene escribir cosas claras.

Ejemplo integrador: descomponer una fecha con / y %

Ahora juntamos división entera y módulo en un programa real de la cátedra (clase_02_fechas.cpp). El problema: el usuario ingresa una fecha como un único número entero en formato AAAAMMDD (año-mes-día), por ejemplo 20260407 (que representa el 07/04/2026), y queremos reimprimirla en formato DDMMAAAA, o sea 07042026.

La clave es entender que un número como 20260407 es, en realidad, sus dígitos pegados: 2026 (año), 04 (mes) y 07 (día). Con / y % podemos "recortar" cada parte. Mirá el programa completo:

#include <iostream>
using namespace std;

int main() {

    unsigned int fecha;
    cout << "ingrese una fecha en formato AAAAMMDD: " << endl;
    cin >> fecha;

    unsigned int anio = fecha / 10000;
    unsigned int dia  = fecha % 100;
    unsigned int mes  = (fecha / 100) % 100;

    unsigned int fechaSalida = dia * 1000000 + mes * 10000 + anio;

    cout << "La fecha en formato DDMMAAAA es: " << fechaSalida << endl;

    return 0;
}

(El tipo unsigned int es un entero "sin signo": solo números positivos. Una fecha nunca es negativa, así que encaja perfecto.) Vamos a trazar paso a paso con la entrada fecha = 20260407:

Extraer el año: fecha / 10000

Dividir un entero por 10000 (un 1 seguido de cuatro ceros) equivale a borrar los últimos 4 dígitos (división entera, descarta el resto). Como los últimos 4 dígitos son justo el mes y el día (MMDD), lo que queda es el año:

anio = 20260407 / 10000;
// 20260407 / 10000 = 2026,0407  -> division ENTERA: se descarta el ,0407
// anio = 2026

Extraer el día: fecha % 100

El módulo por 100 da el resto de dividir por 100, que son siempre los últimos 2 dígitos del número. Los dos últimos de AAAAMMDD son DD, o sea el día:

dia = 20260407 % 100;
// 20260407 dividido 100 da cociente 202604 y RESTO 07
// dia = 7

Extraer el mes: (fecha / 100) % 100

El mes está "en el medio", así que necesitamos dos pasos (por eso el paréntesis, que por precedencia se ejecuta primero):

// Paso 1: fecha / 100  -> borra los ultimos 2 digitos (el dia DD)
//   20260407 / 100 = 202604   (quedo AAAAMM: 2026 y 04)
// Paso 2: ... % 100   -> toma los ultimos 2 digitos de ESE resultado
//   202604 % 100 = 4          (el resto es 04 = el mes)
mes = (20260407 / 100) % 100;
// mes = 4
La idea general, para que la puedas reusar
Sobre un número entero:
• Dividir por una potencia de 10 (/ 10, / 100, / 1000…) borra dígitos por la derecha.
• Sacar el módulo por una potencia de 10 (% 10, % 100…) se queda con esa cantidad de dígitos de la derecha.
Combinando ambos podés aislar cualquier "tramo" de dígitos de un número. % 10 te da la última cifra (la unidad); / 10 te quita la última cifra; etc.

Rearmar en formato DDMMAAAA

Ya tenemos dia = 7, mes = 4, anio = 2026. Para pegarlos en el orden DDMMAAAA los "empujamos" a su posición multiplicando por la potencia de 10 correspondiente y sumando:

fechaSalida = dia * 1000000 + mes * 10000 + anio;
// dia * 1000000 = 7 * 1000000 = 7000000   (el dia queda en las posiciones de millones)
// mes * 10000   = 4 * 10000   =   40000   (el mes en el medio)
// anio          =                  2026   (el anio en las ultimas 4 posiciones)
// suma          = 7000000 + 40000 + 2026 = 7042026

El programa imprime: La fecha en formato DDMMAAAA es: 7042026. Leído como DDMMAAAA es 07/04/2026, exactamente la fecha original. (Se muestra 7042026 sin el cero inicial porque, como número, el 0 de la izquierda no se guarda; el valor numérico es correcto.)

¿Por qué no alcanza con / 10000 y listo?
Para el año alcanza una sola división porque está al principio (a la izquierda). Para el día alcanza un solo módulo porque está al final (a la derecha). Pero el mes está en el medio: si solo dividieras (fecha / 100) te quedaría 202604 (año + mes pegados), y si solo sacaras módulo (fecha % 10000) te quedaría 0407 (mes + día pegados). Por eso hay que combinar los dos: primero borrar el día con / 100 y después quedarte con dos dígitos usando % 100.

Repaso de la unidad

Lo que tenés que llevarte
• Una expresión se evalúa hasta dar un único valor; un operador es el símbolo de la operación y los operandos son los valores sobre los que actúa.
• Aritméticos (número→número): + - * / %. División de dos enteros ⟶ entera (descarta decimales: 5/2 da 2); con al menos un real ⟶ conserva decimales (5.0/2 da 2.5). El % da el resto (5%2 da 1).
• Comparación (número→bool): > >= < <= == !=. Ojo: == compara, = asigna.
• Lógicos (bool→bool): ! invierte; && da V solo si ambos son V; || da F solo si ambos son F.
• Precedencia: ( ) → ! → * / % → + - → relacionales → && → || → =. Ante la duda, paréntesis.
• Contador: suma/resta de a 1 (x++, ++x, x += 1, x = x + 1). Acumulador: de a k (x += k, x = x + k).
• Regla de oro: todo contador/acumulador se inicializa antes de usarse; si no, arranca con basura.
• Pre vs post: ++i incrementa y luego usa; i++ usa y luego incrementa. En k = (++i + j++) con i=10, j=20 → i=11, j=21, k=31.
• Fechas: / 10000 saca el año, % 100 saca el día y (/ 100) % 100 saca el mes de un AAAAMMDD.
4 Unidad 4: Estructuras de decisión (if, switch, ternario)

Hasta ahora tus programas iban siempre derecho: una sentencia abajo de la otra, de arriba hacia abajo, ejecutando todas las líneas sí o sí. En esta unidad eso cambia: el programa va a aprender a tomar decisiones. Según una condición que se cumpla o no, va a ejecutar ciertas líneas o saltearlas. Vamos a ver el if, el if/else, las escaleras else if, el operador ternario y el switch, paso a paso y desde cero.

¿Qué es el flujo de control?

El flujo de control es el orden en el que se van ejecutando las sentencias de tu programa. En la Unidad 1 viste la regla de oro: el programa corre secuencialmente, de arriba hacia abajo, una sentencia a la vez. Eso es el flujo secuencial: no se saltea nada, no se repite nada, todas las líneas se ejecutan una vez, en orden.

Pero los programas de verdad necesitan reaccionar. "Si el usuario es mayor de edad, dejalo pasar; si no, mostrale un cartel." "Si la nota es mayor o igual a 4, aprobó; si no, desaprobó." Esa palabrita "si" es la clave: introduce una bifurcación, un punto donde el camino se parte en dos (o más) y el programa elige por cuál seguir.

El flujo de control en la vida real
Pensá en cómo salís de tu casa: "Si está lloviendo, agarro el paraguas; si no, lo dejo." El paso "agarrar el paraguas" solo se ejecuta cuando se cumple la condición "está lloviendo". Tu cabeza evalúa la condición y elige el camino. Una estructura de decisión hace exactamente eso, pero en el programa.

A las estructuras que controlan ese orden se las llama estructuras de control. Las de esta unidad se llaman estructuras de decisión (o selección): permiten ejecutar (o no) un bloque de código según una condición.

La condición: una expresión que vale true o false

Toda decisión se basa en una condición: una expresión booleana, es decir, una expresión que al evaluarse da uno de dos valores posibles: verdadero (true) o falso (false). No hay grises: o se cumple, o no se cumple.

La forma más común de armar una condición es comparar dos valores con un operador relacional:

OperadorSignificadoEjemploResultado
>mayor que3 > 2true
<menor que3 < 2false
>=mayor o igual5 >= 5true
<=menor o igual4 <= 3false
==igual a2 == 2true
!=distinto de2 != 3true
Para comparar igualdad se usan DOS signos igual: ==
Un solo = en C++ significa asignar (guardar un valor en una variable): x = 5 mete un 5 en x. Para preguntar "¿son iguales?" usás dos: x == 5. Confundirlos es uno de los errores más típicos y peligrosos; le dedicamos una caja entera más abajo.

También podés combinar varias condiciones con los operadores lógicos: && (Y / and: se cumplen ambas), || (O / or: se cumple al menos una) y ! (NO / not: invierte el valor). Por ejemplo, edad >= 18 && tieneEntrada es true solo si las dos cosas se cumplen a la vez. Y existe el tipo de dato booleano, que se declara con bool y solo puede valer true o false: bool esValido = true;.

El if simple: ejecutar algo SOLO si se cumple una condición

El if (que en inglés significa "si") es la estructura de decisión más básica. Dice: "si esta condición es verdadera, ejecutá esto; si es falsa, salteálo". La sintaxis más simple, para una sola sentencia, es:

if (CONDICION)
    sentencia;

Se lee así: se evalúa lo que está entre paréntesis. Si da true, se ejecuta sentencia. Si da false, esa sentencia no se ejecuta y el programa sigue con la línea de abajo. Ojo: la condición va entre paréntesis ( ) y no lleva punto y coma después del paréntesis.

Veamos el primer ejemplo de la cátedra:

if (3 > 2) // true
    cout << "Hola mundo" << endl;

El programa evalúa 3 > 2. ¿Tres es mayor que dos? Sí. La condición es verdadera, así que se ejecuta la sentencia: en pantalla aparece Hola mundo. Si la condición hubiera sido falsa, esa línea simplemente no se ejecutaría.

Con bloque: varias sentencias bajo el if

Si querés que más de una sentencia dependa de la condición, las agrupás en un bloque con llaves { } (¿te acordás de los bloques de la Unidad 1?). Todo lo que esté adentro de las llaves se ejecuta junto, solo si la condición es verdadera:

if (CONDICION) {
    sentencia1;
    sentencia2;
    // ... cuantas haga falta
}

El segundo ejemplo de la cátedra usa una condición falsa a propósito:

if (3 > 4) { // false
    cout << "Hola" << endl;
    cout << "Chau" << endl;
}

Acá la condición es 3 > 4. ¿Tres es mayor que cuatro? No. La condición es falsa, así que todo el bloque se saltea: no se muestra ni Hola ni Chau. El programa salta directo a lo que venga después de la llave de cierre }.

La traza del if, paso a paso
Cuando el programa llega a un if:

1. Evalúa la condición entre paréntesis → obtiene true o false.
2. Si es true → ejecuta el cuerpo (la sentencia o el bloque) y después sigue abajo.
3. Si es false → saltea el cuerpo por completo y sigue directo en la línea posterior.

"Hacer de computadora": parate en la condición, decidí verdadero/falso, y recién ahí elegí qué líneas corren.
Consejo de oro: usá SIEMPRE llaves { }
Aunque el cuerpo sea una sola sentencia y las llaves no sean obligatorias, conviene ponerlas siempre. ¿Por qué? Porque sin llaves, el if solo "agarra" la primera sentencia de abajo. Mirá la trampa:

if (edad >= 18)
    cout << "Mayor" << endl;
    cout << "Pasá" << endl;  ← esta línea se ejecuta SIEMPRE, no depende del if.

La indentación engaña: parece que las dos líneas están "adentro", pero solo la primera lo está. Con llaves esto no te pasa nunca. Es un hábito que te ahorra horas de bugs.

if / else: el camino del SÍ y el camino del NO

Muchas veces no solo querés hacer algo cuando la condición se cumple, sino otra cosa distinta cuando NO se cumple. Para eso está el else (en inglés, "si no"). La sintaxis es:

if (CONDICION) {
    // camino A: se ejecuta si la condición es TRUE
} else {
    // camino B: se ejecuta si la condición es FALSE
}

La clave del if/else es que se ejecuta exactamente UNO de los dos caminos, nunca los dos, nunca ninguno. Si la condición es verdadera, corre el bloque del if y se ignora el else. Si es falsa, se ignora el if y corre el bloque del else. Son mutuamente excluyentes.

El ejemplo de la cátedra (auto / avión):

if (3 > 4) {
    cout << "auto" << endl;   // en caso de verdad
} else {
    cout << "avión" << endl;  // en caso de falso
}

La condición 3 > 4 es falsa. Por lo tanto, se saltea el bloque del if (no se muestra auto) y se ejecuta el del else: en pantalla aparece avión. Si la condición hubiera sido verdadera, habría pasado al revés: se mostraría auto y nunca avión.

Traza completa de un if/else
int nota = 7;
if (nota >= 4) {
    cout << "Aprobado" << endl;
} else {
    cout << "Desaprobado" << endl;
}

La condición nota >= 4 es 7 >= 4 → true. Se ejecuta el primer bloque → muestra Aprobado. El else se ignora por completo. Si nota valiera 2, la condición sería false y mostraría Desaprobado.

if anidados y la escalera else if

Un if dentro de otro if (o dentro de un else) se dice que está anidado. Es perfectamente válido y a veces necesario. La cátedra lo muestra así:

if (3 > 4) {
    cout << "auto" << endl;   // en caso de verdad
} else {
    if (2 == 2) {
        // ....
    }
}

Acá, dentro del else hay otro if. Se lee: "si 3 > 4... (es falso, salteo) si no, entro al else, y ahí adentro pregunto si 2 == 2". El anidamiento permite encadenar decisiones, pero si lo abusás, el código se llena de llaves y se vuelve difícil de leer. Para el caso común —varios casos mutuamente excluyentes— existe una forma mucho más prolija: la escalera else if.

La escalera if / else if / else

Cuando tenés varios casos y querés que se ejecute solo uno (el primero que se cumpla), encadenás condiciones así:

if (CONDICION_1) {
    // se ejecuta si CONDICION_1 es true
} else if (CONDICION_2) {
    // se ejecuta si la 1 fue false y la 2 es true
} else if (CONDICION_3) {
    // se ejecuta si las anteriores fueron false y esta es true
} else {
    // se ejecuta si NINGUNA de las anteriores se cumplió
}

El programa evalúa las condiciones de arriba hacia abajo y se detiene en la primera que da true: ejecuta ese bloque y saltea todo el resto de la escalera. El else final (opcional) es el "cajón de sastre": atrapa todos los casos que no encajaron en ninguna condición anterior.

Escalera de notas (rangos)
int nota = 8;

if (nota >= 9) {
    cout << "Sobresaliente" << endl;
} else if (nota >= 7) {
    cout << "Distinguido" << endl;
} else if (nota >= 4) {
    cout << "Aprobado" << endl;
} else {
    cout << "Desaprobado" << endl;
}
Con nota = 8: primero pregunta 8 >= 9 → false, sigue. Después 8 >= 7 → true: muestra Distinguido y corta. Nunca llega a evaluar nota >= 4 ni el else. Por eso el orden importa y alcanza con poner >= 7 (ya sabemos que no es >= 9).
El orden de la escalera importa
Como se toma el primer true, las condiciones se ordenan de la más restrictiva a la más general. Si pusieras nota >= 4 arriba de nota >= 9, ¡un 10 caería en "Aprobado" y nunca llegaría a "Sobresaliente"! Pensá la escalera como un colador con agujeros cada vez más grandes.

El operador ternario ? :: un if/else que devuelve un valor

Hay un caso muy común: un if/else cuyo único trabajo es asignarle a una variable un valor u otro según la condición. Para eso existe un atajo, el operador ternario. Se llama "ternario" porque trabaja con tres partes:

condicion ? valorSiTrue : valorSiFalse

Se lee: "si condicion es verdadera, el resultado es valorSiTrue; si no, es valorSiFalse". El signo de pregunta ? separa la condición del primer valor, y los dos puntos : separan los dos valores. La gran diferencia con un if normal es que el ternario es una expresión que produce un valor, así que podés asignarlo directamente.

Mirá la equivalencia. Este if/else (comentado en el código de la cátedra)...

int x;
if (1 < 2) {
    x = 10;
} else {
    x = 20;
}

...se escribe en una sola línea con el ternario así (esta es la versión que la cátedra deja activa):

int x = (1 < 2) ? 10 : 20;

Los dos hacen exactamente lo mismo. Se evalúa 1 < 2 → es true → entonces x toma el valor 10. Si la condición fuera falsa, x tomaría 20. En general, el patrón de la cátedra es:

// Estas dos formas son equivalentes:
int dato;
if (COND) {
    dato = 1;
} else {
    dato = 2;
}

int dato = (COND) ? 1 : 2;
Cuándo usar el ternario
El ternario es ideal cuando elegís entre dos valores para asignar o mostrar: int mayor = (a > b) ? a : b;. Es corto y claro para casos simples. Pero no abuses: si dentro de cada rama hacés varias cosas (no solo asignar un valor), o si encadenás muchos ternarios, el if/else normal se lee mucho mejor. Regla práctica: ternario para asignar un valor; if/else para ejecutar acciones.

Buenas prácticas al escribir condiciones

No dejes la parte verdadera VACÍA: negá la condición con !
Un error feo de principiante es escribir un if donde el bloque verdadero queda vacío y toda la lógica está en el else. La cátedra lo marca explícitamente como "NO hacer". Así NO:

bool w = true;
if (w) {
    // vacío... no hace nada
} else {
    cout << "hola" << endl;
}

En su lugar, negá la condición con el operador ! (NO lógico, que invierte verdadero/falso) y borrá el else. Así SÍ:

bool w = true;
if (!w) {
    cout << "hola" << endl;
}

!w se lee "no w": vale true cuando w es false. Como acá w es true, !w es false y no se muestra nada — igual que en la versión de arriba, pero mucho más limpio.
No compares un bool contra true
Si esValido ya es un booleano, ya vale true o false: no hace falta volver a compararlo.

✗ if (esValido == true)  → redundante y se presta a confundir == con =.
✓ if (esValido)  → directo, claro, idiomático.

Y para el caso falso: en vez de if (esValido == false), escribí if (!esValido). La condición de un if ya espera un booleano, así que poné directamente el booleano.

El switch: decisión múltiple sobre una variable

Cuando tenés que comparar una misma variable contra varios valores fijos (constantes) y hacer algo distinto en cada caso, el switch es más prolijo que una escalera larga de else if. La sintaxis:

switch (variable) {
case valor1:
    // sentencias para cuando variable == valor1
    break;
case valor2:
    // sentencias para cuando variable == valor2
    break;
default:
    // sentencias para cualquier otro valor (opcional)
}

Funciona así: el switch mira el valor de variable y salta al case cuyo valor coincide. Desde ahí ejecuta las sentencias hacia abajo hasta encontrar un break, momento en el que sale de todo el switch y continúa con lo que venga después de la llave de cierre.

El ejemplo de la cátedra lee un número por teclado y lo clasifica:

int nro;
cin >> nro;

switch (nro) {
case 1:
    cout << "El numero es 1" << endl;
    break;
case 2:
    cout << "El numero es 2" << endl;
    break;
case 3:
    cout << "El numero es 3" << endl;
    break;
default:
    cout << "El numero es mayor a 3" << endl;
}

Si el usuario teclea 2, el switch salta a case 2:, muestra El numero es 2, encuentra el break y sale. Si teclea 1, muestra El numero es 1. Si teclea 3, muestra El numero es 3. Y si teclea cualquier otra cosa (un 5, un 0, un -7) no coincide con ningún case, así que cae en default y muestra El numero es mayor a 3.

El rol de break: cortar el "fallthrough"

El break es fundamental. Sin él, una vez que el switch entra a un case, sigue ejecutando los case de abajo aunque sus valores no coincidan, hasta toparse con un break o llegar al final. A ese "caerse" hacia los casos siguientes se lo llama fallthrough (caída en cascada), y casi siempre es un error.

Olvidar un break = se ejecutan los casos de abajo (fallthrough)
Imaginá que en el ejemplo borrás el break del case 1:

case 1:
    cout << "El numero es 1" << endl;
case 2:  ← sin break arriba, también entra acá
    cout << "El numero es 2" << endl;
    break;

Si el usuario teclea 1, ahora se muestran DOS líneas: El numero es 1 y El numero es 2. ¿Por qué? Porque entró en case 1, no encontró break, y "cayó" hacia case 2 ejecutándolo también, hasta el break de ahí. Por eso: poné break al final de cada case (salvo que el fallthrough sea justo lo que querés, cosa rara al principio).

El default: el caso "por defecto"

default es el caso que se ejecuta cuando ningún case coincide con el valor de la variable. Es el equivalente al else de la escalera. Es opcional (podés no ponerlo, y entonces si nada coincide no se hace nada), pero es buena práctica incluirlo para cubrir lo inesperado. Como suele ir último, su break es opcional (no hay nada debajo hacia donde caer); por eso en el ejemplo de la cátedra el default no lo lleva.

switch vs. escalera if / else if
Usá switch cuando comparás una sola variable contra valores constantes e iguales exactos (nro == 1, nro == 2, ...). Es más claro y muestra de un vistazo todos los casos.

Usá la escalera else if cuando las condiciones son rangos (nota >= 7), combinaciones (edad > 18 && tieneEntrada) o involucran variables distintas. El switch no sabe comparar rangos: solo igualdad contra constantes.

Errores típicos que tenés que evitar

Usar = (asignación) en vez de == (comparación)
Este es el clásico, y el más traicionero porque muchas veces compila igual y no avisa.

✗ if (x = 5)  → esto asigna 5 a x y después usa ese 5 como condición. En C++ cualquier número distinto de cero cuenta como verdadero, así que la condición da siempre true, pase lo que pase. Además, ¡le cambiaste el valor a x sin querer!
✓ if (x == 5)  → esto compara si x vale 5, sin tocar nada.

Para preguntar igualdad, siempre dos signos: ==.
Poner ; justo después del paréntesis del if
✗ if (edad >= 18);  ← ese punto y coma de más es el cuerpo del if (¡un cuerpo vacío!). Lo que escribas en la línea de abajo ya no depende de la condición y se ejecuta siempre. Compila sin chistar, pero hace algo distinto de lo que querías. No pongas ; después de la condición de un if.
Condición que no es booleana
La condición de un if debería dar true o false. Si por error ponés una expresión que da un número (por ejemplo if (cantidad) con cantidad entero), C++ la interpreta como "verdadero si es distinto de cero, falso si es cero". A veces eso es lo que querés, pero al principio escribí la comparación explícita (if (cantidad != 0), if (cantidad > 0)) para que se entienda y no te equivoques.

Repaso de la unidad

Lo que tenés que llevarte
• El flujo de control es el orden de ejecución; las estructuras de decisión permiten ejecutar líneas (o no) según una condición.
• Una condición es una expresión booleana: vale true o false (operadores >, <, >=, <=, ==, !=, combinados con &&, ||, !).
• if (COND) { ... } ejecuta el cuerpo solo si la condición es verdadera. Usá siempre llaves.
• if (COND) { ... } else { ... } ejecuta exactamente uno de los dos caminos.
• La escalera else if toma el primer true; el else final atrapa lo que no encajó.
• El ternario COND ? a : b es un if/else que devuelve un valor: int x = (1 < 2) ? 10 : 20;.
• Buenas prácticas: no dejes el if verdadero vacío (negá con !); no compares un bool con true (usá if (esValido)).
• El switch compara una variable contra valores constantes; cada case necesita su break (si no, hay fallthrough); default es el caso por defecto.
• Cuidado con = vs ==, con el ; de más tras el if y con olvidar el break.
5 Unidad 5: Estructuras de repetición (for, while, do-while) y centinela

En la Unidad 4 tu programa aprendió a decidir: ejecutar ciertas líneas o saltearlas según una condición. En esta unidad aprende a repetir: ejecutar un mismo bloque de código muchas veces, sin que vos tengas que copiarlo y pegarlo. A esas estructuras se las llama ciclos o bucles. Vas a ver las tres que usa la cátedra —for, while y do-while— paso a paso, con trazas, y el patrón centinela para leer datos hasta un valor de corte. Arrancamos de cero, como siempre.

¿Por qué necesitamos repetir? La motivación

Imaginá que tu programa tiene que mostrar la palabra Hola diez veces en pantalla. Con lo que sabés hasta ahora, lo harías así:

cout << "Hola" << endl;
cout << "Hola" << endl;
cout << "Hola" << endl;
// ... y así seis líneas más, hasta diez

Funciona, pero es horrible. ¿Y si fueran cien veces? ¿O un millón? ¿Y si te equivocás en una línea y tenés que corregirla en las cien? Copiar y pegar el mismo código es propenso a errores, imposible de mantener y, sobre todo, no escala: la cantidad de veces muchas veces ni siquiera la conocés de antemano (depende de lo que el usuario tipee).

Un ciclo resuelve esto: es una estructura de control que ejecuta un bloque de código (llamado cuerpo del ciclo) varias veces, mientras se cumpla una condición. Cada ejecución del cuerpo es una iteración (una "vuelta" del ciclo). Vos escribís el bloque una sola vez y el ciclo se encarga de repetirlo.

Los ciclos en la vida real
Hacer flexiones — "Repetí: bajá y subí, hasta llegar a 20." Sabés exactamente cuántas: son 20. Eso es una repetición exacta.

Llenar un balde con un vaso — "Repetí: cargá el vaso y volcalo en el balde, mientras el balde no esté lleno." No sabés cuántos vasos van a ser: depende del tamaño del balde y del vaso. Eso es una repetición indefinida.

Esta diferencia —¿sé cuántas veces, o repito mientras pase algo?— es justo la que separa al for de los otros dos ciclos.

Dos familias de ciclos: repetición DEFINIDA vs INDEFINIDA

Antes de ver la sintaxis, lo más importante es entender cuándo usar cada ciclo. La pregunta clave es una sola: ¿sé de antemano cuántas veces tengo que repetir?

Tipo¿Sé cuántas veces?EstructuraEjemplo típico
Repetición DEFINIDA (o exacta)SÍ — la cantidad es conocida (un número fijo, o calculable)forMostrar "Hola" 10 veces; sumar los números del 1 al 100
Repetición INDEFINIDA (o inexacta)NO — repito mientras se cumpla una condición; la cantidad depende de algo (ej. lo que ingresa el usuario)while / do-whilePedir una contraseña hasta que sea correcta; leer números hasta que ingresen un 0
La regla para elegir el ciclo
• Si conocés la cantidad de repeticiones (o la podés calcular antes de empezar) → usás FOR.
• Si no la conocés y repetís mientras se cumpla una condición → usás WHILE (chequea la condición antes de cada vuelta) o DO-WHILE (la chequea después, así que da al menos una vuelta).

Los tres ciclos podrían escribirse uno en términos de otro, pero cada uno está pensado para un caso: usar el que corresponde hace tu código más claro.

El for: repetición DEFINIDA

El for (en inglés, "para") es el ciclo que usás cuando sabés cuántas veces querés repetir. Su gran ventaja es que junta en una sola línea las tres cosas que todo conteo necesita: desde dónde empiezo, hasta dónde llego y de a cuánto avanzo. La sintaxis es:

for (inicialización; condición; incremento) {
    // cuerpo del ciclo: lo que se repite
}

Adentro de los paréntesis hay tres partes, separadas por punto y coma ;. Esa variable que controla el ciclo y lleva la cuenta de las vueltas se llama índice o variable de control (por costumbre se la nombra i). Veamos qué hace cada parte:

El orden EXACTO de ejecución de un for

Esto es lo que tenés que tener grabado a fuego. Cuando el programa llega a un for, los pasos son siempre en este orden:

Los pasos de un for, en orden
1. Se ejecuta la inicialización (int i = 1). Esto pasa una sola vez.
2. Se evalúa la condición (i <= 10):
    • Si es true → se ejecuta el cuerpo (paso 3).
    • Si es false → el ciclo termina y el programa sigue después de la llave }.
3. Se ejecuta el cuerpo del ciclo (las sentencias entre llaves).
4. Se ejecuta el incremento (i = i + 1).
5. Se vuelve al paso 2 (re-chequear la condición), repitiendo 3 y 4 mientras la condición siga dando true.

Fijate el detalle clave: la inicialización (paso 1) ocurre una sola vez, pero después el ciclo gira entre condición → cuerpo → incremento → condición → cuerpo → incremento... hasta que la condición da false. El cuerpo y el incremento nunca se ejecutan si la condición ya arrancó en false.

El primer ejemplo de la cátedra

Este es el for que muestra la cátedra (con un contador extra para llevar la cuenta de las vueltas, como viste en la Unidad 3):

int contador = 0;
for (int i = 1; i <= 10; i = i + 1) {
    cout << "hola" << endl;
    contador = contador + 1;
}

Leelo en palabras: "para i empezando en 1, mientras i sea menor o igual que 10, y sumándole 1 a i en cada vuelta: mostrá hola y sumá 1 al contador". El índice i va a tomar los valores 1, 2, 3, ..., 10, así que el cuerpo se ejecuta exactamente 10 veces: en pantalla aparece hola diez veces y contador queda valiendo 10.

El índice va del VALOR INICIAL al VALOR FINAL inclusive (con <=)
Cuando usás la condición i <= final, el índice toma todos los valores desde el inicial hasta el final, incluyéndolo. Por eso for (int i = 1; i <= 10; ...) da 10 vueltas (i = 1, 2, ..., 10). El esquema general de la cátedra es:

for (int INDICE = VALOR_INICIAL; INDICE <= VALOR_FINAL; INDICE = INDICE + 1)

El índice siempre se incrementa de a 1 y va desde VALOR_INICIAL hasta VALOR_FINAL inclusive. El ciclo sigue mientras INDICE <= VALOR_FINAL sea true; cuando da false, sale y continúa la ejecución.

Variantes del for: partes vacías y el for infinito

Las tres partes del for son opcionales: podés dejar alguna (o todas) vacías, siempre que mantengas los dos ;. El código de la cátedra muestra dos variantes para que las reconozcas. En la primera, la inicialización y el incremento están fuera del for:

int i = 1;            // inicialización afuera
for (; i <= 10; ) {   // solo la condición; las otras dos partes, vacías
    cout << "hola" << endl;
    i = i + 1;        // incremento adentro del cuerpo
}

Hace exactamente lo mismo que el for completo: 10 vueltas. Simplemente, la creación del índice se hizo antes y el incremento se metió como una línea más del cuerpo. Es válido, aunque lo habitual y más claro es poner las tres partes dentro del paréntesis.

Y si dejás las tres partes vacías, obtenés un for que no termina nunca (la condición ausente se considera siempre verdadera):

for (;;) {            // for INFINITO: no hay condición que lo corte
    cout << "hola" << endl;
}

Este for (;;) muestra hola para siempre. La cátedra lo incluye para ilustrar la sintaxis, pero un ciclo infinito sin una salida controlada es un error (lo vemos en las cajas de trampas).

El while: repetición INDEFINIDA (condición al PRINCIPIO)

El while (en inglés, "mientras") es el ciclo que usás cuando no sabés cuántas veces vas a repetir: repetís mientras se cumpla una condición. La sintaxis es la más simple de todas:

while (CONDICION) {
    // cuerpo: se repite mientras CONDICION sea true
}

Funciona así: se evalúa la condición al principio. Si da true, se ejecuta el cuerpo y se vuelve a evaluar la condición; y así sucesivamente. En cuanto la condición da false, el ciclo termina y el programa sigue después de la llave.

Los pasos de un while, en orden
1. Se evalúa la condición:
    • Si es true → se ejecuta el cuerpo (paso 2).
    • Si es false → el ciclo termina.
2. Se ejecuta el cuerpo.
3. Se vuelve al paso 1 (re-chequear la condición), repitiendo el cuerpo mientras siga dando true.

Como la condición se chequea antes de entrar, el while puede girar 0 veces (si la condición arranca en false, el cuerpo no se ejecuta ni una sola vez) o infinitas veces (si la condición nunca llega a hacerse falsa). Esa es su característica distintiva: puede no ejecutarse nunca.

El ejemplo de la cátedra

La cátedra lee un número con cin y repite mientras ese número sea mayor que 8:

int x;
cin >> x;            // primera lectura: el usuario tipea un número
while (x > 8) {
    cout << "chau" << endl;
    cin >> x;        // vuelve a leer: x puede cambiar en cada vuelta
}

Recordá que cin >> x lee del teclado y guarda lo que el usuario tipea en x (la flecha >> "trae" el dato desde el teclado hacia la variable). Sigamos el flujo según lo que ingrese el usuario:

Traza del while de la cátedra
Supongamos que el usuario va tecleando: 10, después 9, después 3.

• cin >> x → x = 10. Condición 10 > 8 → true → muestra chau → cin >> x → x = 9.
• Condición 9 > 8 → true → muestra chau → cin >> x → x = 3.
• Condición 3 > 8 → false → sale del ciclo.

Mostró chau 2 veces. Ahora mirá un caso límite: si lo primero que teclea es 5, la condición 5 > 8 da false de entrada y el cuerpo no se ejecuta ni una vez (0 vueltas). Eso es lo que solo un while puede hacer.

El do-while: repetición INDEFINIDA (condición al FINAL)

El do-while (en inglés, "hacer... mientras") es casi igual al while, con una diferencia fundamental: la condición se chequea al final, después de ejecutar el cuerpo. La sintaxis es:

do {
    // cuerpo: se ejecuta y RECIÉN DESPUÉS se chequea la condición
} while (CONDICION);

Ojo a dos detalles de escritura: el cuerpo va primero (después de la palabra do), y el while con la condición va al final, terminado en punto y coma ; (este es el único ciclo que lleva ; después del paréntesis de la condición).

Los pasos de un do-while, en orden
1. Se ejecuta el cuerpo (sí o sí, sin preguntar nada todavía).
2. Se evalúa la condición:
    • Si es true → se vuelve al paso 1 (otra vuelta).
    • Si es false → el ciclo termina.

Como el cuerpo se ejecuta antes del primer chequeo, el do-while gira como mínimo 1 vez, pase lo que pase.

El código de la cátedra muestra el do-while paralelo a su while:

int y;
do {
    cout << "chau" << endl;
    cin >> y;
} while (y > 8);

Acá siempre se muestra chau al menos una vez antes de leer y y de chequear nada. Recién después de mostrar y leer, se evalúa y > 8 para decidir si hay otra vuelta. Compará con el while anterior: aquel leía antes y podía no mostrar chau nunca; este muestra chau sí o sí la primera vez.

¿Cuándo el do-while es la elección natural? Cuando necesitás ejecutar el cuerpo al menos una vez para recién después poder evaluar la condición. El ejemplo de manual es un login: tenés que pedir usuario y contraseña al menos una vez antes de poder saber si están bien o mal. La cátedra lo plantea así (en pseudocódigo):

do {
    pedir usuario
    pedir contraseña
} while (las credenciales están mal);

Se piden las credenciales (1ª vuelta, seguro), y solo entonces se evalúa si están mal: si están mal, se vuelven a pedir; si están bien, se sale. Con un while normal tendrías que pedirlas una vez "a mano" antes del ciclo para tener algo que evaluar; el do-while lo resuelve más naturalmente.

El patrón centinela (valor de corte)

Un problema clásico: "se siguen ingresando números hasta que el usuario ingresa un valor especial". Ese valor especial que marca el fin de los datos se llama centinela o valor de corte. No es un dato a procesar: es una señal de "ya terminé de cargar". Ejemplos: terminar cuando ingresan 999, o 0, o un número negativo.

La cátedra lo plantea con el centinela 999: "se siguen ingresando números hasta que termina cuando se ingresa el número 999". Definamos las dos ideas centrales:

CORTE y la idea de "seguir mientras NO sea el centinela"
• CORTE: la condición que indica que hay que parar. Es valor == 999 (el dato ingresado es el centinela).
• !CORTE (no corte): la condición para seguir. Es valor != 999 (el dato no es el centinela).

Como el ciclo repite mientras haya que seguir, la condición del while es justamente !CORTE: "while (valor != 999)", es decir, "seguí mientras lo ingresado no sea 999".

La gran pregunta es dónde poner la lectura (cin >> valor). La cátedra distingue dos esquemas según una sutileza: ¿la condición del ciclo depende del dato que se lee, o no?

Esquema (a): la condición NO depende de la entrada → leés ADENTRO

Si la condición de corte no se fija en el valor recién ingresado (por ejemplo, repetir una cantidad fija de veces, o mientras un contador no llegue a cierto número), podés leer el dato cómodamente dentro del cuerpo:

// SI la CONDICIÓN NO depende de la entrada de datos
while (COND) {
    cin >> x;
    // ... procesar x ...
}

Acá la lectura es una acción más del cuerpo. Como COND no mira a x, no hay riesgo de procesar de más.

Esquema (b): la condición SÍ depende de la entrada → lectura ADELANTADA

Este es el caso del centinela y el que más confunde al principio. Si la condición sí depende del dato ingresado (while (x != 999) mira a x), no podés leer recién dentro del cuerpo, porque la primera vez el while evaluaría x sin que el usuario haya tecleado nada todavía. La solución es la lectura adelantada: leés una vez antes del while (para tener un primer valor que evaluar) y volvés a leer al final del cuerpo (para tener el siguiente):

// SI la CONDICIÓN SÍ depende de la entrada de datos
cin >> x;              // 1) lectura ADELANTADA: primer valor, antes del while
while (x != 999) {    // 2) la condición evalúa el x que YA tenemos
    // ... procesar x (que NO es 999) ...
    cin >> x;          // 3) leé el SIGUIENTE valor, al final del cuerpo
}

El truco es entender los dos cin: el de arriba carga el primer valor para que la condición tenga algo que mirar; el del final del cuerpo prepara el valor para la próxima evaluación de la condición. Así, cuando el usuario ingresa 999, ese valor se lee (en alguno de los dos cin), el while evalúa 999 != 999 → false y sale sin procesar el 999. ¡Eso es justo lo que queremos: el centinela marca el fin, no es un dato!

Traza de la lectura adelantada con centinela 999
El usuario teclea: 5, 8, 999. Seguimos el código del esquema (b):

• cin >> x (adelantada) → x = 5.
• while (5 != 999) → true → procesa el 5 → cin >> x → x = 8.
• while (8 != 999) → true → procesa el 8 → cin >> x → x = 999.
• while (999 != 999) → false → sale. El 999 nunca se procesa.

Se procesaron solo el 5 y el 8 (los datos reales), no el centinela. Si hubieras leído dentro del cuerpo sin la lectura adelantada, habrías procesado el 999 por error antes de chequear.

Dos atajos: break y continue

Dentro de cualquier ciclo podés usar dos sentencias especiales para alterar su flujo. Ya viste break en el switch de la Unidad 4; en los ciclos cumple un rol parecido.

break — corta el ciclo por completo: lo abandona inmediatamente y el programa salta a lo que venga después de la llave de cierre, sin importar la condición. Sirve para salir antes de tiempo cuando ya encontraste lo que buscabas:

for (int i = 1; i <= 10; i = i + 1) {
    if (i == 5) {
        break;           // al llegar i a 5, abandona el for
    }
    cout << i << endl;    // muestra 1, 2, 3, 4 y corta
}

continue — saltea el resto del cuerpo de la vuelta actual y va directo a la siguiente iteración (en el for, pasa al incremento y vuelve a chequear la condición). No corta el ciclo: solo se saltea lo que queda de esa vuelta:

for (int i = 1; i <= 5; i = i + 1) {
    if (i == 3) {
        continue;        // en la vuelta de i = 3, salta el cout y sigue
    }
    cout << i << endl;    // muestra 1, 2, 4, 5 (se saltea el 3)
}
break vs continue en una frase
• break = "me voy del ciclo" (lo termina del todo).
• continue = "salteo esta vuelta" (sigo con la próxima iteración).

Usalos con moderación: muchas veces una condición bien pensada en el while o un if en el cuerpo logran lo mismo y se leen mejor.

Errores típicos que tenés que evitar

Ciclo INFINITO: olvidar el incremento o que la condición nunca se haga falsa
Un ciclo que nunca termina deja tu programa colgado mostrando cosas (o sin responder) para siempre. La causa número uno es olvidar modificar la variable de control, de modo que la condición se quede eternamente verdadera. Mirá:

int i = 1;
while (i <= 10) {
    cout << "hola" << endl;
}  ← ¡falta i = i + 1;! Como i siempre vale 1, 1 <= 10 es siempre true y nunca para.

Lo mismo pasa con for (;;) (sin condición) o si en un while (x != 999) te olvidás de volver a leer x. Regla: asegurate de que en cada vuelta algo acerque la condición a hacerse falsa (incrementar el índice, leer un dato nuevo, etc.).
Error "off-by-one": confundir < con <= (una vuelta de más o de menos)
Cambiar <= por < (o al revés) altera la cantidad de vueltas en uno, y es un error tan común que tiene nombre propio: off-by-one ("por uno de diferencia").

• for (int i = 1; i <= 10; i = i + 1) → da 10 vueltas (i = 1, 2, ..., 10).
• for (int i = 1; i < 10; i = i + 1) → da 9 vueltas (i = 1, 2, ..., 9): ¡el 10 se queda afuera!

Antes de dar por bueno un for, "hacé de computadora" con el primer y el último valor del índice y contá las vueltas. ¿Querés incluir el valor final? Usá <=. ¿Querés frenar justo antes? Usá <.
Procesar el valor centinela por error
En un ciclo con centinela, el valor de corte no es un dato: es la señal de "terminé". Si lo procesás (lo sumás, lo mostrás, lo contás), tu resultado queda mal. El error típico es leer dentro del cuerpo sin lectura adelantada:

do {
    cin >> x;
    suma = suma + x;  ← cuando x es 999, ¡lo suma igual antes de cortar!
} while (x != 999);

Por eso, cuando la condición depende del dato, se usa la lectura adelantada (leer antes del while y al final del cuerpo): así el while ve el 999 y sale antes de procesarlo. Si igual querés usar este esquema, tenés que chequear con un if (x != 999) antes de sumar.

Repaso de la unidad

Lo que tenés que llevarte
• Un ciclo repite un bloque (el cuerpo) varias veces; cada vuelta es una iteración. Sirve para no copiar y pegar código.
• Repetición definida (sé cuántas veces) → for. Repetición indefinida (repito mientras se cumpla una condición) → while / do-while.
• for (init; condición; incremento): la init corre una vez; después gira condición → cuerpo → incremento. Con i <= final el índice llega hasta el final inclusive.
• while (COND) evalúa al principio: puede dar 0 vueltas.
• do { ... } while (COND); evalúa al final: da mínimo 1 vuelta (y lleva ; al final).
• Centinela (valor de corte): se repite mientras NO sea el centinela (while (x != 999)). Si la condición depende del dato, usá lectura adelantada (leer antes del while y al final del cuerpo) para no procesar el centinela.
• break abandona el ciclo; continue saltea el resto de la vuelta.
• Cuidado con el ciclo infinito (olvidar el incremento / leer de nuevo), el off-by-one (< vs <=) y procesar el centinela.
6 Unidad 6: Patrones algorítmicos clásicos (contar, sumar, promediar, máximos/mínimos)

En las unidades anteriores aprendiste las piezas sueltas: variables y operadores (U2–U3), tomar decisiones con if (U4) y repetir con ciclos (U5). Esta unidad no trae piezas nuevas: trae recetas. Vas a ver que cuando combinás un ciclo con una variable que se va actualizando adentro, aparecen una y otra vez los mismos cinco o seis patrones: contar, sumar, promediar, buscar el máximo/mínimo y descomponer un número. Si los reconocés, la mitad de los ejercicios de la cátedra se resuelven casi en automático.

La idea central de toda esta unidad
Casi todos estos patrones tienen la misma forma de tres tiempos:

1) ANTES del ciclo → inicializo una variable "acumuladora" (un contador en 0, una suma en 0, un máximo en algún valor de arranque).
2) ADENTRO del ciclo → por cada dato que leo, actualizo esa variable (sumo 1, sumo el valor, comparo y me quedo con el mayor…).
3) DESPUÉS del ciclo → uso el resultado (lo muestro, lo divido para promediar, etc.).

Si entendés este esqueleto, todo lo demás son variantes.

Para los ejemplos vamos a usar muchísimo el ciclo con centinela (un valor especial que marca el fin de los datos), porque es el que más aparece en la guía. Recordá el molde de U5: leemos un valor, y mientras no sea el centinela, lo procesamos y volvemos a leer.

#include <iostream>
using namespace std;

int main() {
    int valor;

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;            // PRIMERA lectura, antes del while

    while (valor != 0) {        // 0 es el CENTINELA: corta el ciclo
        // ... acá adentro PROCESAMOS el valor ...

        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;        // SIGUIENTE lectura, al final del cuerpo
    }

    return 0;
}
El centinela NO se procesa
Fijate que la primera lectura va antes del while y la siguiente al final del cuerpo. Esto se llama "lectura adelantada". Su gracia es que cuando entra el centinela (el 0), el while evalúa la condición, da falso y no ejecuta el cuerpo: el 0 nunca se cuenta ni se suma. Es el error más típico contar o sumar el valor que justamente indicaba "terminá".

Patrón 1 — Contar (contador condicional)

Contar significa responder a la pregunta "¿cuántos elementos cumplen tal condición?". Por ejemplo: cuántos valores fueron cero, cuántos negativos, cuántos alumnos aprobaron. La herramienta es una variable entera, el contador, que arranca en 0 y le sumamos 1 cada vez que el dato cumple la condición.

La receta de contar
• Antes: int cantidad = 0;  (siempre en cero, porque todavía no contamos nada).
• Adentro: if (condición) { cantidad = cantidad + 1; }
• Después: mostrás cantidad.

El cantidad = cantidad + 1; se puede escribir más corto como cantidad++;. Las dos formas hacen exactamente lo mismo: "tomá el valor que tenías, sumale uno y guardalo de nuevo".

Veámoslo con el ejercicio 1.a de la guía: dado un conjunto de valores enteros, calcular cuántos valores cero hubo. Usamos centinela. Ojo: el enunciado dice "valores enteros", así que el cero es un dato válido del conjunto; para no confundir el "cero que cuento" con el "cero que termina", muchos enunciados usan otro centinela, pero acá seguimos el espíritu de la guía contando los ceros que aparezcan antes de que el usuario decida cortar. Para que se vea limpio, usemos un centinela distinto, por ejemplo terminar cuando ingresan -9999:

#include <iostream>
using namespace std;

int main() {
    int valor;
    int cantidadCeros = 0;          // ANTES: arranca en 0

    cout << "Ingrese un valor (-9999 para terminar): ";
    cin >> valor;

    while (valor != -9999) {
        if (valor == 0) {           // ADENTRO: solo si es cero
            cantidadCeros++;        // ...sumo uno al contador
        }

        cout << "Ingrese un valor (-9999 para terminar): ";
        cin >> valor;
    }

    // DESPUES: ya recorrí todo, muestro el resultado
    cout << "Hubo " << cantidadCeros << " valores cero." << endl;
    return 0;
}
Traza con los datos: 4, 0, 7, 0, 0, -2, -9999
Seguimos "haciendo de computadora". cantidadCeros arranca en 0.

• Leo 4 → ¿es 0? No → contador sigue en 0.
• Leo 0 → ¿es 0? Sí → contador pasa a 1.
• Leo 7 → ¿es 0? No → sigue en 1.
• Leo 0 → ¿es 0? Sí → contador pasa a 2.
• Leo 0 → ¿es 0? Sí → contador pasa a 3.
• Leo -2 → ¿es 0? No → sigue en 3.
• Leo -9999 → es el centinela → corta el while (no se procesa).

Resultado en pantalla: Hubo 3 valores cero. ✓
Contar TODO vs. contar CON condición
Si querés contar cuántos datos hubo en total (sin condición), simplemente ponés el contador++; sin if, directamente adentro del ciclo: se suma uno por cada vuelta. Y si querés contar según varias categorías (como el ejercicio 6: cuántos ganan menos de $520, cuántos entre $520 y $780, etc.), usás varios contadores, cada uno con su if. La idea es siempre la misma, multiplicada.

Patrón 2 — Acumular / Sumar (sumatoria)

Sumar (o "acumular") responde a "¿cuánto suma el conjunto?" o "¿cuál es la suma de los que cumplen tal condición?". La diferencia con contar es sutil pero fundamental:

ContarSumar
Sumo siempre 1 (me importa cuántos son).Sumo el valor del dato (me importa cuánto valen juntos).
cantidad = cantidad + 1;suma = suma + valor;

La variable que va guardando la suma se llama acumulador, y también arranca en 0 (porque la suma de "nada" es cero, el elemento neutro de la suma).

Tomemos el ejercicio 1.c: la sumatoria de los valores negativos. Recorremos el conjunto y, cada vez que el valor es negativo, lo agregamos al acumulador:

#include <iostream>
using namespace std;

int main() {
    int valor;
    int sumaNegativos = 0;          // ANTES: acumulador en 0

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;

    while (valor != 0) {
        if (valor < 0) {            // ADENTRO: solo si es negativo
            sumaNegativos = sumaNegativos + valor;   // acumulo el valor
        }

        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;
    }

    cout << "La suma de los negativos es: " << sumaNegativos << endl;
    return 0;
}
Traza con los datos: 5, -3, 8, -10, -2, 0
sumaNegativos arranca en 0.

• Leo 5 → ¿negativo? No → suma sigue en 0.
• Leo -3 → ¿negativo? Sí → suma = 0 + (−3) = −3.
• Leo 8 → ¿negativo? No → sigue en −3.
• Leo -10 → ¿negativo? Sí → suma = −3 + (−10) = −13.
• Leo -2 → ¿negativo? Sí → suma = −13 + (−2) = −15.
• Leo 0 → centinela → corta.

Resultado: La suma de los negativos es: -15 ✓
No inicializar el acumulador (o inicializarlo mal)
Si declarás int suma; sin el = 0, esa variable arranca con basura (un valor impredecible que quedó en la memoria). Tu suma quedaría contaminada con un número al azar. Siempre inicializá el acumulador en 0. (Para multiplicar/acumular un producto, en cambio, se arranca en 1, porque 1 es el neutro de la multiplicación.)

Patrón 3 — Promediar (y sus dos trampas)

El promedio es "suma dividida por cantidad". Es decir: combina los dos patrones anteriores. Necesitás llevar al mismo tiempo un acumulador (la suma) y un contador (cuántos elementos sumaste), y al final dividir uno por el otro.

Hagamos el ejercicio 1.b: el promedio de los valores positivos. Por cada positivo, lo sumo y además cuento uno:

#include <iostream>
using namespace std;

int main() {
    int valor;
    int sumaPositivos = 0;          // acumulador
    int cantPositivos = 0;          // contador

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;

    while (valor != 0) {
        if (valor > 0) {
            sumaPositivos = sumaPositivos + valor;   // sumo
            cantPositivos = cantPositivos + 1;       // y cuento
        }

        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;
    }

    // DESPUES: ¿hubo positivos? Recién ahí divido.
    if (cantPositivos > 0) {
        float promedio = (float) sumaPositivos / cantPositivos;
        cout << "El promedio de positivos es: " << promedio << endl;
    } else {
        cout << "No hubo valores positivos." << endl;
    }

    return 0;
}

Mirá las dos cosas raras de ese final, porque son las dos trampas clásicas del promedio que la cátedra busca que reconozcas:

Trampa 1: división por cero
Si el conjunto no tuvo ningún positivo, cantPositivos vale 0. Hacer suma / 0 es una división por cero: matemáticamente indefinida, y en C++ con enteros provoca que el programa se rompa (crash). Por eso antes de dividir SIEMPRE preguntás if (cantPositivos > 0). Si la cantidad es 0, mostrás un mensaje ("no hubo positivos") en lugar de dividir. Olvidar este chequeo es uno de los errores que más puntos cuesta.
Trampa 2: división entera
En C++, si dividís dos enteros, el resultado es entero: la parte decimal se tira (no redondea, trunca). Por ejemplo 7 / 2 da 3, no 3.5. Entonces, si la suma es 7 y la cantidad 2, un promedio calculado como int te daría 3, ¡que está mal! La solución es que el cálculo se haga en punto flotante: declarás el resultado como float (o double) y casteás uno de los operandos con (float). Con (float) suma / cant, la suma se convierte a real, y entonces la división es real: 7.0 / 2 = 3.5. ✓
¿Qué es "castear"?
Castear es convertir un dato de un tipo a otro momentáneamente. (float) sumaPositivos le dice a C++: "tratá este entero como si fuera un número real para esta operación". Con que uno de los dos lados de la división sea real, C++ hace toda la división en real. Cuidado con esta trampa sutil: (float)(suma / cant) NO sirve — los paréntesis hacen que primero se divida entero (truncando) y recién después convierta. El casteo tiene que estar antes de la división: (float) suma / cant.

Patrón 4 — Máximos y mínimos

El problema es: tenés un conjunto de valores que se van leyendo de a uno (no los tenés todos juntos a la vista), y querés saber cuál es el mayor (o el menor). Como solo ves un valor por vez, la estrategia es llevar una variable max que guarde "el mayor que vi hasta ahora", e ir comparando cada nuevo dato contra ella.

La lógica de comparar contra "el mejor hasta ahora"
Adentro del ciclo, por cada valor leído:
• Máximo: if (valor > max) { max = valor; }  → "si este es más grande que el récord actual, es el nuevo récord".
• Mínimo: if (valor < min) { min = valor; }  → misma idea, al revés.

Es como ver una carrera: te quedás con "el que va primero por ahora", y solo lo cambiás si alguien lo pasa.

Toda la dificultad real está en una sola pregunta: ¿con qué valor arranca max? Porque la primera comparación necesita que max ya tenga algo adentro. Hay tres técnicas para resolver esto (las tres de las notas de clase). Vamos una por una.

Técnica A — Inicializar con un valor FUERA DEL DOMINIO

Si el enunciado te dice en qué rango están los datos (el "dominio"), podés arrancar max en un valor imposible de alcanzar por debajo, de modo que el primer dato real seguro lo supere y se convierta en el nuevo máximo.

Por ejemplo, si el enunciado dice que los valores son del dominio [0, +∞) (cero o positivos), arrancás el máximo en algo más chico que cualquier dato posible, como -1:

#include <iostream>
using namespace std;

int main() {
    int valor;
    int max = -1;       // mas chico que CUALQUIER dato del dominio [0, +inf)

    cout << "Ingrese un valor positivo (-9999 para terminar): ";
    cin >> valor;

    while (valor != -9999) {
        if (valor > max) {      // el primer dato (>= 0) siempre supera al -1
            max = valor;
        }

        cout << "Ingrese un valor positivo (-9999 para terminar): ";
        cin >> valor;
    }

    cout << "El maximo fue: " << max << endl;
    return 0;
}

Para un mínimo es al revés: arrancás en algo más grande que cualquier dato posible. Si el dominio fuese, digamos, notas de 0 a 10, podrías arrancar min = 11;.

La limitación de la técnica A
Esta técnica solo sirve si el enunciado define el dominio y te permite elegir un valor por fuera. Si los datos pueden ser cualquier entero (positivos y negativos sin límite), no existe un "más chico que todos" y esta técnica falla. Ese es justo el peligro de la próxima caja: arrancar un máximo en 0 "porque sí". Cuando no conocés el dominio, usá la técnica B o C.

Técnica B — Tomar el PRIMER elemento usando un contador de posición

La idea acá es: el primer dato que llega es, por definición, el máximo provisorio (es el único que viste, así que es el mayor hasta ahora). Para detectar "¿estoy en el primer dato?" usamos un contador de posición i que arranca en 1, y aprovechamos el operador OR (||):

#include <iostream>
using namespace std;

int main() {
    int valor;
    int max;            // NO la inicializo: el primer dato la define
    int i = 1;          // contador de posicion

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;

    while (valor != 0) {
        if (i == 1 || valor > max) {    // si es el PRIMERO, o si supera al max
            max = valor;
        }

        i = i + 1;                       // avanzo la posicion
        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;
    }

    cout << "El maximo fue: " << max << endl;
    return 0;
}
Por qué funciona el i == 1 || valor > max
El || (OR) da verdadero si al menos una de las dos condiciones se cumple. En la primera vuelta, i == 1 es verdadero, así que entra al if y hace max = valor sin siquiera mirar valor > max (gracias a esto no usamos max antes de inicializarla). En las vueltas siguientes i ya no es 1, entonces lo único que decide es valor > max: la comparación normal. Esta técnica funciona con cualquier dominio, incluso negativos, porque no inventás ningún valor de arranque.

Técnica C — Tomar el primer elemento usando una BANDERA booleana

Es exactamente la misma idea que la B, pero en lugar de contar posiciones usamos una bandera (una variable bool) que dice "¿es la primera vez?". Arranca en true y la apagamos apenas procesamos el primer dato.

#include <iostream>
using namespace std;

int main() {
    int valor;
    int max;
    bool esLaPrimeraVez = true;     // bandera: arranca encendida

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;

    while (valor != 0) {
        if (esLaPrimeraVez || valor > max) {
            max = valor;
            esLaPrimeraVez = false;     // la apago: ya no es la primera vez
        }

        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;
    }

    cout << "El maximo fue: " << max << endl;
    return 0;
}
Traza de la técnica C con: -5, -2, -9, -1, 0
Estos son todos negativos, justo el caso donde "arrancar en 0" fallaría. Veamos que con la bandera anda perfecto. max = (sin definir), esLaPrimeraVez = true.

• Leo -5 → ¿esLaPrimeraVez? Sí → entra: max = -5, bandera pasa a false.
• Leo -2 → ¿primera vez? No. ¿−2 > −5? Sí → max = -2.
• Leo -9 → ¿−9 > −2? No → max sigue en −2.
• Leo -1 → ¿−1 > −2? Sí → max = -1.
• Leo 0 → centinela → corta.

Resultado: El maximo fue: -1 ✓  (correcto: −1 es el mayor de los negativos).
El bug estrella: inicializar el máximo en 0 cuando hay negativos
Es tentador escribir int max = 0; y comparar directo. Pero si todos los datos son negativos (como −5, −2, −9, −1), ningún valor va a superar al 0, así que el if nunca entra y el programa informa que el máximo es… 0, ¡un valor que ni siquiera estaba en el conjunto! El 0 solo es un arranque seguro si el dominio garantiza que hay valores ≥ 0. Ante la duda, técnica B o C.

Variante — Máximo y cuántas veces se repite

Esta es una vuelta de tuerca muy pedida (el ejercicio 12 modificado de las notas): además del máximo, querés saber cuántas veces aparece ese máximo en el conjunto. La clave está en distinguir tres situaciones al comparar cada valor con el máximo actual:

CasoQué hacés
El valor es mayor que el máximoHay un nuevo récord: max = valor y reinicio el contador de repeticiones en 1 (esta es la primera vez que veo este nuevo máximo).
El valor es igual al máximoApareció otra vez el mismo récord: repeticiones++ (sumo una aparición).
El valor es menorNo hago nada: ni cambia el máximo ni el contador.
#include <iostream>
using namespace std;

int main() {
    int valor;
    int max;
    int repeticiones = 0;
    bool esLaPrimeraVez = true;

    cout << "Ingrese un valor (0 para terminar): ";
    cin >> valor;

    while (valor != 0) {
        if (esLaPrimeraVez || valor > max) {
            max = valor;            // nuevo maximo...
            repeticiones = 1;       // ...lo vi por PRIMERA vez (reinicio en 1)
            esLaPrimeraVez = false;
        } else if (valor == max) {
            repeticiones = repeticiones + 1;    // mismo maximo otra vez
        }

        cout << "Ingrese un valor (0 para terminar): ";
        cin >> valor;
    }

    cout << "El maximo es " << max
         << " y se repite " << repeticiones << " veces." << endl;
    return 0;
}
Traza con: 1 5 7 7 7 15 4 15 15 3 9 7 15 2 (centinela 0)
Vamos siguiendo max y repeticiones. Empieza con la bandera en true.

• 1 → primera vez → max=1, rep=1
• 5 → 5>1 → max=5, rep se reinicia a 1
• 7 → 7>5 → max=7, rep=1
• 7 → 7==7 → rep=2
• 7 → 7==7 → rep=3
• 15 → 15>7 → max=15, rep se reinicia a 1
• 4 → 4<15 → nada (max=15, rep=1)
• 15 → 15==15 → rep=2
• 15 → 15==15 → rep=3
• 3 → menor → nada
• 9 → menor → nada
• 7 → menor → nada
• 15 → 15==15 → rep=4
• 2 → menor → nada
• 0 → centinela → corta

Resultado
El maximo es 15 y se repite 4 veces.
En el conjunto, el 15 aparece en las posiciones del 6º, 8º, 9º y 13º dato → efectivamente 4 apariciones. (Si contás solo "a ojo" rápido podrías decir 3; por eso la traza paso a paso es tan importante: el cuarto 15 aparece tarde, después de varios números chicos.)
El error: reiniciar repeticiones a 0 (en vez de 1) al cambiar de máximo
Cuando encontrás un nuevo máximo, ese valor ya cuenta como una aparición: lo estás viendo en este preciso instante. Por eso se reinicia en 1, no en 0. Si lo ponés en 0, vas a terminar con una repetición de menos.

Variante — Posición relativa del máximo

Otra pregunta muy común (el ejercicio 10: imprimir el valor máximo y su posición relativa dentro del conjunto). "Posición relativa" significa el lugar que ocupa: si fue el 1º dato ingresado, el 5º, etc. La idea es llevar un contador de posición i, y cada vez que actualizás el máximo, guardar también en qué posición estabas.

El ejercicio 10 trabaja con valores positivos terminados con un negativo, así que el centinela es "valor negativo" (corta cuando valor < 0):

#include <iostream>
using namespace std;

int main() {
    int valor;
    int max;
    int posMax;             // posicion donde encontre el maximo
    int i = 1;              // posicion actual
    bool esLaPrimeraVez = true;

    cout << "Ingrese un valor positivo (negativo para terminar): ";
    cin >> valor;

    while (valor >= 0) {            // corta con el primer negativo
        if (esLaPrimeraVez || valor > max) {
            max = valor;
            posMax = i;             // me guardo la posicion del nuevo maximo
            esLaPrimeraVez = false;
        }

        i = i + 1;
        cout << "Ingrese un valor positivo (negativo para terminar): ";
        cin >> valor;
    }

    cout << "El maximo es " << max
         << " y esta en la posicion " << posMax << endl;
    return 0;
}
Traza con: 4 9 2 9 7 -1
• 4 (pos 1) → primera vez → max=4, posMax=1
• 9 (pos 2) → 9>4 → max=9, posMax=2
• 2 (pos 3) → 2<9 → nada
• 9 (pos 4) → 9>9 es falso → nada (se queda con la PRIMERA aparición)
• 7 (pos 5) → 7<9 → nada
• -1 → centinela → corta

Resultado: El maximo es 9 y esta en la posicion 2. ✓

Detalle fino: como usamos > estricto (no >=), si el máximo se repite nos quedamos con la posición de la primera vez que apareció. Si el enunciado pidiera la última, usarías >=.

Patrón 5 — Descomposición numérica (cambio de billetes)

Este patrón aparece en el ejercicio 14: dado un monto, calcular cuántos billetes de $100, $50, $20, $10, $5, $2 y $1 se necesitan, usando la mínima cantidad de billetes. La estrategia se llama "algoritmo voraz" (greedy): siempre usás la mayor cantidad posible del billete más grande, y con lo que sobra repetís bajando de denominación.

Las dos herramientas son operadores que ya viste en U3, pero acá lucen su verdadera utilidad:

División entera / y módulo %
• monto / 100 → cuántos billetes de 100 entran (la división entera tira los decimales: 5388/100 = 53).
• monto % 100 → cuánto sobra después de sacar esos billetes de 100 (el resto: 5388%100 = 88).

La receta por cada denominación es siempre la misma pareja:
billetes = resto / denominacion;   (cuántos uso)
resto = resto % denominacion;   (qué me queda para la próxima) 
#include <iostream>
using namespace std;

int main() {
    int monto;
    cout << "Ingrese el monto: ";
    cin >> monto;

    int b100 = monto / 100;     monto = monto % 100;
    int b50  = monto / 50;      monto = monto % 50;
    int b20  = monto / 20;      monto = monto % 20;
    int b10  = monto / 10;      monto = monto % 10;
    int b5   = monto / 5;       monto = monto % 5;
    int b2   = monto / 2;       monto = monto % 2;
    int b1   = monto;           // lo que queda son billetes de 1

    cout << "Billetes de 100: " << b100 << endl;
    cout << "Billetes de  50: " << b50  << endl;
    cout << "Billetes de  20: " << b20  << endl;
    cout << "Billetes de  10: " << b10  << endl;
    cout << "Billetes de   5: " << b5   << endl;
    cout << "Billetes de   2: " << b2   << endl;
    cout << "Billetes de   1: " << b1   << endl;
    return 0;
}
Traza completa con $5388
Arrancamos con monto = 5388 y vamos "gastando" el monto denominación por denominación:

• $100: 5388 / 100 = 53 billetes. Resto: 5388 % 100 = 88.
• $50: 88 / 50 = 1 billete. Resto: 88 % 50 = 38.
• $20: 38 / 20 = 1 billete. Resto: 38 % 20 = 18.
• $10: 18 / 10 = 1 billete. Resto: 18 % 10 = 8.
• $5: 8 / 5 = 1 billete. Resto: 8 % 5 = 3.
• $2: 3 / 2 = 1 billete. Resto: 3 % 2 = 1.
• $1: queda 1 billete.

Verificación
53·100 + 1·50 + 1·20 + 1·10 + 1·5 + 1·2 + 1·1 = 5300 + 50 + 20 + 10 + 5 + 2 + 1 = 5388 ✓
Total de billetes: 53 + 1 + 1 + 1 + 1 + 1 + 1 = 59 billetes, la mínima cantidad posible.
Detalle clave: por qué reutilizamos monto
Fijate que después de cada paso hacemos monto = monto % denominacion;. Así monto deja de ser el total original y pasa a ser "lo que falta por cambiar". El paso siguiente trabaja sobre ese resto, no sobre el monto entero. Si te olvidás de actualizar el resto y siempre dividís el monto original, te dan cantidades disparatadas. (El ejercicio 14 completo pide hacer esto para un conjunto de sueldos terminado en cero — o sea: este bloque de billetes va adentro de un ciclo con centinela, acumulando los billetes de todos los sueldos.)

Patrón extra — Validación de entrada con do-while

Muchos enunciados exigen que un dato esté dentro de cierto rango (por ejemplo "ingresar N menor que 25", como en varios ejercicios de la guía). Si el usuario mete algo inválido, no querés seguir: querés volver a pedírselo hasta que esté bien. El ciclo ideal para esto es el do-while, porque pide el dato al menos una vez y repite mientras siga siendo inválido.

#include <iostream>
using namespace std;

int main() {
    int n;
    do {
        cout << "Ingrese N (entre 1 y 24): ";
        cin >> n;
    } while (n < 1 || n > 24);     // repite MIENTRAS el dato sea invalido

    cout << "Perfecto, N = " << n << endl;
    return 0;
}
Cómo leer la condición del do-while
La condición describe cuándo seguir pidiendo (cuándo el dato es malo), no cuándo está bien. n < 1 || n > 24 es verdadero si N se pasó por abajo o por arriba: en cualquiera de esos casos, vuelve a pedir. En cuanto el usuario mete un valor del 1 al 24, la condición da falso y el ciclo termina dejando un dato garantizado válido para el resto del programa.

Repaso de la unidad

Lo que tenés que llevarte
• Todos los patrones siguen el esqueleto inicializar (antes) → actualizar (adentro del ciclo) → usar (después).
• Contar: contador en 0; if (cond) contador++; (sumo 1).
• Sumar: acumulador en 0; suma = suma + valor; (sumo el valor).
• Promediar: suma / cantidad. Cuidado con dividir por cero (chequeá if (cant > 0)) y con la división entera (usá (float) antes de dividir).
• Máximo/mínimo: el problema real es la inicialización. Tres técnicas: (A) valor fuera del dominio, (B) primer elemento con contador i == 1 || ..., (C) primer elemento con bandera bool. Nunca arranques un máximo en 0 si puede haber negativos.
• Máximo + repeticiones: al subir el máximo, reiniciás repeticiones en 1; si es igual, sumás 1.
• Posición del máximo: guardás posMax = i cuando actualizás el máximo.
• Descomposición / billetes: por cada denominación, billetes = resto / denom; y resto = resto % denom;.
• Validar entrada: do { pedir } while (dato invalido);.
• El centinela nunca se procesa: por eso la lectura adelantada (una antes del ciclo, otra al final del cuerpo).
7 Unidad 7: Modularización — procedimientos, funciones, parámetros y recursividad

Hasta ahora escribiste todos tus programas amontonados dentro de main: una sentencia abajo de la otra, todo junto. Eso funciona para programas chiquitos, pero apenas crecen se vuelven un bollo imposible de leer y de mantener. En esta unidad vas a aprender a partir un programa en piezas —llamadas módulos— para que cada una haga una cosa bien. Vas a ver los dos tipos de módulos de C++: los procedimientos (que hacen algo pero no devuelven nada) y las funciones (que devuelven un valor). Después: cómo pasarles datos (parámetros), la diferencia clave entre pasarlos por valor y por referencia, qué es la firma de una función y la sobrecarga, el alcance (scope) de las variables, y por último el tema más alucinante: la recursividad, funciones que se llaman a sí mismas. Todo desde cero y con el código tal cual lo da la cátedra.

¿Qué es modularizar y por qué conviene?

Modularizar es dividir un programa grande en piezas más chicas, cada una con un nombre y una tarea concreta. A esas piezas las llamamos módulos, y en C++ se construyen con funciones y procedimientos. En vez de tener doscientas líneas seguidas en main, tenés un main cortito que llama a piezas con nombres que se entienden: leerDatos(), calcularPromedio(), mostrarResultado().

Modularizar en la vida real
Pensá en un restaurante. No hay una persona que compre, cocine, sirva, cobre y limpie todo a la vez en un solo bloque caótico. Hay roles: el que cocina, el mozo, el cajero. Cada uno hace su tarea, y vos —cliente— pedís "una pizza" sin saber cómo se amasa por dentro. El restaurante es el programa; cada rol es un módulo. Si mañana cambian la receta de la masa, solo se toca al cocinero: el mozo y el cajero ni se enteran.
Las cuatro razones para modularizar
• Legibilidad: un main que llama a saludar(), procesar(), despedir() se lee como un índice. Entendés qué hace el programa de un vistazo, sin perderte en el cómo.
• Reusabilidad: escribís el módulo una sola vez y lo llamás muchas. ¿Necesitás dibujar una línea separadora diez veces? Escribís raya() una vez y la llamás diez veces, en vez de copiar y pegar el mismo cout diez veces.
• Abstracción: para usar un módulo te alcanza con saber qué hace y qué recibe/devuelve, sin conocer su tripa interna. Usás cout sin saber cómo le habla a la pantalla; igual usás tus propias funciones.
• Mantenimiento: si hay un error en el cálculo del promedio, lo arreglás en un solo lugar (la función) y queda arreglado en todos lados donde se la llama. Sin módulos, tendrías que cazar el mismo bug copiado en mil lados.

A esta forma de encarar problemas se la llama "divide y vencerás" (divide and conquer): un problema grande y difícil se vuelve manejable cuando lo partís en subproblemas chicos, resolvés cada uno por separado (cada uno en su módulo) y después los combinás. Es la idea más importante de toda la programación, y la vas a usar para siempre.

Procedimientos: módulos que hacen pero no devuelven nada (void)

Un procedimiento es un módulo que ejecuta una serie de acciones pero no entrega ningún valor de vuelta. En C++ se lo declara con la palabra clave void (que en inglés significa "vacío", "nada"): justamente, no devuelve nada. La sintaxis más simple es:

void nombre() {
    // las acciones que hace el procedimiento
}

Se lee de izquierda a derecha: void dice "no devuelve nada"; nombre es el nombre que vos le ponés (con el que después lo vas a llamar); los paréntesis () son donde irían los parámetros (por ahora vacíos, lo vemos más adelante); y entre llaves { } va el cuerpo, las sentencias que se ejecutan cuando lo llamás. El ejemplo más simple de la cátedra es una línea separadora:

void raya() {
    cout << "------------" << endl;
}

Cómo se invoca (se llama) un procedimiento

Definir el procedimiento no lo ejecuta: solo lo deja "guardado", listo para usar. Para que efectivamente corra, hay que invocarlo (llamarlo) escribiendo su nombre seguido de los paréntesis y un punto y coma:

raya();   // ahora SÍ se ejecuta: muestra ------------

Cuando el programa llega a raya();, hace una especie de "salto": va al cuerpo de raya, ejecuta sus líneas (el cout), y al terminar vuelve exactamente a la línea de abajo de donde lo llamaste, y sigue. Ese ida y vuelta es lo que hace tan cómodos a los módulos.

Un procedimiento puede llamar a otro

Adentro de un procedimiento podés llamar a otros procedimientos. La cátedra arma saludar() y despedir(), y saludar() reutiliza a raya():

void saludar() {
    cout << "Hola" << endl;
    cout << "Como va?" << endl;
    raya();
}

void despedir() {
    cout << "hasta luego" << endl;
    cout << "nos vemos la proxima" << endl;
    raya();
}

Fijate la reusabilidad en acción: tanto saludar como despedir terminan con una línea separadora, y ninguna de las dos repite el cout << "------------": ambas llaman a raya(). Si mañana querés que la raya sea más larga, la cambiás en un solo lugar (dentro de raya) y se actualiza en todos lados.

Llamándolos desde main (varias veces = reuso)

En main los invocás como cualquier otra sentencia. Y los podés llamar las veces que quieras:

int main() {

    saludar();
    saludar();

    despedir();

    return 0;
}
Traza: qué muestra ese main
El programa arranca en main y va de arriba hacia abajo.

1. saludar(); → salta a saludar: muestra Hola, Como va?, y llama a raya() que muestra ------------. Vuelve a main.
2. saludar(); otra vez → repite lo mismo: Hola, Como va?, ------------.
3. despedir(); → muestra hasta luego, nos vemos la proxima, y raya() muestra ------------.

Una sola definición de saludar, dos llamadas, dos veces el saludo: eso es reuso.

Funciones: módulos que devuelven un valor (return)

Una función es un módulo que, además de poder hacer cosas, calcula y devuelve un valor al que la llamó. La diferencia con un procedimiento es justamente esa: el procedimiento no devuelve nada (void); la función devuelve un dato de un tipo concreto. La sintaxis es:

tipo nombre() {
    // ... cálculos
    return valor;   // entrega un valor del tipo declarado
}

Ahora, donde antes ponías void, va el tipo del dato que devuelve: int si devuelve un entero, bool si devuelve verdadero/falso, float si devuelve un decimal, string si devuelve texto, etc. Y aparece la palabra clave return, que cumple dos roles a la vez:

Qué hace exactamente return valor;
• Entrega el valor a quien llamó a la función: ese valor "sale" de la función y ocupa el lugar de la llamada.
• Termina la función en el acto: cualquier línea que esté debajo del return ejecutado no se corre. El return es la puerta de salida.
• El tipo del valor tiene que coincidir con el tipo declarado: si la función es int, devolvés un entero; si es bool, un true/false.

Estos son los ejemplos de la cátedra, uno por cada tipo. Una función que devuelve un int:

int obtenerNumero() {
    int n = 30;
    return n;     // devuelve 30
}

Una que devuelve un bool (un booleano, verdadero/falso) y otra que devuelve un float (un decimal):

bool pepe() {
    return true;
}

float func2() {
    return 1.5;
}

Lo más importante: hay que USAR el valor devuelto

Acá está la diferencia práctica más grande con los procedimientos. A un procedimiento lo llamás "suelto" (raya();) porque no devuelve nada. Pero una función devuelve un valor, y ese valor tenés que hacer algo con él: guardarlo en una variable, mostrarlo, o usarlo en una cuenta. Si no, el valor se calcula y se tira a la basura.

La forma más común es guardarlo en una variable:

int w = obtenerNumero();   // obtenerNumero() devuelve 30, así que w queda en 30
cout << w << endl;          // muestra: 30

Pensálo así: cuando el programa ejecuta obtenerNumero(), esa llamada se reemplaza por el valor que devuelve. O sea, la línea termina siendo, en los hechos, int w = 30;. Por eso también podés usar la llamada dentro de una expresión más grande, como si fuera un número más:

int z = 1 + obtenerNumero();   // 1 + 30
cout << z << endl;              // muestra: 31

Acá obtenerNumero() devuelve 30, la expresión queda 1 + 30, da 31, y eso es lo que se guarda en z. Una función con un nombre claro se lee casi como castellano:

int calcularLaCantidadDeAlumnos() {
    //................
    return 50;
}

int cant = calcularLaCantidadDeAlumnos();   // cant queda en 50
Trampa: olvidar el return en una función no void
Si declarás una función que devuelve un tipo (por ejemplo int) pero te olvidás de poner el return, la función no entrega ningún valor: el resultado es basura impredecible (un número cualquiera que había en memoria) y el compilador, en el mejor de los casos, te avisa con un warning. La regla: toda función no void tiene que terminar devolviendo un valor de su tipo por todos los caminos posibles. Si tu módulo no necesita devolver nada, entonces no es una función: hacelo void.
Trampa: llamar a una función y no usar lo que devuelve
Escribir obtenerNumero(); sola, en una línea, no es un error de compilación, pero casi siempre es un error lógico: la función calcula su valor 30 y, como nadie lo recibe, se descarta. Es como ir al cajero, sacar la plata y dejarla ahí. Si te interesa el valor, guardalo o usalo: int w = obtenerNumero();.

Parámetros: pasarle datos al módulo para que trabaje

Los módulos de recién siempre hacían exactamente lo mismo: raya() siempre dibuja la misma línea, obtenerNumero() siempre devuelve 30. Para que un módulo sea de verdad útil, necesita poder trabajar con datos distintos cada vez. Esos datos de entrada se llaman parámetros, y se declaran entre los paréntesis, indicando el tipo y un nombre para cada uno.

Un procedimiento que recibe un string (un texto) y saluda a esa persona:

void saludarA(string nombre) {
    cout << "Hola " << nombre << endl;
}

Dentro del cuerpo, nombre se usa como una variable normal: vale lo que le hayan pasado al llamar. Y al llamar, ponés el valor concreto entre los paréntesis:

saludarA("Adrian");   // muestra: Hola Adrian
saludarA("Carla");    // muestra: Hola Carla

El mismo procedimiento, con distintos datos, produce distintos resultados. También podés pasarle el valor a través de una variable, no solo un literal escrito a mano:

string n = "Pedro";
saludarA(n);          // muestra: Hola Pedro

Parámetro vs. argumento (la palabra fina)

Dos nombres para no confundir
• Parámetro: es el nombre que aparece en la definición de la función, el "hueco" que espera un valor. En void saludarA(string nombre), el parámetro es nombre.
• Argumento: es el valor concreto que le pasás al llamarla. En saludarA("Adrian"), el argumento es "Adrian".

Dicho fácil: el parámetro es el casillero, el argumento es lo que metés en el casillero. (En la práctica mucha gente los usa como sinónimos; no te van a retar por eso, pero está bueno saber la diferencia.)

Funciones con parámetros: lo mejor de los dos mundos

Lo más potente es combinar las dos cosas: un módulo que recibe datos (parámetros) y devuelve un resultado (función). El ejemplo canónico de la cátedra es una suma:

int suma(int a, int b) {
    return a + b;
}

Recibe dos enteros (a y b, separados por coma) y devuelve su suma. Mirá las distintas formas de llamarla y usar lo que devuelve:

int total = suma(2, 8);     // argumentos literales: total queda en 10
cout << total << endl;       // muestra: 10

int d = 5;
int f = 6;
int total2 = suma(d, f);    // argumentos por variables: total2 queda en 11
cout << total2 << endl;      // muestra: 11

Otro ejemplo de la cátedra, que recibe un número y devuelve el siguiente:

int dameElSiguienteNumero(int nro) {
    return nro + 1;
}

int x = dameElSiguienteNumero(8);   // x queda en 9
cout << x << endl;                   // muestra: 9
El orden de los argumentos importa
Los argumentos se asignan a los parámetros por posición: el primer argumento va al primer parámetro, el segundo al segundo, y así. En suma(d, f) con d=5 y f=6, adentro de la función a vale 5 y b vale 6. Para la suma da igual el orden, pero para una resta resta(10, 3) y resta(3, 10) dan resultados opuestos. Prestá atención a en qué orden pasás las cosas.

Paso por valor vs. paso por referencia (sección clave)

Esta es una de las ideas más importantes —y más confundidas— de toda la unidad. La pregunta es: cuando le paso una variable a un módulo y el módulo la modifica… ¿se modifica también la variable original de afuera, o no? La respuesta depende de cómo pasaste el parámetro: por valor o por referencia.

Por VALOR (lo que pasa por defecto): se trabaja sobre una COPIA

Por defecto, cuando pasás un argumento, la función recibe una copia de ese valor. Es como si fotocopiaras el dato y le dieras la fotocopia a la función. La función puede rayar, romper o cambiar su fotocopia todo lo que quiera: el original de afuera queda intacto. Mirá:

void duplicarMal(int n) {      // n es una COPIA del argumento
    n = n * 2;                  // cambio la copia... nada más
}

int main() {
    int x = 5;
    duplicarMal(x);             // le paso una copia de x (un 5)
    cout << x << endl;           // muestra: 5  (¡NO cambió!)
    return 0;
}
¿Por qué x sigue valiendo 5?
1. int x = 5; → en memoria, la variable x de main vale 5.
2. duplicarMal(x); → se crea una copia de ese 5 y se la mete en el parámetro n. Ahora hay dos casilleros distintos: x (en main, vale 5) y n (en la función, vale 5), independientes.
3. n = n * 2; → se modifica solo n: ahora n vale 10. Pero x ni se enteró, sigue en 5.
4. La función termina y n desaparece. Volvemos a main.
5. cout << x → muestra 5. El original nunca se tocó.

Por REFERENCIA (con &): se trabaja sobre la variable ORIGINAL

Si querés que la función modifique la variable de verdad (no una copia), agregás un ampersand & pegado al tipo del parámetro. Eso lo convierte en un parámetro por referencia: la función ya no recibe una fotocopia, sino que trabaja directamente sobre el mismo casillero de memoria de afuera. Es como darle a la función no la fotocopia, sino el original mismo. Cualquier cambio que haga, persiste al volver:

void duplicar(int& n) {        // OJO el &: n es la variable ORIGINAL, no una copia
    n = n * 2;                  // modifico el original
}

int main() {
    int x = 5;
    duplicar(x);                // le paso x "de verdad"
    cout << x << endl;           // muestra: 10  (¡SÍ cambió!)
    return 0;
}
¿Por qué ahora x sí cambia a 10?
1. int x = 5; → x vale 5.
2. duplicar(x); → como el parámetro es int& n (por referencia), no se copia nada: n pasa a ser otro nombre para el mismísimo casillero de x. Donde dice n, leé "x".
3. n = n * 2; → como n es x, esto pone 10 en el casillero de x.
4. La función termina. Volvemos a main.
5. cout << x → muestra 10. El cambio quedó.
El detalle que decide todo: el &
La única diferencia entre void duplicar(int& n) y void duplicarMal(int n) es ese &. Con & → por referencia → modifica el original. Sin & → por valor → trabaja sobre una copia y el original no cambia. Un solo carácter cambia por completo el comportamiento del programa. El & va pegado al tipo (podés verlo pegado al tipo int& n o pegado al nombre int &n; son lo mismo).

¿Para qué sirve el paso por referencia?

Tiene dos usos centrales que vas a aprovechar muchísimo:

Cuándo usar referencia
• Parámetros de salida: devolver MÁS de un resultado. Una función con return devuelve un solo valor. Pero a veces necesitás devolver dos o tres (por ejemplo, el máximo y el mínimo de una lista). Pasás esas variables por referencia y la función las "carga" desde adentro: void calcular(int datos, int& maximo, int& minimo). Salen modificadas con los resultados.
• Modificar el dato que recibís. Cuando el objetivo del módulo es cambiar la variable que le das (duplicarla, ordenarla, incrementarla), la referencia es la herramienta.
Trampa: modificar un parámetro por VALOR esperando que cambie afuera
El error clásico es escribir algo como void incrementar(int n) { n = n + 1; }, llamarlo con incrementar(x) y esperar que x aumente. No aumenta: n es una copia, el incremento se pierde cuando la función termina. Si querés que el cambio persista afuera, el parámetro tiene que ser por referencia: void incrementar(int& n). Es uno de los bugs más comunes y silenciosos del principiante: el programa compila, corre, y "misteriosamente" la variable no cambia.

La firma de una función y la sobrecarga (overloading)

La firma de una función es lo que la identifica de forma única para el compilador. Y está compuesta por exactamente dos cosas:

¿Qué forma la FIRMA?
Firma = NOMBRE de la función + TIPOS de sus parámetros (en orden).

Y muy importante: el tipo de retorno NO forma parte de la firma. Tampoco forman parte los nombres de los parámetros (da igual si el parámetro se llama nombre o apellido): lo que cuenta son los tipos y su orden.

Por ejemplo, la firma de void mostrarPersona(string nombre) es mostrarPersona(string). La firma de int suma(int a, int b) es suma(int, int).

Sobrecarga: varias funciones con el MISMO nombre

La sobrecarga (en inglés overloading) es poder tener varias funciones con el mismo nombre, siempre y cuando tengan firmas distintas (es decir, difieran en la cantidad o el tipo de sus parámetros). El compilador decide cuál llamar según los argumentos que le pases. Es comodísimo: usás un solo nombre intuitivo para "la misma idea" aplicada a distintos datos. El ejemplo de la cátedra con mostrarPersona:

// FIRMA: mostrarPersona(string)
void mostrarPersona(string nombre) {
    cout << "Nombre: " << nombre << endl;
}

// FIRMA: mostrarPersona(string, string)
void mostrarPersona(string nombre, string apellido) {
    cout << "Nombre: " << nombre << " - Apellido: " << apellido << endl;
}

// FIRMA: mostrarPersona(string, int)
void mostrarPersona(string nombre, int dni) {
    cout << "Nombre: " << nombre << " - DNI: " << dni << endl;
}

// FIRMA: mostrarPersona(string, string, int)
void mostrarPersona(string nombre, string apellido, int edad) {
    cout << "Nombre: " << nombre << " - Apellido: " << apellido << " - Edad: " << edad << endl;
}

Las cuatro se llaman mostrarPersona, pero cada una tiene una firma distinta, así que conviven sin problema. Al llamarlas, el compilador mira los argumentos y elige la correcta:

mostrarPersona("Adrian");                    // usa mostrarPersona(string)
mostrarPersona("Adrian", "Fiore");           // usa mostrarPersona(string, string)
mostrarPersona("Adrian", 10);                // usa mostrarPersona(string, int)  → el 10 es DNI
mostrarPersona("Pedro", "Gonzalez", 25);     // usa mostrarPersona(string, string, int)

Cuándo NO se puede sobrecargar

No podés tener dos funciones con la misma firma, aunque te parezca que son distintas. Dos casos sutiles que la cátedra marca explícitamente como "NO SE PUEDE":

// Ya existe: void mostrarPersona(string nombre, string apellido)  → firma (string, string)

// NO SE PUEDE: tiene la MISMA firma (string, string).
// Cambiar el NOMBRE de los parámetros no cambia la firma.
// void mostrarPersona(string apellido, string nombre) {
//     cout << "Nombre: " << nombre << " - Apellido: " << apellido << endl;
// }
// Ya existe: void mostrarPersona(string, string, int)

// NO SE PUEDE: misma firma (string, string, int).
// El TIPO DEL RETURN no forma parte de la firma: cambiar void por int NO alcanza.
// int mostrarPersona(string nombre, string apellido, int edad) {
//     cout << "..." << endl;
//     return 1;
// }
Trampa: creer que cambiar el nombre del parámetro o el tipo de retorno crea una firma nueva
Son los dos errores típicos con sobrecarga:
✗ Renombrar el parámetro (de nombre a apellido) no cambia la firma: los tipos son los mismos.
✗ Cambiar solo el tipo de retorno (de void a int) no cambia la firma: el retorno no cuenta.
En ambos casos el compilador ve la misma firma repetida y tira error de "redefinición / función duplicada". Para sobrecargar de verdad tenés que cambiar la cantidad o los tipos de los parámetros.
Ojo: una llamada que compila igual puede ser un error LÓGICO
Como mostrarPersona(string, string) existe, la llamada mostrarPersona("Fiore", "Adrian") compila perfecto… pero muestra "Nombre: Fiore - Apellido: Adrian", que está al revés. La cátedra lo marca como error lógico: el programa funciona, pero hace lo que no querías porque te equivocaste en el orden de los argumentos. En cambio, una llamada como mostrarPersona("Pedro", 25, "Gonzalez") directamente no compila: no existe ninguna firma mostrarPersona(string, int, string).

Alcance (scope) de las variables: ¿dónde vive cada variable?

El alcance (en inglés scope) de una variable es la zona del programa donde esa variable existe y se la puede usar. La regla de oro es simple:

La regla del bloque { }
Una variable existe solo dentro del bloque { } donde fue declarada, desde la línea en que se declara hasta la llave de cierre } de ese bloque. Apenas el programa sale de ese bloque, la variable desaparece (deja de existir y no se la puede usar más). A una variable así se la llama variable local de ese bloque.

Esto explica algo que ya venías viendo sin darte cuenta: la variable n dentro de obtenerNumero no existe en main; los parámetros de una función solo viven dentro de esa función. Cada bloque es como una habitación: lo que declarás adentro, se queda adentro.

Variables locales de distintas funciones son INDEPENDIENTES

Como cada función es su propio bloque, podés tener una variable res en una función y otra res en otra: son dos variables totalmente distintas que casualmente comparten nombre. No se pisan, no se mezclan, no saben una de la otra. El nombre se "reusa" sin conflicto porque viven en cuartos separados.

Ocultamiento (shadowing): un bloque interno tapa a uno externo

Hay un caso fino: si declarás una variable en un bloque interno con el mismo nombre que una de afuera, la de adentro "tapa" (oculta) a la de afuera mientras dure el bloque interno. Adentro, el nombre se refiere a la variable interna; al salir del bloque, vuelve a "verse" la de afuera (que nunca se tocó). Es exactamente lo que pasa en el ejemplo de scope de la cátedra. Mirálo entero:

int main() {

    int x = 3;
    cout << x << endl;

    int z = 10;
    cout << "z vale: " << z << endl; //10

    if (1 == 1) {
        int y = 28;
        cout << y << endl;
        x = 7;
        cout << "z vale: " << z << endl; //10
        int z = 20;
        cout << "z vale: " << z << endl; //20
    }

    cout << x << endl;
    cout << "z vale: " << z << endl; //10

    return 0;
}

Hay dos cosas distintas pasando acá: el ocultamiento de z y la modificación de x. Vamos paso a paso.

Traza completa: qué muestra el programa
Seguimos el bloque externo (el de main) y el interno (el del if):

1. int x = 3; → x (externa) vale 3.
2. cout << x → muestra 3.
3. int z = 10; → z (externa) vale 10.
4. cout << "z vale: " << z → muestra z vale: 10.
5. Entra al if (porque 1 == 1 es true). Abre bloque interno.
6. int y = 28; → y existe solo dentro del if. Muestra 28.
7. x = 7; → ojo: NO hay un x interno, así que esto modifica la x externa (la misma de siempre). Ahora x vale 7.
8. cout << "z vale: " << z → todavía no se declaró el z interno, así que este z es el externo → muestra z vale: 10.
9. int z = 20; → acá nace un nuevo z interno que vale 20. A partir de esta línea y hasta el cierre del if, este z interno TAPA al externo (ocultamiento).
10. cout << "z vale: " << z → ahora z es el interno → muestra z vale: 20.
11. Cierra el bloque interno }: mueren y y el z interno. El z externo sigue valiendo 10 (nunca se tocó: el de 20 era otro).
12. cout << x → muestra 7 (la x externa quedó modificada desde el paso 7).
13. cout << "z vale: " << z → de nuevo se ve el z externo → muestra z vale: 10.

Salida en pantalla: 3 · z vale: 10 · 28 · z vale: 10 · z vale: 20 · 7 · z vale: 10 (cada uno en su renglón).
Las dos lecciones del ejemplo
• z (ocultamiento): afuera vale 10; adentro del if se declara otro z = 20 que oculta al de afuera; al salir del if, ese z interno muere y vuelve a verse el 10. Eran dos variables distintas que compartían nombre.
• x (modificación real): como dentro del if no se declaró ningún x, la línea x = 7; no crea uno nuevo: modifica el único x que existe (el externo). Por eso afuera, después del if, x ya vale 7. La diferencia con z es que z fue redeclarada adentro (con int) y x no.

Variables globales: por qué se evitan

Una variable declarada fuera de toda función (a nivel del archivo) se llama global: la pueden ver y modificar todas las funciones del programa. Suena cómodo, pero es una mala práctica en general, porque cualquier parte del programa puede cambiarla y se vuelve imposible saber quién la modificó y cuándo: aparecen bugs muy difíciles de rastrear, y rompe la abstracción (las funciones dejan de ser cajas independientes). La regla práctica de la materia: pasá los datos como parámetros y devolvé resultados con return (o por referencia); reservá las globales para constantes que de verdad sean de todo el programa.

Recursividad: una función que se llama a sí misma

La recursividad es una técnica donde una función se llama a sí misma para resolver un problema, descomponiéndolo en una versión más chica del mismo problema. Suena a magia (¿una función que se llama a sí misma no se cuelga para siempre?), pero la clave es que cada llamada trabaja sobre un caso más pequeño, hasta llegar a uno tan simple que se resuelve sin volver a llamarse. Por eso, toda función recursiva necesita dos partes:

Los dos ingredientes obligatorios de la recursión
• Caso base (condición de corte): el caso más simple, que se resuelve directamente, SIN volver a llamarse. Es el freno que detiene la cadena. Si falta, la recursión nunca termina.
• Caso recursivo: la función se llama a sí misma con un problema más chico, acercándose al caso base.

El ejemplo clásico: el factorial

El factorial de un número n (se escribe n!) es el producto de todos los enteros desde 1 hasta n. Por ejemplo, 3! = 3 · 2 · 1 = 6. La definición matemática ya es recursiva: n! = n · (n−1)!, y 0! = 1 (ese es el caso base). Así lo escribe la cátedra en C++:

int factorial(int nro) {
    int res;
    if (nro != 0) {
        res = nro * factorial(nro - 1);   // CASO RECURSIVO: se llama con nro-1 (más chico)
    } else {
        res = 1;                          // CASO BASE: 0! = 1, sin volver a llamarse
    }
    return res;
}

Leelo así: "si nro no es 0, el resultado es nro multiplicado por el factorial de nro − 1 (un problema más chico); si nro es 0, el resultado es 1 (y acá freno)". Cada llamada reduce nro en 1, así que tarde o temprano llega a 0 y se corta.

Traza de factorial(3): cómo se apilan las llamadas
Cada llamada queda en pausa esperando el resultado de la llamada que hizo. Primero se "baja" hasta el caso base, y después se "sube" calculando:

Bajada (cada una llama a la siguiente y queda esperando):
• factorial(3): 3 != 0 → res = 3 * factorial(2)  ⟶ pausa, espera factorial(2)
• factorial(2): 2 != 0 → res = 2 * factorial(1)  ⟶ pausa, espera factorial(1)
• factorial(1): 1 != 0 → res = 1 * factorial(0)  ⟶ pausa, espera factorial(0)
• factorial(0): 0 != 0 es false → entra al else → res = 1 → devuelve 1  ✋ (caso base, acá frena)

Subida (cada una recibe el resultado y completa su cuenta):
• factorial(1) recibe 1 → res = 1 * 1 = 1 → devuelve 1
• factorial(2) recibe 1 → res = 2 * 1 = 2 → devuelve 2
• factorial(3) recibe 2 → res = 3 * 2 = 6 → devuelve 6

Resultado final: factorial(3) = 3 · 2 · 1 = 6. Y por el mismo mecanismo: factorial(0)=1, factorial(1)=1, factorial(2)=2, factorial(4)=24.
La "pila" de llamadas
Cada vez que una función se llama (a sí misma o a otra), la llamada en curso se apila: queda guardada con todas sus variables locales, en pausa, hasta que la nueva llamada devuelva. Por eso factorial(3) espera a factorial(2), que espera a factorial(1)… Cuando el caso base devuelve, la pila se va desapilando de a una, y cada nivel completa su cuenta. Esa estructura "lo último que entra es lo primero que sale" se llama pila (stack), y la vas a estudiar en detalle más adelante.
Trampa MORTAL: recursión sin caso base (recursión infinita)
Si te olvidás del caso base —o la condición de corte nunca se cumple— la función se llama a sí misma para siempre. Por ejemplo, si en el factorial te olvidás el else y siempre hacés res = nro * factorial(nro - 1), con un número negativo (o sin freno) nro nunca llega a 0 y las llamadas se apilan sin fin. Como cada llamada ocupa memoria en la pila, esta se llena y revienta: el programa explota con un error llamado desbordamiento de pila (stack overflow). Toda recursión DEBE tener un caso base alcanzable.

Lo mismo, sin recursión: la versión iterativa

Casi todo lo que se puede hacer con recursión se puede hacer también con un ciclo (iteración). El propio archivo de la cátedra trae, comentada, la versión del factorial con un for:

int factorial(int nro) {
    int res = 1;
    for (int i = 1; i <= nro; i++) {
        res = res * i;          // 1*1, *2, *3, ... hasta nro
    }
    return res;
}

Esta versión multiplica res por 1, 2, …, hasta nro, sin que la función se llame a sí misma. Da el mismo resultado que la recursiva. ¿Cuál usar? La iterativa suele ser más eficiente (no apila llamadas, no arriesga desbordar la pila); la recursiva a veces es más elegante y se parece más a la definición matemática del problema. Las dos son válidas: con el tiempo vas a desarrollar el ojo para elegir.

Repaso de la unidad

Lo que tenés que llevarte
• Modularizar = partir el programa en módulos chicos (funciones/procedimientos). Gana en legibilidad, reuso, abstracción y mantenimiento ("divide y vencerás").
• Un procedimiento (void nombre() { ... }) hace algo pero no devuelve nada; se llama con nombre();.
• Una función (tipo nombre() { ... return valor; }) devuelve un valor con return (que además corta la función). Hay que usar el valor: int w = obtenerNumero();.
• Los parámetros son los datos de entrada (en la definición); los argumentos son los valores concretos al llamar. Se asignan por posición.
• Por valor (default): la función recibe una copia; el original no cambia. Por referencia (con &): trabaja sobre el original; los cambios persisten. Sirve para parámetros de salida (devolver más de un dato) o modificar lo recibido.
• La firma = nombre + tipos de los parámetros; el tipo de retorno y los nombres de parámetros no cuentan. La sobrecarga permite mismo nombre con firmas distintas; no se puede repetir firma.
• El alcance (scope): una variable vive solo dentro de su bloque { }. El ocultamiento hace que una variable interna tape a otra externa del mismo nombre (mientras dura el bloque). Las globales se evitan.
• La recursividad = función que se llama a sí misma. Necesita caso base (corte, sin recursión) y caso recursivo (problema más chico). factorial(3) = 3·2·1 = 6. Sin caso base → desbordamiento de pila. Alternativa: versión iterativa con for.
Estructuras de datos Unidades 8–10
8 Unidad 8: Arreglos (vectores)

Hasta ahora cada dato que guardabas vivía en su propia variable: edad, nota, sueldo. Eso alcanza cuando son pocos. Pero, ¿qué hacés cuando tenés que guardar 100 notas a la vez para después recorrerlas? En esta unidad aparece la primera estructura de datos de verdad de la materia: el arreglo (también llamado array o vector). Vamos desde cero: qué problema resuelve, cómo se declara, cómo se accede a cada posición, cómo se recorre con un for, qué pasa por dentro en la memoria, y cómo se pasa a una función. No hace falta más que lo de las unidades anteriores (variables, for, los patrones de la U6).

El problema: 100 variables es inviable

Imaginá que el enunciado te pide leer las notas de 100 alumnos y después hacer algo con ellas (mostrarlas todas, buscar la más alta, promediarlas…). Con lo que sabés hasta ahora tendrías que declarar:

int nota1;
int nota2;
int nota3;
// ... y así hasta ...
int nota100;

Esto es inviable por varios motivos: son 100 líneas para declarar, ¿cómo las leés con un ciclo si cada una tiene un nombre distinto?, ¿cómo recorrés nota1, nota2, … automáticamente? No se puede escribir notaX donde X sea una variable. El nombre de cada variable es fijo y hay que escribirlo a mano.

La idea del arreglo
Un arreglo (array / vector) guarda un conjunto de elementos del MISMO tipo bajo un solo nombre, y a cada elemento lo identificás por su número de posición (un índice). En vez de 100 nombres distintos, tenés un nombre (notas) y pedís el elemento que quieras con un número: notas[0], notas[1], … notas[99]. Y como ese número puede ser una variable, ahora sí podés recorrer todo con un ciclo.

Las tres palabras —arreglo, array y vector— son sinónimos en esta materia: nombran la misma cosa. Vas a escucharlas indistintamente, así que acostumbrate a las tres.

Cómo se declara un arreglo

La forma general de declarar un arreglo es:

tipo nombre[CANTIDAD_MAX];

Donde:

ParteQué significa
tipoEl tipo de dato de cada elemento (todos iguales): int, float, char, etc.
nombreEl nombre del arreglo (uno solo para todo el conjunto).
[CANTIDAD_MAX]Entre corchetes, cuántos elementos como máximo va a poder guardar. Es el tamaño FIJO del arreglo.

Un ejemplo concreto, el de la cátedra:

int arr[5];

Esa línea dice: "creá un arreglo llamado arr que puede guardar hasta 5 números enteros". Reservás de una el espacio para 5 enteros, todos juntos, bajo el nombre arr.

El tamaño es FIJO y se decide al declarar
CANTIDAD_MAX es la cantidad máxima de elementos que el arreglo puede guardar, y queda fijada al momento de declararlo. No podés cargar más que eso: en int arr[5] entran 5 enteros y ni uno más. (En esta etapa de la materia el tamaño es un número fijo conocido al escribir el programa; más adelante verás formas de manejar tamaños variables.)

Posiciones, índices y subíndices: ¡arrancan en CERO!

Para acceder a un elemento puntual del arreglo usás el nombre seguido de la posición entre corchetes:

nombre[posicion];

Esa posición se llama índice o subíndice. Y acá viene lo más importante de toda la unidad, lo que más confunde al principio:

Los índices van de 0 a CANTIDAD_MAX − 1
El primer elemento NO es la posición 1: es la posición 0. Las posiciones válidas van desde 0 hasta CANTIDAD_MAX − 1.

En int arr[5] las posiciones válidas son: 0, 1, 2, 3, 4. Son 5 posiciones (que es lo correcto: el arreglo tiene 5 lugares), pero numeradas del 0 al 4. No existe la posición 5.

Una vez que tenés el arreglo declarado, cada arr[i] se comporta como una variable normal de tipo int: le podés asignar un valor con = y podés leer su valor (por ejemplo, mostrarlo). Veamos las dos cosas, tal como aparecen en el código de la cátedra:

int arr[5];        // 5 lugares: posiciones 0, 1, 2, 3, 4

arr[0] = 21;       // guardo 21 en la posicion 0
arr[1] = 48;       // guardo 48 en la posicion 1
arr[3] = 7;        // guardo 7 en la posicion 3
arr[2] = 28;       // guardo 28 en la posicion 2
arr[4] = 70;       // guardo 70 en la posicion 4

cout << arr[0] << endl;   // LEO la posicion 0 -> muestra: 21
cout << arr[1] << endl;   // LEO la posicion 1 -> muestra: 48
El orden en que cargás no importa
Fijate que en el código de arriba se carga primero la posición 0, después la 1, después la 3, después la 2 y al final la 4. Da igual: cada arr[i] = ... es independiente, escribe en su casillero sin importar el orden en que aparezcan las líneas. Después de esas 5 asignaciones el arreglo quedó así, sin importar el orden de carga:
Índice (posición)01234
Valor guardado214828770

Te conviene imaginarte el arreglo como una fila de casilleros numerados (como los lockers de un gimnasio): todos del mismo tamaño (porque guardan el mismo tipo), pegados uno al lado del otro, y cada uno con su número de casillero (el índice) empezando en 0.

Inicialización por lista (cargar en la misma declaración)

Cuando ya conocés los valores desde el arranque, en vez de asignar posición por posición podés cargarlos todos juntos en la misma línea de la declaración, usando llaves y separando con comas:

int arr2[3] = {4, 9, 56};

Eso es equivalente a haber escrito tres asignaciones:

int arr2[3];
arr2[0] = 4;
arr2[1] = 9;
arr2[2] = 56;

Los valores se reparten en orden: el primero de la lista va a la posición 0, el segundo a la 1, el tercero a la 2. Así, arr2[0] es 4, arr2[1] es 9 y arr2[2] es 56.

Recorrer un arreglo con un for

Acá está la verdadera potencia del arreglo: como la posición es un número, podés usar la variable del for como índice y así pasar por todos los elementos con un ciclo de pocas líneas. El patrón es recorrer de 0 hasta CANTIDAD − 1:

for(int i = 0; i <= 4; i++) {
    cout << arr[i] << endl;
}

En cada vuelta, i toma un valor distinto (0, 1, 2, 3, 4) y arr[i] es el elemento de esa posición. Vamos a "hacer de computadora" y trazar el recorrido con el arreglo que cargamos antes (21, 48, 28, 7, 70):

Traza del recorrido: arr = {21, 48, 28, 7, 70}
• i = 0 → ¿0 <= 4? Sí → muestra arr[0] = 21, baja renglón.
• i = 1 → ¿1 <= 4? Sí → muestra arr[1] = 48.
• i = 2 → ¿2 <= 4? Sí → muestra arr[2] = 28.
• i = 3 → ¿3 <= 4? Sí → muestra arr[3] = 7.
• i = 4 → ¿4 <= 4? Sí → muestra arr[4] = 70.
• i = 5 → ¿5 <= 4? No → corta el ciclo.

Salida en pantalla (uno por renglón):
21

28
7
70 ✓
Dos formas equivalentes de escribir la condición
Como las posiciones de int arr[5] llegan hasta 4, podés cortar el for de dos maneras que hacen exactamente lo mismo:
• for(int i = 0; i <= 4; i++)  → "hasta el índice máximo, 4, inclusive".
• for(int i = 0; i < 5; i++)  → "mientras sea menor que el tamaño, 5".

La segunda (i < 5, o sea i < CANTIDAD) es la que más vas a ver, porque escribís directamente el tamaño del arreglo y no tenés que acordarte de restarle 1. Las dos recorren las posiciones 0, 1, 2, 3, 4.

Qué pasa por dentro: memoria contigua y acceso directo

¿Por qué un arreglo es tan cómodo y rápido? La razón está en cómo se guarda en la memoria. Cuando declarás int arr[5], la máquina reserva un bloque CONTIGUO de memoria: 5 casilleros para enteros, pegados uno tras otro, sin huecos en el medio.

El nombre del arreglo guarda la dirección del comienzo
En la variable arr (el nombre del arreglo) no está "el arreglo entero": está la dirección de memoria donde EMPIEZA el bloque (la posición de arranque). A partir de ahí, los elementos siguen ordenados de a uno.

Entonces, ¿cómo hace la computadora para ir a la posición i sin recorrer todo desde el principio? Con una cuentita. Como sabe dónde empieza el bloque y sabe cuánto ocupa cada elemento (cuántos bits ocupa el tipo de dato), calcula directamente:

direccion de arr[i] = direccionDeComienzo + i × (tamano del tipo)

Por ejemplo, con int arr[5] (donde cada int ocupa, digamos, 32 bits), para ubicar arr[i] hace direccionDeComienzo + i × 32. Es una multiplicación y una suma: una sola cuenta, y listo.

Acceso directo en tiempo CONSTANTE
Como ubicar cualquier posición se reduce a esa única cuenta, acceder a cualquier elemento cuesta lo mismo: da igual pedir arr[0] que arr[4] que arr[9999] (en un arreglo grande). No hay que "caminar" desde el principio. Esto se llama acceso directo y se dice que es en tiempo constante. En la notación de complejidad que viste, esto se anota como O(1) (o, como aparece en las notas, O(n) = k: el costo no depende de la posición, es siempre el mismo k).

Tamaño físico vs. elementos útiles (la variable N)

Hay una distinción que la cátedra remarca mucho y que conviene tener clarísima. El arreglo tiene un tamaño FÍSICO fijo (lo que reservaste al declararlo, por ejemplo 100 lugares). Pero en la práctica casi nunca usás todos los lugares: reservás "de más, por las dudas" y cargás solo los que necesitás.

Pensalo así: declarás int notas[100] porque "podrían venir hasta 100 alumnos", pero hoy se anotaron solo 30. Tenés 100 casilleros reservados, pero solo 30 están cargados con datos válidos. Los otros 70 contienen basura: valores impredecibles que quedaron en la memoria y que no significan nada.

Llevá una variable N con los elementos REALMENTE cargados
Como el tamaño físico no te dice cuántos datos válidos hay, se acostumbra llevar una variable entera —que la cátedra llama N (o también cantElemUtiles, size, length, len)— que guarda cuántas posiciones están realmente en uso. Y entonces:

• El recorrido válido va de 0 hasta N − 1 (NO hasta el tamaño físico − 1).
• Las posiciones de N en adelante contienen basura y no se tocan.
ConceptoQué esEjemplo
Tamaño físicoCuánto reservaste al declarar (fijo).int notas[100] → 100

Confundir tamaño físico con elementos útiles
Si recorrés siempre hasta el tamaño físico (las 100 posiciones) cuando en realidad cargaste solo 30, vas a procesar 70 posiciones llenas de basura: tu promedio, tu máximo y tus cuentas van a salir mal, con números que nunca ingresaste. Siempre recorré hasta N − 1, no hasta el tamaño físico, salvo que el arreglo esté lleno y N coincida con el tamaño.

Operación 1 — Cargar el arreglo (con cin en un for)

"Cargar" es llenar el arreglo con datos que el usuario ingresa. Como cada posición es un arr[i], alcanza con un for que en cada vuelta lea un valor con cin y lo guarde en la posición i. Acá usamos un N ya conocido (por ejemplo 5):

#include <iostream>
using namespace std;

int main() {
    int notas[5];
    int n = 5;                  // cuantos voy a cargar

    for(int i = 0; i < n; i++) {
        cout << "Ingrese la nota " << i << ": ";
        cin >> notas[i];         // guardo lo ingresado en la posicion i
    }

    return 0;
}

En la primera vuelta (i = 0) lo que el usuario escriba se guarda en notas[0]; en la segunda (i = 1) en notas[1]; y así hasta notas[4]. El mismo cin >> notas[i] sirve para todas las posiciones, porque i va cambiando.

Operación 2 — Búsqueda secuencial

Buscar en un arreglo es responder "¿está tal valor? ¿en qué posición?". La búsqueda secuencial (o lineal) es la más simple: recorrés el arreglo desde el principio comparando cada elemento con el valor buscado, hasta encontrarlo (o llegar al final sin éxito). Usamos una bandera y guardamos la posición:

#include <iostream>
using namespace std;

int main() {
    int arr[5] = {21, 48, 28, 7, 70};
    int n = 5;
    int buscado = 28;

    int posEncontrada = -1;         // -1 = "todavia no lo encontre"

    for(int i = 0; i < n; i++) {
        if(arr[i] == buscado) {
            posEncontrada = i;      // me guardo DONDE estaba
        }
    }

    if(posEncontrada != -1) {
        cout << "Encontrado en la posicion " << posEncontrada << endl;
    } else {
        cout << "No esta en el arreglo." << endl;
    }

    return 0;
}
Traza buscando el 28 en {21, 48, 28, 7, 70}
posEncontrada arranca en −1.

• i = 0 → ¿arr[0] (21) == 28? No.
• i = 1 → ¿arr[1] (48) == 28? No.
• i = 2 → ¿arr[2] (28) == 28? Sí → posEncontrada = 2.
• i = 3 → ¿arr[3] (7) == 28? No.
• i = 4 → ¿arr[4] (70) == 28? No.

Como posEncontrada quedó en 2 (distinto de −1): Encontrado en la posicion 2 ✓
¿Por qué arrancar la posición en −1?
El −1 es un valor "imposible" como posición (los índices válidos arrancan en 0), así que sirve de marca de "no encontrado". Si después del ciclo posEncontrada sigue valiendo −1, es porque nunca entró al if: el valor no estaba. Es la misma idea de bandera/centinela que usabas en los patrones de la U6, aplicada a posiciones.

Operación 3 — Copiar un arreglo en otro

Un arreglo no se copia con un simple = (eso no funciona con arreglos como con las variables comunes). Para copiar el contenido hay que recorrer y copiar posición por posición, justo como en el código de la cátedra:

int arr[5] = {21, 48, 28, 7, 70};

int copia[5];
for(int i = 0; i <= 4; i++) {
    copia[i] = arr[i];      // copio el elemento i de arr al elemento i de copia
}

En cada vuelta tomás arr[i] (el valor original de esa posición) y lo guardás en copia[i] (la misma posición del nuevo arreglo). Al terminar el ciclo, copia tiene exactamente los mismos valores que arr, pero es un arreglo independiente: cambiar uno no afecta al otro (cada uno tiene su propio bloque de memoria).

Operación 4 — Buscar el máximo (o el mínimo) del arreglo

Acá reusás un patrón que ya conocés: el de máximo/mínimo de la Unidad 6. La diferencia es que antes los valores llegaban de a uno por cin con un centinela; ahora ya están todos guardados en el arreglo, así que en vez de leer con cin simplemente recorrés con el for y comparás arr[i].

Y hay una ventaja muy linda: como el arreglo te deja acceder a cualquier posición, podés arrancar el máximo con el primer elemento (arr[0]) y comparar desde la posición 1 en adelante. Así te evitás todo el lío de "¿con qué valor inicializo el máximo?" que tenías en la U6:

#include <iostream>
using namespace std;

int main() {
    int arr[5] = {21, 48, 28, 7, 70};
    int n = 5;

    int max = arr[0];               // arranco con el PRIMER elemento
    for(int i = 1; i < n; i++) {    // comparo desde la posicion 1
        if(arr[i] > max) {
            max = arr[i];           // nuevo record
        }
    }

    cout << "El maximo es: " << max << endl;
    return 0;
}
Traza del máximo en {21, 48, 28, 7, 70}
max arranca en arr[0] = 21. El for empieza en i = 1.

• i = 1 → ¿arr[1] (48) > 21? Sí → max = 48.
• i = 2 → ¿arr[2] (28) > 48? No.
• i = 3 → ¿arr[3] (7) > 48? No.
• i = 4 → ¿arr[4] (70) > 48? Sí → max = 70.

Resultado: El maximo es: 70 ✓  Para el mínimo es idéntico, pero arrancás min = arr[0] y comparás con <: if(arr[i] < min) min = arr[i];.

Pasaje de arreglos a funciones

Como vas a querer reusar estas operaciones (cargar, buscar el máximo, etc.), lo natural es meterlas en funciones. Para que una función reciba un arreglo, se declara el parámetro con corchetes vacíos: tipo nombre[]. El ejemplo de la cátedra:

void cargarArray(int a[]) {
    a[0] = 7;
    a[1] = 30;
}

Pero acá hay algo muy importante que la cátedra remarca, y que es distinto a todo lo que viste con las variables comunes:

Los arreglos se pasan SIEMPRE por referencia
Con una variable común (un int, por ejemplo), la función recibe una copia: si la modifica adentro, afuera no cambia nada. Con los arreglos es al revés: NO se copia el arreglo entero. Lo que se pasa es, en realidad, la dirección de memoria donde empieza (ese "comienzo" del que hablamos antes). Por eso la función trabaja sobre el mismo arreglo que está afuera: si la función modifica una posición, el cambio PERSISTE cuando la función termina.

Veámoslo con el programa completo de la cátedra. El main declara un arreglo, lo manda a cargarArray y después lo recorre para ver qué quedó:

#include <iostream>
using namespace std;

void cargarArray(int a[]) {
    a[0] = 7;
    a[1] = 30;
}

int main() {
    int arrayPrueba[2];             // sin cargar: contiene basura
    cargarArray(arrayPrueba);       // le paso el arreglo a la funcion

    for(int i = 0; i <= 1; i++) {
        cout << arrayPrueba[i] << endl;
    }

    return 0;
}
¿Qué imprime? — y por qué cambió afuera
Antes de llamar a la función, arrayPrueba tiene basura en sus 2 posiciones. Al llamar cargarArray(arrayPrueba), la función recibe la dirección de arrayPrueba (su comienzo), así que dentro de la función a es el mismo arreglo que arrayPrueba afuera. La función hace a[0] = 7 y a[1] = 30, que escriben directamente en los casilleros reales. Cuando la función termina, esos cambios quedan. El for entonces muestra:

7
30 ✓

Si los arreglos se pasaran por copia (como un int común), afuera arrayPrueba habría seguido con basura. Pero no: con arreglos, lo que toca la función queda tocado afuera.
Por eso se pasa también N como parámetro aparte
Cuando le pasás un arreglo a una función, la función recibe la dirección de inicio… pero no sabe cuántos elementos útiles tiene (esa información no viaja con el arreglo). Por eso lo habitual es pasar también el N como un segundo parámetro, así la función sabe hasta dónde recorrer. Por ejemplo:

void cargar(int a[], int n) { for(int i = 0; i < n; i++) cin >> a[i]; }

Y como el arreglo es por referencia, lo que la función cargue queda cargado en el arreglo del main.

Errores típicos (para no perder puntos)

Salirse de rango: arr[5] en un int arr[5]
Es el error más grave y el más fácil de cometer por culpa de que los índices arrancan en 0. En int arr[5] las posiciones que existen son 0, 1, 2, 3, 4. La posición 5 NO existe (sería la sexta). Si hacés arr[5] = 10; estás escribiendo fuera del espacio reservado, pisando memoria que no es tuya. C++ muchas veces no te avisa al compilar: el programa parece andar pero corrompe datos o se rompe de forma impredecible (en la materia se anota como "no tengo que cargar datos fuera del espacio reservado"). Regla de oro: el índice máximo válido es tamaño − 1.
Confundir tamaño físico con elementos útiles
Ya lo vimos, pero se repite tanto que va de nuevo: si reservaste int v[100] pero cargaste N = 30, recorré 0 a N − 1 (0 a 29), NO 0 a 99. Procesar las 70 posiciones de basura te arruina cualquier cuenta.
Olvidar que el índice arranca en 0
El primer elemento es arr[0], no arr[1]. Y el "elemento número 5" (el quinto) es arr[4], no arr[5]. Arrancar un recorrido en i = 1 "porque empiezo a contar desde 1" te saltea el primer elemento (el de la posición 0). Salvo casos puntuales (como el máximo, donde arrancás en 1 a propósito porque ya tomaste el 0), los recorridos empiezan en i = 0.

Repaso de la unidad

Lo que tenés que llevarte
• Un arreglo (array / vector) guarda un conjunto de elementos del mismo tipo bajo un solo nombre. Resuelve el problema de "necesito 100 variables".
• Se declara tipo nombre[CANTIDAD_MAX]; (ej. int arr[5];). El tamaño es fijo.
• Se accede con nombre[posicion]. Los índices van de 0 a CANTIDAD_MAX − 1 (¡arrancan en 0!). En int arr[5]: posiciones 0,1,2,3,4; el índice máximo es 4.
• Inicialización por lista: int arr2[3] = {4, 9, 56};.
• Se recorre con for(int i = 0; i < n; i++) usando arr[i] en cada vuelta.
• En memoria es un bloque contiguo; el nombre guarda la dirección de comienzo; ubicar arr[i] es una sola cuenta → acceso directo en tiempo constante, O(1).
• Distinguí tamaño físico (lo reservado) de elementos útiles N (lo cargado). Recorré de 0 a N − 1; el resto es basura.
• Operaciones básicas: cargar (for con cin), búsqueda secuencial (recorrer comparando), copiar (posición a posición), máximo/mínimo (arrancando con arr[0]).
• Los arreglos se pasan a funciones por referencia (se pasa la dirección): lo que la función modifica persiste afuera. Por eso se suele pasar N como parámetro aparte.
9 Unidad 9: Registros (structs) y arreglos de structs

Hasta ahora, cuando necesitabas guardar muchos datos juntos, usabas un arreglo (un vector): una fila de cajitas que sirve para almacenar muchos valores… pero todos del mismo tipo. Un arreglo de int guarda enteros, uno de string guarda textos. ¿Y si lo que querés describir es una cosa formada por datos de distinto tipo? Por ejemplo una persona: tiene un DNI (un número), un nombre (un texto) y un apellido (otro texto). Para eso existe el registro —en C++, el struct—: un tipo de dato nuevo, inventado por vos, que agrupa varios datos relacionados bajo un solo nombre. En esta unidad vas a aprender a definir tus propios tipos, a meterlos unos adentro de otros, a pasarlos a funciones (por valor y por referencia) y a combinarlos con arreglos. Todo desde cero y con el código tal cual lo da la cátedra.

¿Qué problema resuelve un registro?

Pensá en un punto del plano, como en geometría: tiene una coordenada x y una coordenada y. Las dos son enteros, así que hasta podrías guardarlas en dos variables sueltas:

int x = 3;
int y = 2;
cout << x << ", " << y << endl;   // muestra: 3, 2

Funciona… pero x e y son dos variables independientes: nada en el código dice que "van juntas", que forman un punto. Si ahora querés un segundo punto, te aparece otro par de variables sueltas:

int x2 = 1;
int y2 = 4;
cout << x2 << ", " << y2 << endl;  // muestra: 1, 4

Con dos puntos ya tenés cuatro variables flotando. Con diez puntos, veinte variables. Y si quisieras pasarle "un punto" a una función, tendrías que pasarle dos parámetros y rezar para no mezclarlos. El problema de fondo es que el lenguaje no sabe que x e y son una sola entidad.

Tampoco te salva un arreglo: un arreglo agrupa muchos datos, sí, pero todos del mismo tipo. Un punto justo da la casualidad de ser dos enteros, pero una persona es un int (el DNI) y dos string (nombre y apellido): tipos distintos que no entran juntos en un solo arreglo.

Arreglo vs. registro: la diferencia de fondo
• Un arreglo agrupa muchos datos del MISMO tipo (muchos enteros, muchos textos). Los accedés por posición: v[0], v[1]…
• Un registro (struct) agrupa pocos datos de DISTINTO tipo que describen una entidad (un punto, una persona). Los accedés por nombre de campo: p.x, persona.dni.

Un struct es, ni más ni menos, un tipo de dato definido por vos (el usuario), hecho a medida del problema.

Definir un registro: la palabra clave struct

Para crear un tipo nuevo usás la palabra clave struct, le ponés un nombre y, entre llaves, listás los campos (los datos que lo componen), cada uno con su tipo y su nombre. La forma general es:

struct NombreDelTipo {
    tipoDeDato nombreCampo1;
    tipoDeDato nombreCampo2;
    tipoDeDato nombreCampo3;
    ....
    tipoDeDato nombreCampoN;
};

A cada uno de esos datos internos lo llamamos campo (o miembro, o atributo). Aplicado al punto de la cátedra, que guarda x, y y además una descripcion de texto, queda así:

struct Punto {
    int x;
    int y;
    string descripcion;
};

Leído en castellano: "definí un tipo nuevo llamado Punto; todo Punto tiene un entero x, un entero y y un texto descripcion". Por convención, los nombres de tipos se escriben con mayúscula inicial (Punto, Persona, Recta) para distinguirlos de las variables, que van en minúscula.

Definir un tipo NO crea ninguna variable todavía
La definición de un struct es como un molde o plano de construcción: describe cómo es un Punto, pero no fabrica ninguno. Es como el plano de una casa: el plano no es una casa, es la forma de construir casas. Recién cuando declarás una variable de ese tipo (lo vemos en la próxima sección) se reserva memoria de verdad. Por eso la definición suele ir arriba de todo, antes de main, junto a los #include.
El error más típico: olvidar el ; después de la }
La llave de cierre de un struct lleva punto y coma. Esto es muy fácil de olvidar porque en los if, los for y las funciones la llave de cierre no lo lleva. Pero un struct es una declaración, y como toda declaración termina en ;:

✗ struct Punto { int x; int y; }  → falta el ;, no compila.
✓ struct Punto { int x; int y; };

El error que tira el compilador suele ser confuso y apuntar a la línea de abajo (a veces directo a int main), porque sigue leyendo esperando que la declaración termine. Ante un error raro justo después de un struct, lo primero que tenés que revisar es ese ; final.

Declarar una variable y acceder a los campos: el operador punto .

Una vez definido el tipo Punto, ya podés usarlo igual que usás int o string: para declarar variables. Escribís el nombre del tipo y el nombre de la variable:

Punto punto1;

Esto crea una variable punto1 que adentro tiene los tres campos (x, y, descripcion), todavía sin valores útiles. Para entrar a un campo —tanto para escribirlo como para leerlo— se usa el operador punto .: se escribe la variable, un punto, y el nombre del campo. Se lee "el x de punto1":

Punto punto1;
punto1.x = 3;                  // guardo 3 en el campo x de punto1
punto1.y = 2;                  // guardo 2 en el campo y de punto1
punto1.descripcion = "el punto 1";
cout << punto1.x << ", " << punto1.y << endl;   // muestra: 3, 2

Fijate que punto1.x se comporta exactamente como una variable int: le podés asignar (punto1.x = 3;), lo podés leer (cout << punto1.x;), sumarlo, etc. Lo mismo punto1.descripcion es un string común y corriente. El operador punto simplemente dice cuál de los campos del registro querés tocar.

El operador punto en una frase
variable.campo significa "el campo que vive adentro de variable". A la izquierda del punto va siempre una variable de tipo struct; a la derecha, el nombre de un campo de ese struct. Y ese variable.campo se usa como cualquier dato del tipo del campo.

Inicialización por lista: cargar todos los campos de una

Asignar campo por campo (tres líneas para tres campos) funciona, pero es largo. C++ te deja inicializar el struct entero en el momento de declararlo, usando una lista de valores entre llaves, separados por comas. Los valores se asignan a los campos en el mismo orden en que los definiste:

Punto punto2 = {1, 4, "este es el punto 2"};
cout << punto2.x << ", " << punto2.y << endl;   // muestra: 1, 4

Como en struct Punto el orden de los campos es x, y, descripcion, el 1 va a x, el 4 va a y y el texto "este es el punto 2" va a descripcion. Es decir, estas dos formas dejan a punto2 exactamente igual:

Campo por campoPor lista (equivalente)
Punto punto2;
punto2.x = 1;
punto2.y = 4;
punto2.descripcion = "este es el punto 2";		Punto punto2 = {1, 4, "este es el punto 2"};
El orden importa, y mucho
La lista {...} se asigna por posición, no por nombre. Si te equivocás de orden, el compilador no te avisa (mientras los tipos coincidan) y el programa hace cosas raras. Por ejemplo, Punto p = {4, 1, "x"}; deja x = 4 e y = 1, ¡al revés de lo que quizás querías! Respetá siempre el orden en que aparecen los campos en la definición del struct.

Asignar un struct a otro: se copia TODO (semántica de valor)

Acá hay algo muy importante y muy cómodo: si tenés dos variables del mismo tipo struct, podés asignar una a la otra con un simple =, y C++ copia todos los campos, uno por uno. No tenés que copiar campo por campo a mano.

Punto a = {3, 2, "original"};
Punto b = a;     // b queda con x=3, y=2, descripcion="original": una COPIA de a

Lo crucial: b es una copia totalmente independiente de a. Son dos cajas separadas en memoria que por ahora tienen el mismo contenido. Si después cambiás un campo de b, a no se entera. A esto se lo llama semántica de valor: asignar copia el valor completo, no comparte.

Esto se ve clarísimo con la Recta de la cátedra, que es un struct con dos puntos adentro (ya lo vemos en detalle en la próxima sección; por ahora alcanza con saber que r.p1.x es la x del primer punto de la recta r). Mirá esta secuencia:

Recta r;
r.p1.x = 9;        // la x del primer punto de r vale 9

Recta r3 = r;      // r3 es una COPIA independiente de r
r3.p1.x = 2;       // toco SOLO la copia r3

cout << r.p1.x  << endl;   // muestra: 9   (la original NO cambió)
cout << r3.p1.x << endl;   // muestra: 2   (solo cambió la copia)

Sigamos la traza como si fuéramos la computadora:

Línear.p1.xr3.p1.xQué pasó
r.p1.x = 9;9—r3 todavía no existe.
Recta r3 = r;99r3 nace como copia de r: copia todos los campos, así que su p1.x arranca en 9.
r3.p1.x = 2;92Toco solo a r3. Como es independiente, r queda intacta.
Asignar un struct = fotocopiarlo
Punto b = a; (o b = a;) hace una fotocopia de a dentro de b, campo por campo. Después son dos cosas distintas: tocar una no afecta a la otra. Esto vale aunque el struct tenga otros structs adentro (se copia todo, hasta el último rincón).

Structs anidados: un registro adentro de otro

Un campo de un struct puede ser de cualquier tipo… incluso de otro struct que vos hayas definido antes. A esto se lo llama anidar (un struct dentro de otro). Es la forma natural de modelar cosas que están compuestas por otras cosas.

El ejemplo de la cátedra es la Recta: una recta tiene un nombre y está formada por dos puntos. Como ya tenemos el tipo Punto, lo reutilizamos como tipo de dos campos:

struct Recta {
    string nombre;
    Punto p1;
    Punto p2;
};

Ahora, para acceder a un campo que está dentro de otro struct, encadenás el operador punto: primero entrás a la Recta, después al Punto, después al campo del punto. Se lee de izquierda a derecha:

Recta r;
r.nombre = "recta ejemplo 1";
r.p1.x = 9;                    // la x  del punto p1 de la recta r
r.p1.y = 7;                    // la y  del punto p1 de la recta r
r.p1.descripcion = "aaaaa";
r.p2 = punto1;                 // a p2 le asigno un Punto entero (copia)

cout << r.p2.x << endl;        // la x del punto p2 de la recta r

Desglosá r.p1.x de izquierda a derecha: r es la recta → .p1 es su primer punto → .x es la coordenada x de ese punto. Tres puntos, tres niveles. Y fijate en r.p2 = punto1;: a un campo que es Punto le podés asignar otro Punto entero de una sola vez (se copian sus tres campos), exactamente por la semántica de valor de la sección anterior.

Una Recta también se puede inicializar por lista, anidando llaves: la lista de afuera es para la Recta, y donde va un Punto metés otra lista entre llaves:

Recta r2 = {"abc", {1, 4, "bbbb"}, punto1};
//          nombre   ↑ p1 (un Punto entre llaves)   ↑ p2 (un Punto ya existente)

El anidamiento puede tener más de un nivel. La cátedra modela una Persona que, además de DNI, nombre y apellido, tiene una dirección, que a su vez es un struct con calle, número, etc. Primero se define el tipo interno y después el que lo usa:

struct Direccion {
    string calle;
    int nro;
    int cp;
    string provincia;
    string pais;
};

struct Persona {
    int dni;
    string nombre;
    string apellido;
    Direccion direccion;
};

Y se accede igual, encadenando puntos hasta el campo que querés:

Persona persona;
persona.dni = 40123456;
persona.nombre = "Ana";
persona.direccion.calle = "Medrano";   // la calle, de la direccion, de la persona
persona.direccion.nro = 951;
cout << persona.direccion.calle << endl;   // muestra: Medrano
Regla para definir tipos anidados
El tipo interno tiene que estar definido antes de usarlo. Por eso Punto se define arriba de Recta, y Direccion arriba de Persona: cuando el compilador lee Punto p1; dentro de Recta, ya tiene que saber qué es un Punto. Y para acceder, recordá la lectura de izquierda a derecha: persona.direccion.calle = "la calle, de la dirección, de la persona".

Funciones con structs: recibir, devolver y modificar

La gran ventaja de tener un tipo propio es que ahora podés tratar a un punto como un solo dato: pasárselo a una función completo, o que una función te devuelva uno. Veamos los tres casos, con el código de la cátedra.

Recibir un struct por valor

Una función puede recibir un struct como parámetro, igual que recibe un int. Acá un procedimiento que muestra un punto:

void mostrarPunto(Punto p) {
    cout << p.x << ", " << p.y << endl;
}

Y se lo llamamos pasándole una variable Punto entera:

mostrarPunto(punto1);   // muestra: 3, 2

Como el parámetro p se recibe por valor, lo que entra a la función es una copia de punto1 (con todos sus campos). Adentro, p es una variable local; cualquier cosa que le hicieras a p no tocaría a punto1.

Devolver un struct

Una función puede construir un struct adentro y devolverlo con return. El tipo de retorno (a la izquierda del nombre) es el nombre del struct. Esta función arma un punto nuevo que es la suma de otros dos:

Punto sumar(Punto p1, Punto p2) {
    Punto res;
    res.x = p1.x + p2.x;
    res.y = p1.y + p2.y;
    return res;
}

Adentro declara un Punto res, le carga campo por campo la suma, y lo devuelve con return res;. Quien la llama recibe ese punto y lo puede guardar en una variable:

Punto p3 = sumar(punto1, punto2);   // p3.x = 3+1 = 4 ; p3.y = 2+4 = 6

Con punto1 = {3,2,...} y punto2 = {1,4,...}, el resultado p3 tiene x = 4 e y = 6. (La función no toca la descripcion, así que ese campo de res queda sin un valor útil; en este ejemplo no importa porque solo nos interesan las coordenadas.)

Modificar el original: recibir por referencia con &

¿Y si quiero que la función cambie el punto original, no una copia? Para eso se recibe el parámetro por referencia, poniendo un & (ampersand) después del tipo. Con &, el parámetro no es una copia: es el mismo dato de afuera, con otro nombre adentro. Lo que le hagas, le pasa al original.

void incX(Punto& p) {
    p.x = p.x + 1;
}

Mirá el efecto al llamarla. punto1.x valía 3; después de incX(punto1) vale 4, de verdad:

incX(punto1);
cout << punto1.x << endl;   // muestra: 4

Tracemos qué pasa con punto1.x:

Momentopunto1.xComentario
Antes de llamar3Lo dejamos así en punto1.x = 3;.
Dentro de incX3 → 4Como p es Punto& p, es punto1: p.x = p.x + 1 le suma 1 al original.
Después de volver4El cambio quedó: punto1.x ahora vale 4.

Si incX hubiera recibido el punto por valor (void incX(Punto p), sin el &), habría incrementado solo su copia local y punto1.x habría seguido valiendo 3 afuera. El & es lo que marca toda la diferencia.

Por valor vs. por referencia, con structs
• Por valor (void f(Punto p)): entra una copia. La función puede leerla y trastearla, pero el original de afuera no cambia.
• Por referencia (void f(Punto& p), con &): entra el mismo dato. Lo que la función modifica sí cambia afuera.

Además, pasar un struct por valor copia todos sus campos, y si el struct es grande eso cuesta tiempo y memoria. Por eso muchas veces se pasan por referencia: para modificar el original o simplemente para evitar la copia.
Creer que "por valor" modifica el original
Un error clásico: escribís void incX(Punto p) (sin &), adentro hacés p.x = p.x + 1;, y te sorprende que afuera punto1.x siga en 3. No está roto: sin &, p es una copia, y le sumaste 1 a la copia, que se descarta al terminar la función. Si querés tocar el original, necesitás el &.

Arreglos de structs: juntar las dos ideas

Ahora combinamos lo de esta unidad con los arreglos: nada te impide hacer un arreglo cuyos elementos son structs. Cada casillero del arreglo es un struct completo. Es la forma natural de guardar muchas entidades del mismo tipo: muchos puntos, muchas personas.

Punto puntos[2] = { {1, 2}, {3, 4} };

Esto crea un arreglo de 2 Punto. Cada par de llaves de adentro inicializa un punto: el casillero 0 queda en {1,2} y el 1 en {3,4}. (Como solo damos dos valores por punto, se completan x e y; la descripcion queda vacía.) Para llegar a un campo, primero elegís el elemento con el corchete [i] y después aplicás el punto:

cout << puntos[0].x << endl;   // muestra: 1   (la x del punto en la posicion 0)
cout << puntos[1].y << endl;   // muestra: 4   (la y del punto en la posicion 1)

La lectura de puntos[1].y es, de izquierda a derecha: puntos es el arreglo → [1] elige el segundo elemento (un Punto) → .y es su coordenada y. Y como es un arreglo, lo recorrés con un for de toda la vida, usando puntos[i] en cada vuelta:

for (int i = 0; i < 2; i++) {
    cout << puntos[i].x << ", " << puntos[i].y << endl;
}
/* Muestra:
   1, 2
   3, 4
*/

También podés declarar el arreglo vacío (sin inicializar) y cargar cada casillero después, asignándole un struct entero. Así aparece en el archivo de complejos de la cátedra:

Complejo arr[5];      // arreglo de 5 Complejo, todavia sin cargar
arr[0] = c1;          // en la posicion 0 guardo el complejo c1 (copia)
arr[1] = c2;
arr[3] = c3;

cout << arr[3].real << " " << arr[3].imaginaria << "i" << endl;

Cada arr[i] = ...; copia un Complejo entero en ese casillero (otra vez la semántica de valor). Y arr[3].real es "la parte real del complejo que está en la posición 3".

Primero el corchete, después el punto
En un arreglo de structs el orden es arreglo[i].campo: primero elegís cuál elemento con [i], y después entrás a su campo con .. Escribir arreglo.campo[i] no tiene sentido (el arreglo no tiene un campo campo) y no compila.

Ejemplo integrador completo: números complejos

Cerramos juntando todo lo de la unidad en un solo programa: el de números complejos de la cátedra. Un número complejo tiene una parte real y una parte imaginaria (lo que en matemática escribís como 3 + 5i). Lo modelamos con un struct de dos campos float:

struct Complejo {
    float real;
    float imaginaria;
};

Ahora tres módulos que muestran los tres usos de structs en funciones. Primero, uno que crea un complejo a partir de sus partes y lo devuelve (usa inicialización por lista adentro):

Complejo crearComplejo(float real, float imaginaria) {
    Complejo c = {real, imaginaria};
    return c;
}

Segundo, uno que recibe dos complejos por valor y devuelve su suma (sumar dos complejos es sumar real con real e imaginaria con imaginaria):

Complejo sumarComplejos(Complejo c1, Complejo c2) {
    Complejo c = {c1.real + c2.real, c1.imaginaria + c2.imaginaria};
    return c;
}

Tercero, un procedimiento que multiplica un complejo por un número (un escalar). Como queremos modificar el complejo original, lo recibimos por referencia con &:

void multiplicarEscalar(Complejo& c, int valor) {
    c.real = c.real * valor;
    c.imaginaria = c.imaginaria * valor;
}

Y el main que lo usa todo —crear, sumar, multiplicar por referencia y guardar en un arreglo—:

int main() {

    Complejo c1 = crearComplejo(40, 10);
    Complejo c2 = crearComplejo(50, 5);

    Complejo c3 = sumarComplejos(c1, c2);
    cout << c3.real << " " << c3.imaginaria << "i" << endl;

    multiplicarEscalar(c3, 2);
    cout << c3.real << " " << c3.imaginaria << "i" << endl;

    Complejo arr[5];
    arr[0] = c1;
    arr[1] = c2;
    arr[3] = c3;

    cout << arr[3].real << " " << arr[3].imaginaria << "i" << endl;

    return 0;
}

Sigamos la traza paso a paso, como una computadora:

En catorce líneas de main usaste todo: definiste un tipo propio (struct Complejo), una función que devuelve un struct (crearComplejo), otra que recibe structs y devuelve uno (sumarComplejos), un procedimiento que modifica por referencia (multiplicarEscalar con &), accediste a campos con el punto (c3.real) y guardaste structs en un arreglo (arr). Ese es exactamente el repertorio de la unidad, funcionando junto.

Repaso de la unidad

Lo que tenés que llevarte
• Un registro (struct) es un tipo de dato definido por vos que agrupa campos de distinto tipo para describir una entidad (un punto, una persona).
• Se define con struct Nombre { tipo campo1; tipo campo2; ... };  ¡con ; después de la }!
• Se declara como cualquier variable (Punto p1;) y se accede a los campos con el operador punto: p1.x = 3; cout << p1.x;.
• Se puede inicializar por lista, en el orden de los campos: Punto p2 = {1, 4, "..."};.
• Asignar copia todo (semántica de valor): Recta r3 = r; crea una copia independiente; tocar r3 no afecta a r.
• Los structs se pueden anidar: un campo puede ser otro struct (Recta con dos Punto; Persona con Direccion), y se accede encadenando puntos (r.p1.x, persona.direccion.calle).
• Las funciones pueden recibir structs (por valor = copia), devolverlos (return res;) y modificar el original recibiéndolos por referencia con & (void incX(Punto& p)).
• Un arreglo de structs guarda muchas entidades del mismo tipo; se accede arreglo[i].campo (primero el corchete, después el punto) y se recorre con un for.
10 Unidad 10: Matrices (arreglos bidimensionales)

En la unidad de arreglos aprendiste a guardar muchos datos del mismo tipo en una fila de casilleros: un vector. Eso resuelve un montón de problemas… pero hay datos que no son una fila, son una tabla: un tablero de ajedrez, las notas de varios alumnos en varias materias, los píxeles de una imagen, las temperaturas tomadas a lo largo de muchos días y muchas horas. Para esos datos —los que tienen filas y columnas— está la matriz: un arreglo de dos dimensiones. En esta unidad vas a ver qué es, cómo se declara, cómo se accede a cada celda, cómo se recorre con un doble for, los recorridos más útiles (sumar, buscar el máximo, contar) y cómo pasar una matriz a una función. Todo desde cero, asumiendo que ya manejás vectores y ciclos for.

¿Por qué un vector no alcanza? De la fila a la tabla

Un vector es una fila de casilleros numerados: nota[0], nota[1], nota[2]… Con un solo número (el índice) alcanza para señalar cualquier casillero. Es perfecto para una lista: las 167 notas de un curso, los sueldos de una empresa, los días de un mes.

Pero pensá en estos datos:

Datos que son naturalmente una TABLA
Notas de alumnos en materias — 5 alumnos, 3 materias. No es una lista plana: es una grilla. La nota de Ana en Matemática vive en el cruce de la fila de Ana con la columna de Matemática.

Tablero de ajedrez — 8 filas por 8 columnas. Cada casilla se ubica por su fila y su columna (la torre está en "fila 1, columna 1").

Imagen en blanco y negro — una grilla de píxeles; cada píxel tiene un valor de gris según su fila y su columna.

Temperaturas por día y hora — un día tiene 24 horas; un mes, 30 días. La temperatura de "el día 5 a las 14 hs" se ubica por su fila (día) y su columna (hora).

En todos estos casos necesitás dos números para señalar un dato: en qué fila y en qué columna. Eso es justo lo que un vector (con un solo índice) no te da.

Podrías intentar forzarlo con un vector gigante y "hacer la cuenta a mano" para saber qué posición corresponde a cada fila/columna, pero es incómodo y propenso a errores. C++ te da la herramienta exacta para esto: la matriz, un arreglo de dos dimensiones, donde a cada dato lo ubicás dando fila y columna.

La idea en una frase
Un vector organiza datos en una dimensión (una fila): un índice. Una matriz los organiza en dos dimensiones (filas × columnas): dos índices. Si el dato "se dibuja como una tabla", pedís una matriz.

Qué es una matriz y cómo se declara

Una matriz (o arreglo bidimensional) es una colección de casilleros del mismo tipo, organizados en filas y columnas. Se declara igual que un vector, pero con dos pares de corchetes: el primero dice cuántas filas tiene; el segundo, cuántas columnas:

tipo nombre[FILAS][COLUMNAS];

Por ejemplo, una matriz de enteros con 3 filas y 4 columnas:

int m[3][4];

Esa declaración reserva en memoria 3 × 4 = 12 casilleros de tipo int, todos pegados, listos para guardar 12 números enteros. Visualmente, pensala como una grilla de 3 filas por 4 columnas:

col 0col 1col 2col 3
fila 0m[0][0]m[0][1]m[0][2]m[0][3]
fila 1m[1][0]m[1][1]m[1][2]m[1][3]
fila 2m[2][0]m[2][1]m[2][2]m[2][3]
Una matriz es "un arreglo de arreglos"
La forma más útil de imaginar int m[3][4] es: un vector de 3 elementos, donde cada elemento es, a su vez, un vector de 4 enteros. O sea, m tiene 3 filas, y cada fila es un vectorcito de 4 columnas. Esta idea —"un arreglo cuyos elementos son arreglos"— explica por qué se escribe con dos corchetes y, más adelante, por qué al pasarla a una función hay que aclarar cuántas columnas tiene cada fila.

El tipo puede ser cualquiera: int, float, char, etc. Y las dimensiones suelen ser constantes conocidas. Es muy común definirlas con const para no repetir números "mágicos" por todo el código:

const int FILAS = 3;
const int COLUMNAS = 4;

int m[FILAS][COLUMNAS];   // misma matriz de 3x4, pero con nombres claros

Acceder a una celda: m[i][j]

Para usar una celda puntual escribís el nombre de la matriz seguido de dos índices entre corchetes: el primero es la fila, el segundo es la columna.

m[i][j]   // i = numero de FILA, j = numero de COLUMNA
El orden es SIEMPRE [fila][columna]
En m[i][j]: el primer índice i es la fila; el segundo índice j es la columna. Igual que en un vector, ambos arrancan en 0. Para una matriz int m[3][4], las filas válidas son 0, 1, 2 (tres filas) y las columnas válidas son 0, 1, 2, 3 (cuatro columnas).

Una celda se usa igual que cualquier variable int: le podés asignar un valor, leer el que tiene, mostrarlo, usarlo en una cuenta. Mirá:

int m[3][4];

m[0][0] = 7;          // guarda 7 en la celda fila 0, columna 0 (esquina superior izquierda)
m[1][2] = 25;         // guarda 25 en la celda fila 1, columna 2
m[2][3] = 100;        // guarda 100 en la celda fila 2, columna 3 (esquina inferior derecha)

cout << m[1][2] << endl;            // muestra: 25
int doble = m[1][2] * 2;           // doble queda en 50
m[0][0] = m[0][0] + 1;             // ahora m[0][0] vale 8

También podés cargar celdas desde el teclado con cin, exactamente como con un vector:

cout << "Ingrese el valor de la fila 0, columna 1: ";
cin >> m[0][1];        // lo que tipea el usuario queda guardado en esa celda
Trampa MUY común: confundir el orden fila/columna
m[i][j] es fila i, columna j, en ese orden. Si querés la celda de la fila 1 y la columna 2, es m[1][2], no m[2][1] (esa última es fila 2, columna 1, ¡otra celda!). En una matriz cuadrada (mismas filas que columnas) el programa igual compila y "anda", pero te da el dato equivocado: es un error lógico silencioso. Memorizá: primero fila, después columna.
Trampa: salirse de rango
En int m[3][4] la última fila es la 2 y la última columna es la 3 (no la 3 y la 4: arrancan en 0). Escribir m[3][0] o m[0][4] es pasarse de rango: estás tocando memoria que no es tuya. C++ no te avisa con un error claro; el programa puede mostrar basura, dar resultados raros o cerrarse de golpe. Cuidá siempre que la fila vaya de 0 a FILAS-1 y la columna de 0 a COLUMNAS-1.

Inicializar una matriz por lista de valores

Igual que un vector se puede inicializar con {...}, una matriz se inicializa con llaves dentro de llaves: una llave general que contiene una subllave por cada fila. Cada subllave lista, en orden, los valores de las columnas de esa fila:

int m[2][3] = { {1, 2, 3},
                {4, 5, 6} };

Leelo así: la matriz tiene 2 filas y 3 columnas. La primera subllave {1, 2, 3} es la fila 0; la segunda subllave {4, 5, 6} es la fila 1. Dentro de cada subllave, los valores van llenando las columnas 0, 1, 2 en orden. Queda así:

col 0col 1col 2
fila 0123
fila 1456

Con esa inicialización, por ejemplo, m[0][0] vale 1, m[0][2] vale 3, m[1][0] vale 4 y m[1][2] vale 6. La estructura de llaves copia visualmente la tabla: cada renglón de código es una fila de la matriz, lo cual ayuda muchísimo a leerla.

Cada subllave = una fila
En int m[2][3] = { {1,2,3}, {4,5,6} }: hay 2 subllaves porque hay 2 filas, y cada subllave tiene 3 números porque hay 3 columnas. Si la cantidad de subllaves o de números por subllave no coincide con las dimensiones declaradas, el compilador se queja o rellena con ceros. Mantené la coherencia: la forma de las llaves tiene que reflejar el tamaño de la matriz.

Recorrer toda la matriz: el doble for (ciclos anidados)

Para recorrer un vector usabas un for que movía el índice de 0 a N-1. Una matriz tiene dos índices (fila y columna), así que necesitás dos for, uno adentro del otro. A esto se lo llama ciclos anidados (o "doble for"). El patrón es siempre el mismo:

for (int i = 0; i < FILAS; i++) {           // for EXTERNO: recorre las filas
    for (int j = 0; j < COLUMNAS; j++) {    // for INTERNO: recorre las columnas
        // aca uso la celda m[i][j]
    }
}

La clave para entenderlo es el orden en que se visitan las celdas. El for externo fija una fila (i empieza en 0) y no avanza hasta que el for interno terminó de recorrer todas las columnas de esa fila. O sea: se completa la fila 0 entera (columna 0, 1, 2, 3), recién ahí i pasa a 1 y se hace la fila 1 entera, y así. Se barre la tabla de a renglones, de izquierda a derecha y de arriba hacia abajo, igual que cuando leés.

Traza del doble for sobre una matriz de 2×3
Con FILAS = 2 y COLUMNAS = 3, estos son todos los pasos, en orden, y qué celda m[i][j] se visita en cada uno:

Pasoi (fila)j (col)Celda visitada
100m[0][0]
201m[0][1]
302m[0][2]
410m[1][0]
511m[1][1]
612m[1][2]

Fijate el patrón: mientras i vale 0 (fila 0), j recorre 0, 1, 2 (toda la fila). Recién cuando j se pasa de 2, el for interno termina, i avanza a 1 y j vuelve a 0 para recorrer la fila 1 completa. Son 2 filas × 3 columnas = 6 celdas, visitadas en 6 pasos.
Quién manda a quién
El for externo (filas) avanza una sola vez por cada vuelta completa del for interno (columnas). Por eso el interno "gira más rápido": para cada valor de i, el j hace todo su recorrido de 0 a COLUMNAS-1. Si la matriz es de F filas por C columnas, el cuerpo de adentro se ejecuta F × C veces (una por celda).

Cargar la matriz desde el teclado con doble for

El uso más típico del doble for es llenar toda la matriz pidiendo los datos al usuario, celda por celda:

#include <iostream>
using namespace std;

const int FILAS = 3;
const int COLUMNAS = 4;

int main() {
    int m[FILAS][COLUMNAS];

    for (int i = 0; i < FILAS; i++) {
        for (int j = 0; j < COLUMNAS; j++) {
            cout << "Ingrese el valor de la celda [" << i << "][" << j << "]: ";
            cin >> m[i][j];
        }
    }

    return 0;
}

Ese doble for le pide al usuario, en orden, la celda [0][0], [0][1], …, [0][3], después [1][0], y así hasta [2][3]: las 12 celdas, fila por fila.

Imprimir la matriz como tabla

Para mostrar la matriz con forma de tabla (cada fila en su propio renglón) usás el mismo doble for, con dos detalles: dentro del for interno mostrás cada celda seguida de un espacio (con "\t", una tabulación, o un simple espacio), y al terminar cada fila —es decir, justo después del for interno, todavía dentro del externo— hacés un endl para bajar de renglón:

for (int i = 0; i < FILAS; i++) {
    for (int j = 0; j < COLUMNAS; j++) {
        cout << m[i][j] << "\t";    // muestra la celda y un tab (sin bajar de renglon)
    }
    cout << endl;                    // OJO: aca, fuera del for interno: termina la fila
}
El endl va ENTRE los dos for
El detalle que arma la tabla es dónde ponés el endl: afuera del for interno pero adentro del externo. Así, todas las celdas de una misma fila salen en el mismo renglón (separadas por el tab), y el salto de línea ocurre una sola vez por fila, al terminarla. Si pusieras el endl adentro del for interno, bajarías de renglón en cada celda y verías la matriz como una columna larguísima.
Qué imprime, con la matriz de ejemplo
Si la matriz es int m[2][3] = { {1,2,3}, {4,5,6} }, el doble for de impresión de arriba muestra en pantalla:

1    2    3
4    5    6

La fila 0 (1 2 3) sale en un renglón; el endl baja; la fila 1 (4 5 6) sale en el siguiente. Se ve como la tabla original.

Recorridos útiles sobre matrices

Con el doble for como herramienta base, resolvés casi cualquier problema típico. Veamos los más frecuentes. En todos asumimos una matriz int m[FILAS][COLUMNAS] ya cargada.

1) Sumar TODOS los elementos

Acumulás en una variable que arranca en 0, recorriendo todas las celdas con el doble for:

int suma = 0;
for (int i = 0; i < FILAS; i++) {
    for (int j = 0; j < COLUMNAS; j++) {
        suma = suma + m[i][j];     // sumo cada celda
    }
}
cout << "Suma de todos los elementos: " << suma << endl;

Es la misma idea del acumulador que usabas en vectores, solo que el recorrido ahora es doble. Si la matriz es { {1,2,3}, {4,5,6} }, da 1+2+3+4+5+6 = 21.

2) Buscar el MÁXIMO de toda la matriz

Arrancás suponiendo que el máximo es la primera celda (m[0][0]) y, recorriendo el resto, cada vez que encontrás una celda mayor, actualizás:

int maximo = m[0][0];              // arranco con la primera celda como candidata
for (int i = 0; i < FILAS; i++) {
    for (int j = 0; j < COLUMNAS; j++) {
        if (m[i][j] > maximo) {
            maximo = m[i][j];       // encontre una mayor: la guardo
        }
    }
}
cout << "El maximo es: " << maximo << endl;

Misma estrategia que el máximo de un vector (inicializar con el primer elemento y comparar contra el resto), extendida a dos dimensiones. Para guardar dónde está el máximo, te alcanza con recordar también la fila y la columna en dos variables extra cuando actualizás.

3) Sumar una FILA dada

Si te interesa una sola fila (digamos la fila f), no hace falta doble for: fijás la fila y recorrés solo sus columnas con un for:

int f = 1;                         // quiero la suma de la fila 1
int sumaFila = 0;
for (int j = 0; j < COLUMNAS; j++) {
    sumaFila = sumaFila + m[f][j]; // f queda fijo; j recorre las columnas
}
cout << "Suma de la fila " << f << ": " << sumaFila << endl;

Fijate que m[f][j] mantiene f constante y solo mueve j: recorrés "a lo ancho", quedándote en el mismo renglón. Para la matriz de ejemplo, la fila 1 es {4,5,6}, así que da 15.

4) Sumar una COLUMNA dada

Al revés: para una sola columna (la columna c), fijás la columna y recorrés las filas. Ojo el detalle: ahora lo que se mueve es el primer índice:

int c = 2;                         // quiero la suma de la columna 2
int sumaColumna = 0;
for (int i = 0; i < FILAS; i++) {
    sumaColumna = sumaColumna + m[i][c];  // c queda fijo; i recorre las filas
}
cout << "Suma de la columna " << c << ": " << sumaColumna << endl;

Acá m[i][c] mantiene c fijo y mueve i: recorrés "a lo alto", bajando por la misma columna. Para la matriz de ejemplo, la columna 2 es 3 (de la fila 0) y 6 (de la fila 1), así que da 9.

Fila fija vs. columna fija
Para recorrer una fila: dejás el primer índice fijo y movés el segundo (m[f][j], variando j). Para recorrer una columna: dejás el segundo índice fijo y movés el primero (m[i][c], variando i). Confundir cuál índice se mueve es el error más típico de estos recorridos.

5) Contar cuántas celdas cumplen una condición

Llevás un contador que arranca en 0 y lo incrementás cada vez que la celda cumple lo pedido. Por ejemplo, contar cuántas celdas son mayores a 50:

int cuenta = 0;
for (int i = 0; i < FILAS; i++) {
    for (int j = 0; j < COLUMNAS; j++) {
        if (m[i][j] > 50) {
            cuenta++;               // una mas que cumple
        }
    }
}
cout << "Hay " << cuenta << " celdas mayores a 50" << endl;

Pasar una matriz a una función: las columnas son obligatorias

Igual que con los vectores, conviene modularizar: tener una función que cargue la matriz, otra que la muestre, otra que sume, etc. Pero al declarar el parámetro matriz hay una regla que tenés que respetar sí o sí:

La regla de oro al pasar una matriz
Para pasar una matriz a una función, hay que indicar el número de COLUMNAS en el parámetro. El número de filas se puede dejar vacío (y, como con los vectores, se suele pasar aparte como un int). La forma típica es:

void mostrar(int m[][COLUMNAS], int filas)

Las columnas van entre los segundos corchetes, obligatorias; las filas van como parámetro entero aparte.

Por ejemplo, una función que muestra una matriz de 4 columnas como tabla:

const int COLUMNAS = 4;

void mostrar(int m[][COLUMNAS], int filas) {
    for (int i = 0; i < filas; i++) {
        for (int j = 0; j < COLUMNAS; j++) {
            cout << m[i][j] << "\t";
        }
        cout << endl;
    }
}

Y se la llama pasándole la matriz (solo el nombre, sin corchetes) y la cantidad de filas:

int main() {
    int datos[3][COLUMNAS];
    // ... (acá se cargaría la matriz) ...

    mostrar(datos, 3);     // le paso la matriz y le aviso que tiene 3 filas
    return 0;
}

¿Por qué las columnas son obligatorias y las filas no?

Acá es donde vuelve la idea de "un arreglo de arreglos". En memoria, la matriz está guardada como una sola tira de casilleros, fila tras fila: primero toda la fila 0, después toda la fila 1, etc. (esto se llama "por filas"). Cuando vos pedís m[i][j], el compilador calcula en qué posición de esa tira está la celda, y para eso necesita saber cuántas columnas tiene cada fila: la cuenta es, a grandes rasgos, "saltá i filas enteras (cada una de COLUMNAS casilleros) y después avanzá j". Sin el número de columnas, no puede saber dónde termina una fila y empieza la siguiente, así que no puede ubicar la celda. El número de filas, en cambio, no entra en esa cuenta de posición: por eso se puede omitir (y se pasa aparte solo para saber hasta dónde recorrer).

Trampa: olvidar el número de columnas en el parámetro
Escribir void mostrar(int m[][], int filas) (con los dos corchetes vacíos) no compila: el compilador necesita las columnas para calcular las posiciones. Tampoco sirve int m[3][] (vacío justo el de columnas). Lo correcto es dejar vacío el primero y poner el número de columnas en el segundo: int m[][4] (o int m[][COLUMNAS]). Regla mnemotécnica: las columnas no se negocian.

Las matrices también se pasan por referencia (los cambios persisten)

Otra cosa que heredás de los vectores: cuando pasás una matriz a una función, no se hace una copia. La función trabaja directamente sobre la matriz original, así que cualquier cambio que le haga adentro, persiste afuera al volver (es, en los hechos, un paso por referencia, sin necesidad de poner &). Por eso una función puede cargar la matriz desde adentro y, al volver a main, los datos quedan cargados:

const int COLUMNAS = 4;

void cargar(int m[][COLUMNAS], int filas) {
    for (int i = 0; i < filas; i++) {
        for (int j = 0; j < COLUMNAS; j++) {
            cin >> m[i][j];        // escribe en la matriz ORIGINAL
        }
    }
}

int main() {
    int datos[3][COLUMNAS];
    cargar(datos, 3);             // al volver, datos YA quedo cargada
    mostrar(datos, 3);            // y la mostramos cargada
    return 0;
}
Patrón completo: main cortito + funciones
Como con los vectores, lo prolijo es un main que solo orquesta —cargar(datos, 3); mostrar(datos, 3); cout << suma(datos, 3);— mientras cada función se encarga de su tarea con su propio doble for adentro. Todas reciben la matriz y la cantidad de filas; todas declaran las columnas en el parámetro. Ese es el esqueleto de casi todos los ejercicios de matrices de la cátedra.

Conexión: matrices de structs y el ejercicio de las temperaturas

Dos ideas para cerrar y conectar con lo que ya sabés y con lo que viene.

Matrices de cualquier tipo, incluso de structs. Una matriz puede ser de int, de float, de char… y también de registros (structs). Por ejemplo, si tenés un struct Punto { int x; int y; };, podés declarar Punto tablero[3][3]; y acceder con tablero[i][j].x. Es la misma idea de siempre —filas y columnas— pero donde cada celda guarda un dato compuesto en vez de un número suelto.

El ejercicio 13 de la guía (las temperaturas) es un caso perfecto para pensar con estas herramientas. Dice: "se dispone de 8640 temperaturas horarias, tomadas durante los 12 meses del año, considerando que todos los meses tienen 30 días y cada día 24 horas; determinar la mayor temperatura y en qué mes, día y hora ocurrió". Notá que 12 × 30 × 24 = 8640: el dato es naturalmente multidimensional. Una versión más simple del mismo tipo de problema (el ejercicio 56) trabaja con una sola matriz día × hora: una matriz de 30 filas (días) por 24 columnas (horas), donde temp[d][h] es la temperatura del día d a la hora h. Buscar la temperatura máxima y en qué día y hora ocurrió es exactamente el recorrido de "máximo de toda la matriz" que viste recién, recordando además la fila (día) y la columna (hora) donde apareció.

Una dimensión por cada "eje" del dato
La cantidad de dimensiones de un arreglo se corresponde con la cantidad de "ejes" independientes del dato. Día × hora → 2 dimensiones (una matriz). Mes × día × hora (como el ejercicio 13 completo) → 3 dimensiones (se declara con tres corchetes: int t[12][30][24] y se recorre con un triple for). Las matrices que viste acá son el peldaño de dos dimensiones; el salto a tres o más es la misma idea, con un índice y un for más por cada dimensión extra.

Repaso de la unidad

Lo que tenés que llevarte
• Una matriz (arreglo bidimensional) organiza datos del mismo tipo en filas × columnas; es la extensión natural del vector a dos dimensiones ("un arreglo de arreglos").
• Se declara tipo nombre[FILAS][COLUMNAS];. Ej: int m[3][4] tiene 3 filas, 4 columnas → 12 casilleros.
• Se accede con m[i][j]: primero la fila i, después la columna j, ambas desde 0. En int m[3][4], filas válidas 0..2 y columnas 0..3.
• Inicialización por lista: int m[2][3] = { {1,2,3}, {4,5,6} }; — cada subllave es una fila.
• Se recorre con un doble for (anidado): el externo para las filas, el interno para las columnas. Se visita la fila 0 completa, después la fila 1, etc. El cuerpo corre FILAS × COLUMNAS veces.
• Para imprimir como tabla, el endl va entre los dos for (fuera del interno, dentro del externo): así cada fila ocupa un renglón.
• Recorridos clave: sumar todo, sumar una fila (fila fija, se mueve j), sumar una columna (columna fija, se mueve i), máximo de toda la matriz, contar los que cumplen una condición.
• Al pasar una matriz a una función, las columnas son obligatorias: void mostrar(int m[][COLUMNAS], int filas). Las filas se pasan aparte. El compilador necesita el ancho de fila para calcular posiciones. Se pasan por referencia: los cambios persisten.
• Puede haber matrices de structs, y datos como las temperaturas mes × día × hora (ejercicio 13) se modelan con estas ideas, escalando a más dimensiones cuando hace falta.
